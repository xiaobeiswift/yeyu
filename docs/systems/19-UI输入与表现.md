# 《雾州侠行》UI、输入与表现系统规格

> 状态：规划冻结候选稿
>
> 本文只定义未来实现契约，不代表代码已经存在。

## 1. 目标与非目标

### 1.1 目标

- 建立探索、对话、菜单、战斗、加载、只读恢复等模式下统一且可预测的输入路由。
- 支持点击移动与 WASD，所有键鼠关键操作均有等价 UI 路径。
- 支持轻功越障、定点跳跃与水面通行的点击/WASD 输入；玩家意图与动画表现不得代替 26 的通行校验和状态判定。
- UI 通过 ViewModel 读取状态、通过应用用例提交命令，不直接修改任何领域对象。
- 战斗表现严格消费确定性 CombatEvent 流，动画速度、掉帧和跳过不改变战斗结果。
- 以 1920×1080 为设计基准，使用锚点、安全区和字号策略适配其他分辨率。
- 全部提交型交互覆盖加载、忙碌、结果未知、失败、重试和只读状态。

### 1.2 非目标

- 不在 presentation 层实现任务、战斗、背包、商城、擂台或存档规则。
- 首发不要求手柄、移动触控、屏幕阅读器完整支持，但配置结构为后续输入设备预留。
- 不允许 UI 本地缓存成为进度、货币、权益、领奖或对话选择的权威来源。
- 不通过表现时间、客户端帧率或本地时钟驱动玩法结算。

## 2. 依赖与跨系统接口

| 依赖 | 用途 |
|---|---|
| 各应用 Query/Command | 读取 ViewModel、提交权威命令 |
| UIService | Y3 UI 创建、Prefab、文本、图像、进度和事件 |
| InputService | 键鼠按键、指针、焦点与世界点击 |
| Camera/Unit/Effect/Sound | 探索与战斗表现 |
| LocalizationService | 中文文本和参数格式化 |
| SaveCoordinator | 忙碌、只读、恢复与冲突状态 |
| CombatPresentationSource | 有序 CombatEvent 与事件哈希 |
| 24 设置应用接口 | 查询 SettingsProfile，调用 PreviewSettings/CommitSettings；本系统不拥有设置领域状态 |
| 26 轻功探索与特殊通行 | 查询 LightnessTraversalProfile、TraversalLink、WaterSurfaceZone 与可达格快照，提交 `RequestTraversal`、消费权威 TraversalEvent |

对外提供：

- ScreenNavigator、ModalCoordinator、ToastService。
- InputActionRouter：把设备输入映射为稳定 Action ID。
- CommandPresenter：提交、去重、超时确认和错误映射。
- CombatEventPresenter：按 sequence 播放或快进事件。
- TraversalPresenter：呈现候选落点、越障轨迹、踏水状态和失败反馈，并严格消费 26 的权威事件。
- UIStateQuery：供引导、截图测试和诊断读取非敏感状态。
- UIAnchorQuery：按语义 anchor ID 查询当前可用性；结果仅为 presentation 内部状态。

## 4. 领域模型与表现模型

UIState 本身不是业务领域权威。设置、输入绑定和教程进度的唯一领域所有者是 24；本系统只呈现其 ViewModel，并把玩家意图提交给 24 的应用用例。

### 4.1 ScreenDescriptor

| 字段 | 类型 | 说明 |
|---|---|---|
| screen_id | string | 唯一 screen_ ID |
| layer | enum | HUD、PANEL、MODAL、SYSTEM |
| allowed_modes | list | 可打开的 GameMode |
| blocks_world_input | boolean | 是否阻断世界点击和移动 |
| pauses_local_presentation | boolean | 仅影响单机表现，不改变服务器时间 |
| close_policy | enum | BACK、EXPLICIT、COMMAND_COMPLETE、FORBIDDEN |
| initial_focus_id | string? | 键盘默认焦点 |
| prefab_id | string | Y3 Prefab 映射 ID |

### 4.2 InputAction

| 字段 | 类型 | 说明 |
|---|---|---|
| action_id | string | 例如 MOVE_UP、INTERACT、OPEN_BAG、`OpenLightnessTargeting`、`MoveLightnessCursor`、`ConfirmLightnessTarget`、`CancelLightnessTargeting` |
| phase | enum | PRESSED、RELEASED、HELD |
| device | enum | KEYBOARD、MOUSE、UI |
| context | string | EXPLORE、TRAVERSE、DIALOGUE、MENU、BATTLE |
| pointer_position | object? | 仅世界/界面点击 |
| occurred_frame | integer | 只用于表现去重，不参与权威玩法 |

### 4.3 ScreenInstanceState

包含 instance_id、screen_id、state（OPENING、ACTIVE、BUSY、RESULT_UNKNOWN、ERROR、CLOSING）、command_id、view_revision、focus_id、error_code 和 temporary_fields。

### 4.4 PresentationCue

包含 cue_id、source_event_id、sequence、actor_ref、target_refs、animation_id、effect_id、sound_id、camera_id、duration_policy、skippable 和 fallback_policy。

### 4.5 TraversalPresentationState

这是 26 权威状态的临时 ViewModel，不得保存或反向写入领域：

| 字段 | 类型 | 说明 |
|---|---|---|
| `mode` | enum | `NONE/TARGETING/TRAVERSING/WATER_MOVING/RECOVERING` |
| `origin_cell_id` | StableId? | 打开选点时的权威起始 TraversalCell |
| `candidate_cells` | TraversalCell ViewModel 列表 | 由 26 Query 返回的离散可达/邻近无效格，UI 不自行按距离补候选 |
| `selected_cell_id` | StableId? | 当前悬停或键盘选中的目标格 |
| `selected_link_id` | StableId? | 仅目标格通过特殊 TraversalLink 时存在，不是独立选点流程 |
| `path_cell_ids` | StableId 列表 | 起点到当前目标的预览路径 |
| `water_zone_id` | StableId? | 当前已获授权的水面区域 |
| `traversal_session_id` | StableId? | 26 创建的本局 TraversalSession，不保存、不由 UI 构造 |
| `spatial_revision` | integer | 12 的空间/动态阻挡修订号，确认时原样回传 |
| `world_revision` | integer | 12 槽 2 世界事实/flag 修订号，条件变化时使候选过期 |
| `source_loadout_revision/source_progress_revision` | integer/integer | 04 当前主角负载与对应已学轻功行的来源修订 |
| `profile_hash/rules_version` | string/integer | 04 当前派生 Profile 的规范哈希与轻功探索规则版本 |
| `candidate_set_hash` | string | 规范化候选集哈希，用于拒绝陈旧预览 |
| `command_state` | enum | `IDLE/BUSY/RESULT_UNKNOWN/REJECTED` |
| `failure_reason` | error code? | 能力不足、落点不可用、状态禁止等受控反馈 |

### 4.6 TraversalCell 选点模型

轻功选点覆盖层使用 26 的世界空间离散 TraversalCell 可达集，不是少量固定跳点，也不是战斗 3×3 阵型网格。格子只用于显示和选点，26 仍按 LightnessTraversalProfile、TraversalLink/WaterSurfaceZone 与当前权威状态判定：

| 字段 | 类型 | 说明 |
|---|---|---|
| `traversal_cell_id` | StableId | 23 对地图/区域预烘焙的稳定 ID，不能用屏幕坐标代替 |
| `world_position` | world point | 只读显示中心 |
| `surface_type` | enum | 与 12 一致的 `GROUND/WATER/HAZARD/VOID`；视觉至少区分陆地有效与水面有效 |
| `target_role` | enum | `LANDING/WATER_STEP/SHORE_EXIT/NEIGHBOR_INVALID`；这是 26 的本次候选语义，不回写 TraversalCell 空间事实 |
| `validity` | enum | `VALID/INVALID`，来自 26 候选快照 |
| `invalid_reason` | error code? | 能力、距离、高差、阻挡、区域或状态原因 |
| `visual_state` | enum | `NORMAL/HOVERED/SELECTED/PATH`，仅 presentation 状态 |
| `link_id` | StableId? | 固定跳跃落点对应 TraversalLink |
| `path_cell_ids` | StableId 列表 | 预览路径；不得作为成功判定或逻辑移动轨迹 |
| `visibility` | enum | `VISIBLE/HIDDEN`；HIDDEN 格不得进入 UI payload，避免剧透未探索区域 |

## 5. 配置字段

### 5.1 ScreenDefinition

- screen_id、prefab_id、layer、allowed_modes、close_policy。
- anchor_policy、safe_area_policy、min/max aspect ratio。
- view_model_id、empty_state_id、loading_state_id、error_state_id、read_only_state_id。
- initial_focus_id、tab_order、input_context_id。
- localization_namespace、help_topic_id。

### 5.2 InputBindingDefinition

- binding_id、action_id、device、key/button、modifier、context、priority。
- repeat_delay_ms 和 repeat_rate_ms 只用于导航或移动表现。
- conflict_group、rebindable、reserved。

该定义由 24 设置系统拥有并生成，本系统只消费生成结果建立运行时映射，不保存第二份绑定配置。

### 5.3 PresentationCueDefinition

- combat_event_type、cue_id、animation/effect/sound/camera 映射。
- start_offset_ms、maximum_duration_ms、skippable、fallback_cue_id。
- 必须声明缺少模型、音效或特效时的降级表现。

### 5.4 Theme 与本地化

主题包含纸卷/水墨色板、字体、字号级别、九宫格边框、图标、焦点框、禁用态和危险态。玩家可见文字全部使用 message_key，不写在领域事件中。

### 5.5 LightnessTargetOverlayDefinition

- `overlay_id` 使用 `traversal_overlay_` 前缀，并定义陆地有效、水面有效、无效、悬停目标、选中落点、预览路线六类样式、不可达原因图标、地面投影材质和 fallback 图标。
- 每一状态同时定义颜色和至少一种非颜色编码（边框、纹理、形状或图标）；色弱方案不可只换色相。
- `max_visible_cells`、视距裁剪、批次渲染和低特效降级策略只影响表现，不得裁掉当前选中格、路径终点或错误原因。
- 低特效模式允许关闭脉冲、残影和水花，仍必须显示有效范围边界、当前光标、目标格和确认/取消提示。
- 配置引用 23 生成的 cell style/presentation ID，不直接引用 Y3 数字 Key。

### 5.6 TraversalPresentationProfile

- `presentation_profile_id` 使用 `traversal_presentation_` 前缀；04 的轻功等级行只引用该逻辑 ID。
- 字段包括 `jump_motion_id/water_motion_id/shore_exit_motion_id`、轨迹样式、朝向策略、主角动作/残影/水花 cue、伙伴跟随 cue、最大表现时长和 fallback cue。
- 该 Profile 只选择表现，不含格数、高差、能力、落点或世界条件；缺失资源时走 fallback，不能改成另一条规则路径。
- Y3 数字 Key 只存在适配映射；19 拥有表现 Schema，26 只把已授权路径和逻辑 Profile ID 交给表现端口。

## 6. 运行时状态

### 6.1 GameMode

BOOT、LOADING、EXPLORE、DIALOGUE、MENU、BATTLE、CUTSCENE、SAVE_READ_ONLY、SAVE_RECOVERY、BLOCKED_ERROR。

### 6.2 PresentationSession

- current_mode。
- screen_stack：按 layer 和打开顺序排列。
- active_modal_id。
- input_context_stack。
- pressed_actions：当前按住动作。
- pending_commands：command_id 到页面实例。
- combat_queue：按 sequence 排序的表现事件。
- last_consumed_combat_sequence。
- layout_metrics：分辨率、安全区和 UI scale。
- settings_snapshot：来自 24 SettingsProfile 的只读快照，包含音量、字幕、震屏、闪烁和战斗速度。
- traversal_state：来自 26 的只读 TraversalPresentationState；切地图、进入战斗或恢复时必须清空本地候选、旧修订号与旧 TraversalSession。

模式切换必须一次性清理不再合法的输入上下文，避免按键卡住。

## 7. 输入、页面与表现规则

### 7.1 输入优先级

输入依次路由：

1. SYSTEM 模态。
2. 顶层 MODAL。
3. 顶层 PANEL。
4. 当前 GameMode。
5. 世界探索。

上层标记 consumed 后不得穿透。文本输入焦点存在时，WASD 不触发移动。打开阻断世界输入的页面时立即停止持续移动命令。

### 7.2 探索输入

- 鼠标左键点击有效地面发出 MoveToWorldPoint。
- WASD 发出方向意图；应用层或 Y3 适配器转换为移动，不写任务状态。
- 靠近可交互目标后，INTERACT 或点击目标调用同一 Interact 用例。
- 点击普通可达地面仍走 MoveToWorldPoint；点击被沟壑、屋顶、高差或水域边界隔开的目标时，以该命中格作为初始焦点打开同一轻功 TARGETING 流程并向 26 查询完整 TraversalCell 候选集。TraversalLink 只是候选格可能采用的特殊边，不能形成第二套只选 link 的流程，UI 也不能用直线距离猜测可跳跃。
- `OpenLightnessTargeting` 进入轻功选点态：以当前 origin_cell_id 及候选来源向量 `{spatial_revision, world_revision, source_loadout_revision, source_progress_revision, profile_hash, rules_version}` 请求一次 TraversalCell 可达集，地面覆盖层显示本次可跳跃/可踏水行走范围，并可按配置显示邻近无效格与原因。稳定地面使用顶层选点会话；处于踏水总会话 `ON_WATER_IDLE` 时必须携带 parent traversal_session_id 打开唯一嵌套水面段选点。不得逐帧重算全图；仅在打开、角色权威起点变化、来源向量任一分量变化或 26 明确失效通知后刷新。
- UI payload 只包含当前已探索且可展示的 TraversalCell；HIDDEN 格、隐藏出口和未揭示区域连边不得生成覆盖层、轮廓、不可达提示或路径，以免用选点系统剧透地图。
- 鼠标悬停/点击、方向键或 WASD 触发 `MoveLightnessCursor`，只能在本次候选快照的格子间移动表现光标；`CancelLightnessTargeting` 清除覆盖层，顶层会话返回 EXPLORE，嵌套水面会话返回父 TraversalSession 的 `ON_WATER_IDLE`，均不产生领域事实。
- `ConfirmLightnessTarget` 对有效格提交 `RequestTraversal(command_id, targeting_session_id, parent_traversal_session_id?, origin_cell_id, traversal_cell_id, link_id?, spatial_revision, world_revision, source_loadout_revision, source_progress_revision, profile_hash, rules_version, candidate_set_hash)`；水面每一段必须创建新 command_id，parent 必须与嵌套会话一致。无效格只显示原因，不提交命令。唯一候选也仍需玩家确认，除非设置中显式开启并通过可用性评审的单击确认策略。
- 点击坐标、悬停格、预烘焙路径和绿色标记都只是选择/预览意图。`RequestTraversal` 必须由 26 在确认瞬间以当前 LightnessTraversalProfile、位置、世界条件和碰撞状态重新校验；陈旧候选返回后刷新覆盖层，UI 不自行改判。
- 命令 BUSY 期间吸收重复点击，结果未知时只能查询原 command_id；不能生成新 command_id 再请求同一位移。
- 处于活动踏水总会话时，26 在每段完成后打开/刷新 parent 匹配的嵌套候选快照；点击或 WASD 只把输入解析为其中的目标水格/岸格，随后仍调用统一 `RequestTraversal`。嵌套会话关闭后才能执行该段，段完成后回到 `ON_WATER_IDLE`；不存在能绕过候选、剩余预算或安全出口校验的 `MoveOnWater*` 权威旁路。
- 未装备踏水能力、能力等级不足、轻功切换尚未提交、角色被控制或水面区域不可用时，只展示 26 返回的拒绝原因；UI 不允许临时放行或把点击改写为岸边成功。
- 越障或踏水过程中，普通移动、交互、换装、传送和开战输入按 26 返回的 input lock 策略禁用；ESC 只能请求取消可取消的瞄准阶段，不能中止已提交的权威位移。
- 顶层选点经 InputActionRouter 取得选点输入锁并关闭 Y3 内置 `RIGHT_MOUSE_UNIT_MOVE`；入水接受后，该锁升级为父 TraversalSession 持有的通行输入锁，直到安全离水或恢复才释放。嵌套水面选点只租借覆盖层/焦点子锁；取消或完成嵌套选点仅回收子锁，不能恢复普通移动或重新开启 `RIGHT_MOUSE_UNIT_MOVE`。顶层取消、命令拒绝以及父会话完成/切图/断线/异常恢复均走按 owner 分层的 finally 清理，防止右键确认穿透或父锁被子页面误释放。
- 本地鼠标进入、离开或点击 TraversalCell 只更新悬停、路径和选择预览；只有同步 `ConfirmLightnessTarget` 才提交 `RequestTraversal`。
- 点击 UI、拖拽物品和框选文本不得穿透到世界。
- 镜头固定斜俯视；镜头运动不改变导航目标。

### 7.3 轻功表现权威边界

- `RequestTraversal` 返回接受结果并建立或复用 TraversalSession 后才能播放起跳、踏水或攀越主动画；候选格、高亮和轨迹线只是预览，不代表命令已接受。
- 接受结果给出的 traversal_session_id、逐段 command_id/segment_sequence、link_ids、起点、落点和路径采样是唯一表现输入。表现器可插值、加残影和水花，但不能改落点、规则阶段或碰撞结果。
- `TraversalLanded` 到达后，单位逻辑位置必须校准到事件中的权威安全点；动画提前到达时等待事件，动画超时时瞬移校准并记录诊断。
- `RequestTraversal` 返回拒绝 Result 时不播放成功位移；按错误码显示能力提示、不可达提示或安全恢复提示。
- `WaterWalkEntered` 与 `WaterWalkExited` 控制水面脚步、涟漪和导航层视觉；Y3 单位是否看似站在水面不构成授权。
- `TraversalRecoveryRequired` 到 `TraversalRecoveryCompleted` 期间使用遮罩或受控回正表现，禁止玩家输入；恢复由 26 编排、12 解析并返回 `last_safe_marker_id`，19 不读取 UI 缓存坐标或自选最近点。
- 表现帧率、动画取消、镜头遮挡、特效缺失或快进不得改变 TraversalEvent 顺序和最终位置。

### 7.4 页面栈

- HUD 常驻但可按模式隐藏子区域。
- 普通 PANEL 默认同层互斥；MODAL 必须返回到原焦点。
- ESC/返回只执行顶层 ScreenDescriptor 的 close_policy。
- BUSY 页面不能被普通返回关闭；可取消命令必须由用例明确提供 Cancel。
- RESULT_UNKNOWN 页面只能查询结果或安全重试，不能生成新幂等键。

### 7.5 战斗表现

- 事件按 combat_id、sequence 严格消费；缺号时暂停并请求补齐/报告。
- CombatEvent 是通用 DomainEvent 信封的确定性专化：event_id 固定为 combat_id 与 sequence 的规范组合，aggregate_id=combat_id，revision=sequence，occurred_at 省略；专有字段为 combat_id、sequence、action_index 和 payload。
- 表现器可以等待上一 Cue、并行播放明确并行组或快进，但不能改变事件。
- 全自动、手动绝招只影响 CombatCommand 的产生，不由动画判断技能是否成功。
- 跳过后必须立即把血条、状态图标、位置和资源同步到事件流最终状态。
- Cue 超时使用 fallback 并继续队列，不能阻塞领域战斗。

## 9. 事件契约

### 9.1 UI 消费的领域事件

- QuestAccepted、QuestObjectiveProgressed、QuestCompleted。
- ItemGranted、EquipmentEquipped、EquipmentUnequipped、FormationChanged。
- CombatStarted、CombatFinished，以及 06 定义并通过 EventSchemaRegistry 注册的具体 CombatEvent；不存在 CombatEventProduced 这一领域事件。
- SaveReadOnlyEntered、SaveCheckpointCommitted、SaveRecoveryRequired。
- ArenaScoreChanged、EntitlementReconciled、GachaDrawCommitted。
- 26 注册的 TraversalCandidateSetInvalidated、TraversalLanded、WaterWalkEntered、WaterWalkAdvanced、WaterWalkExited、TraversalRecoveryRequired 和 TraversalRecoveryCompleted；请求接受或拒绝只由对应 CommandResult 呈现，不另造 Authorized/Rejected 同义事件。

### 9.2 UI 输出边界

UI 不发布持久化领域事实，只提交命令：

- 设置提交给 24 的 CommitSettings；成功事件为 24 定义的 SettingsChanged。
- 教程确认提交给 24 的 AdvanceTutorial；成功事件为 TutorialStepAdvanced 或 TutorialCompleted。
- 对话选择提交给 13 的选择用例；成功事件复用完整 DialogueChoiceCommitted Schema，不在本文缩减 payload。

UIAnchorAvailable、ScreenOpened、ToastShown 等是 presentation 内部信号或遥测，不使用 DomainEvent 信封、不写玩家存档，也不得独立推进任务、奖励或教程领域状态。

## 10. 存档 DTO 与槽位

本系统没有独立存档 DTO，也不注册任何 SectionOwner。24 是设置和教程的唯一所有者：玩家云偏好提交槽 1 settings_profile section，教程进度提交槽 5 tutorial_progress section，设备画质写设备本地存储。本文只读取其 ViewModel，不直接调用 SaveStore/SaveCoordinator 写入。

页面栈、当前焦点、弹窗、临时筛选、拖拽对象、战斗 Cue 队列、内部 UIAnchorAvailable 信号和忙碌动画均不保存。

## 11. Y3 适配

- UI 节点创建、Prefab、文本、图像、进度条和事件全部封装在 y3_ui_adapter。
- ScreenDefinition 使用稳定 prefab_id；数字 UI/物编 Key 仅在 mappings。
- 分辨率变化时重新计算安全区和锚点，不重建领域会话。
- 世界点击先由 UI 命中测试过滤，再做地面/单位射线结果转换。
- 越障点击保留命中点、命中层和候选目标语义，交给 26 查询 TraversalLink；适配器不得直接关闭碰撞、跨导航层瞬移或把水面伪装成普通地面。
- 跳跃曲线、角色朝向、动画、残影、水花和镜头跟随只由 TraversalPresenter 驱动；逻辑位置在事件边界与 26 的权威位置对齐。
- 水面移动每次只使用 26 签发的本局 TraversalSession；切地图、换装失去能力、断线或恢复后旧 session 必须失效。
- 地面格覆盖层优先使用 23 预烘焙的稳定 traversal_cell_id 和批次映射；Y3 适配器只实例化可见表现，不在本地重新计算权威可达性。
- 灰盒阶段首选 Point SceneUI 在世界点承载格子点击/悬停；它始终朝向镜头且可能对所有玩家可见，因此仅适用于首发单人实例，不能承担多人私有信息隔离。
- TraversalCell 标记必须由 traversal_marker_pool 复用：按视锥、距离与 max_visible_cells 分批租借，关闭、刷新或销毁时全部归还，不得为每次打开永久创建节点。密集地图若 Point SceneUI 超预算，降级为低成本地面特效或不可选标记单位；交互仍通过世界射线与 traversal_cell_id 解析。
- Point SceneUI、地面特效和标记单位三种实现消费同一 Overlay ViewModel；fallback 不能改变候选集、隐藏格规则或确认命令 payload。
- Y3 动画、特效、音效或单位句柄失效时返回可诊断结果并执行 fallback。
- UI 事件订阅在页面销毁时成对解除；重复打开不得叠加监听器。

首章至少覆盖：

## 13. 边界、失败与静态校验

### 13.1 边界与失败

- 页面收到旧 view_revision 时提示刷新，不提交陈旧价格、阵型或奖励。
- 重复点击在同一 command_id 完成前被吸收。
- Y3 回调晚于页面关闭时，只更新 CommandPresenter，不访问已销毁节点。
- 任意退出选点路径若未归还 InputActionRouter lock、恢复 `RIGHT_MOUSE_UNIT_MOVE` 或清空 marker pool，记录 `TRAVERSAL_INPUT_LOCK_LEAK`/`TRAVERSAL_MARKER_LEAK` 并执行强制清理。
- CombatEvent 缺失、重复或乱序：重复去重，乱序缓存，缺号超时进入诊断但不猜测。
- 极宽、极窄或低分辨率下优先保持关键按钮、安全区和可读字号。
- 本地化缺失显示受控占位键并记错误，不显示空按钮。
- SAVE_READ_ONLY 模式保留浏览和设置入口，屏蔽一切进度型命令。

### 13.2 生成校验

- screen_id、prefab_id、控件 ID、action_id 和 cue_id 唯一。
- Prefab、字体、图标、动画、音效、特效和本地化引用存在。
- 页面锚点无循环约束，关键控件处于安全区。
- 同一 input context 中不可存在同优先级冲突绑定。
- `OpenLightnessTargeting/MoveLightnessCursor/ConfirmLightnessTarget/CancelLightnessTargeting` 在 EXPLORE/TRAVERSE 上下文均有合法键鼠路径，且不会与菜单、文本输入或 3×3 阵型操作冲突。
- LightnessTargetOverlayDefinition 的陆地有效、水面有效、无效、悬停、选中、路径和不可达原因样式完整，色弱主题含非颜色编码，低特效 fallback 保留关键选点信息。
- 每个提交按钮关联稳定 use_case、忙碌态和错误映射。
- 每种 CombatEvent 有 Cue 或明确 fallback。
- EventSchemaRegistry 中所有被消费事件存在、版本兼容且 payload 字段满足对应 ViewModel 绑定。
- Tab 顺序、初始焦点和返回策略完整。

## 15. 验收标准

- 玩家只用鼠标或键盘均可完成首章关键流程。
- 玩家只用鼠标或键盘均可完成首章必经基础跳与可选踏水教学；多候选落点可以明确选择并取消瞄准。
- UI、动画和 Y3 视觉位置不能绕过 26 的 LightnessTraversalProfile、TraversalLink、WaterSurfaceZone、输入锁或安全恢复判定。
- 选点覆盖层能显示当前轻功可跳跃/可踏水到达的地面格范围，鼠标和键盘均可完成打开、移动、确认、取消；预览与确认间状态变化必由 26 重校验并拒绝陈旧结果。
- UI 不能绕过领域条件修改物品、任务、阵型、积分或权益。
- 任何提交型按钮重复点击都不会产生第二次业务结果。
- 战斗以不同动画速度、掉帧或跳过播放时最终状态和事件哈希一致。
- 所有首章页面在目标分辨率组合下无关键控件越界或不可点击。
- 存档只读、恢复和结果未知状态不会伪装成普通成功/失败。
- 页面反复进入退出不存在重复事件订阅或持续输入卡死。
- 选点态任何正常或异常退出后 `RIGHT_MOUSE_UNIT_MOVE`、世界移动和交互输入恢复，marker pool 无泄漏；密集格按预算降级仍可完成选点。
