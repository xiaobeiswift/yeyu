# 《雾州侠行》经脉与长期成长系统工程规格

> 状态：工程实施规格候选稿；仅描述未来实现，不代表代码或内容配置已经存在。
>
> 上位约束：[00-通用工程约定](./00-通用工程约定.md)。

## 1. 目标与非目标

### 1.1 目标

- 为每名可养成角色提供可读、可规划、无随机失败的经脉节点网络和境界晋升路径。
- 通过真气、材料、角色等级、前置节点和剧情条件形成中后期长期成长，同时不制造主线体力门槛。
- 节点只授予白名单属性修正、效果、武学槽/上限或规则标签；角色最终属性仍由属性系统统一重算。
- 激活、晋升、消耗、存档和事件必须形成可恢复、幂等的单一业务结果；跨槽按 18 Saga 前向恢复，不承诺云端 ACID 回滚。公开擂台快照只保存最小节点/境界事实并本地重建。
- 支持配置图的静态可达性、成本包络、互斥路线和旧版本迁移验证。

### 1.2 非目标

- 不定义角色等级经验、武学十重升级、装备强化、门派身份、采集/制作熟练度或卡池成长。
- V1 不实现随机冲穴成功率、走火入魔、离线修炼、时间加速、付费重置、经脉 PvP 专用词条或无限循环天赋盘。
- 不允许以本地时间累计修炼收益；如后续加入可信时间收益，须另立 ADR 和防篡改测试。
- 不让经脉节点直接执行任意脚本、发物品或改任务状态；跨系统结果必须经白名单应用用例。

## 4. 领域模型

### 4.1 `MeridianDefinition`

| 字段 | 类型/范围 | 说明 |
|---|---|---|
| `meridian_id` | `meridian_*` | 经脉板 ID |
| `owner_scope` | `CHARACTER_SPECIFIC/ARCHETYPE` | 专属或角色原型复用 |
| `character_or_tag_id` | 稳定 ID | 与 scope 对应 |
| `node_ids` | 有序 ID 列表 | 完整节点集合 |
| `starting_node_ids` | 非空子集 | 无前置起点 |
| `max_active_nodes` | 1–256 | 图硬上限；通常等于节点数 |
| `graph_version` | 正整数 | 存档/公开快照兼容 |
| `layout_id` | 稳定 UI 布局 ID | 不影响规则 |
| `deprecated` | 布尔 | 兼容旧角色 |

### 4.2 `MeridianNodeDefinition`

| 字段 | 类型/范围 | 说明 |
|---|---|---|
| `node_id` | `node_meridian_*` | 稳定 ID |
| `meridian_id` | 合法板 ID | 所属图 |
| `node_type` | `MINOR/MAJOR/GATE/CORE` | 展示与部分条件 |
| `prerequisite_mode` | `ALL/ANY/COUNT` | 前置模式 |
| `prerequisite_node_ids` | 有序列表 | 起点必须为空 |
| `prerequisite_count` | 非负整数 | COUNT 模式使用 |
| `exclusive_group_id` | 可空 | 同组最多激活一个；V1 首章默认无互斥 |
| `character_level_required` | 1–100 | 等级门槛 |
| `realm_required` | `realm_*` 或空 | 境界门槛；不得形成死循环 |
| `condition_set_id` | 条件集合或空 | 剧情/伙伴/门派白名单 |
| `cost_set_id` | `cost_*` | 真气/材料/铜钱 |
| `grant_set_id` | `progressgrant_*` | 属性/效果/标签集合 |
| `ui_position_id` | `uipos_*` | 位置映射，不存裸 Y3 坐标句柄 |
| `is_refundable` | V1 false | 激活不可逆 |
| `deprecated` | 布尔 | 旧档兼容 |

### 4.3 `ProgressionGrant`

| 字段 | 说明 |
|---|---|
| `grant_type` | `STAT_FLAT/STAT_RATE_BP/PASSIVE_EFFECT/RULE_TAG/MARTIAL_LEVEL_CAP/LOADOUT_SLOT` |
| `target_id` | 属性、效果、规则或槽标签稳定 ID |
| `value` | 整数；布尔标签使用 1 |
| `stack_policy` | `ADD/MAX/UNIQUE`，由类型固定白名单 |
| `entry_order` | 规范化顺序 |

V1 的 `LOADOUT_SLOT` 只能解锁预先定义的非装备成长槽，不能增加战斗上阵人数或装备槽。

`ProgressionGrant` 是配置输入，不是第二套属性 DTO。解析规则固定为：

- `STAT_FLAT` 输出 01 `StatContribution{source_type=PROGRESSION, operation=ADD_FLAT}`。
- `STAT_RATE_BP` 输出 `StatContribution{source_type=PROGRESSION, operation=ADD_BP}`，不得在本系统提前乘入属性。
- `source_id` 规范为 `node_id + ":" + entry_order`；境界 grant 使用 `realm_id + ":" + entry_order`。
- `target_stat=target_id`、`value=value`；`priority` 来自冻结的经脉贡献优先级，`condition_tags` 是排序去重后的战前上下文标签列表，无条件时为空列表。
- `stable_order_key` 规范为 `progression:<meridian_id>:<realm_sequence>:<node_id_or_realm_id>:<entry_order>:<target_stat>:<operation>`；不得使用 UI 图坐标或激活时间。
- `stable_order_key` 在完整构筑内必须唯一；输出严格按 01 的 `(priority,stable_order_key)` 排序，同键整份构筑拒绝。任何供 UI 展示的分组/总计都只是 view，不进入战斗快照、存档或公共 DTO。

### 4.4 `CharacterProgressionState`

| 字段 | 类型 | 说明 |
|---|---|---|
| `character_id` | `char_*` | 聚合 ID |
| `meridian_id/graph_version` | 稳定 ID/整数 | 绑定配置版本 |
| `active_node_ids` | 排序后的集合 | 权威事实，不保存 `AVAILABLE` |
| `realm_id` | `realm_*` | 当前境界 |
| `node_activation_ordinals` | `node_id -> 正整数` | 审计和表现顺序，不参与加成 |
| `progression_revision` | 非负整数 | 每次激活/晋升加 1 |

节点状态 `LOCKED/AVAILABLE/ACTIVE/UNAVAILABLE_EXCLUSIVE/CONFIG_ORPHAN` 都由当前事实派生；存档只保存 active 集合。

### 4.5 `RealmDefinition`

字段：`realm_id`、`sequence`（从 1 连续）、`name_key`、`required_previous_realm_id`、`required_character_level`、`required_active_node_count`、`required_node_ids`、`condition_set_id`、`cost_set_id`、`grant_set_id`、`next_realm_id?`、`deprecated`。

## 5. 配置表与字段

### 5.1 图与前置关系表

源表分为 `meridians`、`meridian_nodes`、`meridian_edges`。边表字段：`meridian_id`、`from_node_id`、`to_node_id`、`edge_order`。生成器将边归一化为节点前置列表，同时验证有向无环和从起点可达。

### 5.2 `progression_cost_sets`

| 字段 | 约束 | 说明 |
|---|---|---|
| `cost_set_id` | `cost_*` | 成本集合 |
| `entry_order` | 从 1 连续 | 稳定顺序 |
| `resource_type` | `CURRENCY/ITEM` | 资源类型 |
| `resource_id` | 合法货币/物品 | 真气使用 `currency_true_qi` |
| `quantity` | 1–2,000,000,000 | 正整数 |

### 5.3 `progression_grant_sets`

字段使用 4.3；同一 grant set 内 `UNIQUE` 目标不得重复，属性值组合需通过最坏包络校验。

### 5.4 `realm_definitions`

使用 4.5 字段。`sequence` 在同一境界轨道内必须连续，最后一阶 `next_realm_id` 为空。境界成本不能依赖由本次境界 grant 才产生的条件。

### 5.5 条件白名单

允许：角色等级、伙伴已加入、任务/章节标记、门派身份/声望阶、指定节点已激活、指定境界、玩家功能解锁。禁止：本地日期、UI 状态、随机、最终攻击力阈值、平台付费金额、任意 Lua 表达式。

## 6. 运行时状态与不变量

### 6.1 会话状态

- `ProgressionSession`：角色状态索引、槽3基础修订、配置/图版本、贡献缓存。
- `ActivationPreview`：角色、节点、基础修订、条件缺口、成本、预期 grant、预览签名。
- `ProgressionMutation`：命令 ID、预留资源、变更前后状态、槽3/4/5提交状态。

### 6.2 不变量

1. 每个 active 节点存在于角色合法图中，且其前置在激活时满足。
2. 同一互斥组 active 节点不超过 1；迁移不能默默替玩家选择保留项。
3. active 数量不超过 `max_active_nodes`，激活序号唯一且单调。
4. 当前境界必须属于角色轨道，且所有历史必需境界条件可由当前事实解释。
5. 贡献完全由当前配置兼容版本与 active 节点/境界重算，不保存最终属性。
6. 资源不足、条件变化、存档冲突或只读状态下不得激活。
7. 战斗会话创建后成长修改不影响该场战斗；新贡献只进入下一快照。

## 7. 规则、公式与状态机

### 7.1 节点可用性

对未激活节点按顺序计算：图/版本合法 → 互斥组空闲 → 前置模式满足 → 角色等级 → 境界 → 外部条件 → 资源是否足够。UI 可显示多个缺口，但命令返回稳定优先级最高的错误码；资源不足只影响“可购买”而不改变图上的 `AVAILABLE_BY_PATH`。

- `ALL`：所有前置 active。
- `ANY`：前置非空且至少一个 active。
- `COUNT`：active 前置数量 ≥ `prerequisite_count`；count 必须在 1..前置数。

### 7.2 激活状态机

`LOCKED → AVAILABLE → RESERVING → ACTIVATED → COMMITTED`。

验证失败保持原状态；资源预留失败释放；提交未知进入 `ACTIVATION_UNKNOWN` 并锁定该节点按钮，通过收据查询。同节点不同命令在旧修订上提交返回冲突；同幂等键返回原激活结果。

### 7.3 贡献汇总

1. 按境界 `sequence`，再按节点 ID，最后 grant `entry_order` 排序。
2. `STAT_FLAT` 和 `STAT_RATE_BP` 分别转换为 canonical `ADD_FLAT`、`ADD_BP` 条目；不得先聚合成自定义 DTO。01 属性解析器负责相同属性/操作的最终处理。
3. `MAX` 取最大整数，`UNIQUE` 只保留一项且生成阶段防重复。
4. 汇总中间值使用宽整数检查，输出必须落在属性系统允许区间。
5. 输出 `source_id` 保留节点/境界来源，方便 UI 和公共快照诊断。

最终属性乘区和上下限由 01 定义；本文不把 `RATE_BP`直接乘入基础值。

### 7.4 境界晋升

- 只能从当前境界晋升到配置的直接 `next_realm_id`，不能跳阶。
- 同时满足等级、active 节点数量、必需节点和剧情条件，再以资源子收据与成长子收据推进可恢复事务。
- 晋升必成、不可随机、V1 不可降阶。
- 若新境界 grant 提升武学上限，已超过旧上限的非法旧状态先由迁移处理，不能靠晋升修复。

### 7.5 重置策略

V1 无重置：所有 `is_refundable=false`。界面必须在首次激活前说明不可逆。未来加入重置需定义成本、返还比例、互斥分支、战斗快照、公开擂台、任务依赖和迁移；在 ADR 完成前不得增加隐藏重置命令。

## 8. 应用用例契约

| 用例 | 输入 | 前置 | 事务/幂等 | 输出 | 主要错误 |
|---|---|---|---|---|---|
| `GetMeridianBoard` | character ID | 角色已解锁、存档已加载 | 只读 | 节点派生状态、缺口、贡献、修订 | `CHARACTER_NOT_FOUND`、`PROGRESSION_CONFIG_ORPHAN` |
| `PreviewNodeActivation` | character、node | 图合法 | 纯计算，绑定修订/版本 | 成本、grant、缺口、token | `NODE_NOT_FOUND` |
| `ActivateMeridianNode` | character、node、token、`command_id` | 可用、资源足、非战斗限制 | 槽5父意图→槽4资源子收据→槽3成长子收据→COMMITTED，按18 Saga恢复 | 新状态、贡献差、余额、修订 | `NODE_PREREQUISITE_MISSING`、`RESOURCE_INSUFFICIENT`、`PREVIEW_STALE` |
| `PreviewRealmAdvance` | character | 有下一境界 | 纯计算 | 条件、成本、grant、token | `REALM_MAX_REACHED` |
| `AdvanceRealm` | character、target realm、token、`command_id` | 只能下一阶、全部条件满足 | 与激活相同的三槽可恢复 Saga；幂等 | 新境界、贡献差、修订 | `REALM_REQUIREMENT_MISSING`、`SAVE_REVISION_CONFLICT` |
| `GetProgressionContribution` | character、expected version? | 状态可重建 | 只读/可缓存 | canonical `StatContribution[]` + 规则标签 + 哈希 | `RULE_VERSION_UNSUPPORTED` |
| `ValidateArenaProgression` | public DTO、规则版本 | 白名单 | 只读确定性 | 重建贡献或拒绝清单 | `PUBLIC_PROGRESSION_INVALID` |
| `ResolveProgressionUnknown` | receipt ID | 未知事务 | 查询槽3/4/5 | 明确结果/仍未知 | `SAVE_UNAVAILABLE` |

预览 token 绑定角色/节点或境界、成长修订、资源修订、配置版本、成本和 grant 哈希。UI 不得提交自定义成本或贡献。

## 10. 存档 DTO、槽位与迁移

### 10.1 槽 3 `ProgressionSaveDTO`

为满足三层嵌套，使用平行表：

| 字段 | 形态 | 说明 |
|---|---|---|
| `character_progression` | `character_id -> 扁平元数据` | meridian、graph_version、realm、revision、next_ordinal |
| `active_meridian_nodes` | `character_id -> 版本化有序 ID 编码` | 解析后去重和范围校验 |
| `node_activation_ordinals` | `character_id -> 版本化 ID/序号编码` | 可丢弃重建时须明确迁移策略 |

槽 5 保存父事务及恢复索引，槽 4 保存资源子收据与已扣资源，槽 3 保存成长子收据和状态。应用层严格引用 18 `PendingTransaction` 的有序步骤、结果查询和前向恢复；已确认的资源或成长步骤不得通过猜测性回滚改写，领域层不知道槽号。

### 10.2 公开快照

槽 100 仅保存：`character_id`、`meridian_id`、`graph_version`、`realm_id`、排序后的 active node IDs。不得保存最终属性、贡献总值、成本或激活时间。校验顺序：数量硬上限 → ID 白名单 → 图归属 → 前置可达 → 互斥 → 境界合法 → 重算贡献。

### 10.3 迁移规则

- 新增节点不修改旧 active 集合；玩家按新规则自行激活。
- 删除/下线节点必须保留兼容壳，或提供 `old_node_id -> new_node_id/compensation` 显式映射。
- 拆分一个节点为多个节点时不得自动多给价值；迁移 ADR 固定等价目标与补偿，使用永久收据。
- 前置图改变不得使旧合法 active 集合直接被删除。私人档案可标记 `LEGACY_ACTIVE` 并保留效果至明确重置；公共快照只能接受当前或声明兼容规则版本。
- 迁移必须先重建和验证副本，再一次写入；重复执行结果相同，失败进入只读恢复。

## 11. Y3 适配与 UI

### 11.1 Y3 适配

- 经脉图是 UI 数据渲染，不创建 Y3 单位或把 UI 节点句柄写入状态。
- `ui_position_id` 映射锚点/连线资源；连线亮起仅响应已提交事件。
- 激活动画、音效、镜头和数值飘字不参与成功判定；动画中断后从最新修订重建页面。
- 战斗/擂台适配器在构造快照时读取规范化贡献，不直接解析 UI 或存档紧凑字符串。
- 保存失败统一进入只读/未知恢复，不能在本地先亮节点后假定成功。

### 11.2 UI 状态和交互

页面支持 `LOADING/READY/BUSY/READ_ONLY/ERROR/CONFIG_ORPHAN/COMMIT_UNKNOWN`。

- 图上明确 `LOCKED/路径可用但资源不足/可激活/已激活/互斥不可用/兼容旧节点`。
- 点击节点显示前置、实际成本、激活后属性/效果差值、不可逆说明和来源。
- 线条只表达配置边，不让视觉距离暗示费用或顺序。
- 多缺口按“剧情/境界/等级/前置/资源”分组显示，玩家能从来源跳转到任务/物品帮助页。
- 激活按钮在提交期间禁用；未知提交显示核对页；成功后只播放一次并将属性差值交给角色面板。
- 境界页显示当前和下一阶全部条件，不把隐藏剧情文本提前泄露；未解锁条件可显示本地化模糊提示。
- 无引擎可访问性要求：节点可用键盘按稳定图序遍历，颜色之外用图形/文本区分状态。

## 12. 边界、失败与恢复

| 场景 | 必须行为 |
|---|---|
| 图存在环或不可达节点 | 配置构建失败，正式运行不得加载该版本 |
| 节点预览后角色/资源变化 | token 失效，刷新，不自动扣费 |
| 资源扣除与槽3写入未知 | 节点锁定为核对中，按收据恢复；不得再点 |
| active 节点 ID 未知 | 私人档隔离/兼容恢复，公共快照拒绝 |
| 互斥组旧档双激活 | 不静默选一；进入迁移决策或只读恢复 |
| 达到属性上限 | 若配置最坏包络本应合法却运行溢出，命令失败并视为 P1 配置缺陷 |
| 战斗中激活 | V1 允许打开只读；修改返回 `PROGRESSION_COMBAT_LOCKED` |
| 角色暂时离队 | 状态保留，不可编辑；回归后恢复 |
| 下线角色 | 不删除成长状态；UI 隐藏但迁移/存档仍读取 |
| 本地时钟修改 | 对系统无影响；无离线收益与时间门槛 |

## 13. 数据生成与校验

必须执行：

- ID、图归属、起点、前置、重复边、自环、有向环、从起点可达性和最大节点数校验。
- `ALL/ANY/COUNT` 参数组合、互斥组可达性、必需节点与互斥选择冲突校验。
- 节点 `realm_required` 与境界 `required_node_ids` 的跨依赖死锁检测。
- 成本货币/物品来源可达、数量溢出、总板最小/最大成本和首章资源包络。
- grant 类型/目标/stack policy 白名单、最终属性最坏组合、重复 UNIQUE 和未支持槽位校验。
- 每个 `STAT_FLAT/STAT_RATE_BP` 都能生成字段完整、优先级合法且含 `stable_order_key` 的 00/01 canonical `StatContribution`；禁止使用 `stat_key/condition_tag` 或输出自定义贡献 DTO。
- 角色/原型恰好绑定一个有效经脉板，公开允许版本具有兼容读取路径。
- UI 布局每节点有位置、连线无悬空；布局问题可阻断 UI 构建但不影响纯领域生成报告。

报告输出每板节点数、起点/终点、所有可达路径、互斥选择数、全激活成本、各境界最早可达条件、最大属性贡献和旧版本差异。

## 15. 验收标准

- 五名首章角色均能加载合法成长板，节点状态和贡献在 Lua 5.1 无引擎环境可重算并哈希一致。
- 激活/晋升必成且不可跳过条件；资源、成长和收据在任一故障注入点可恢复为唯一业务结果。
- 任意配置图无环、无不可达节点、无境界死锁，成本和属性包络报告通过。
- 保存重进、角色离队/回归、旧版本迁移不丢 active 节点、境界或修订。
- 战斗开始后修改不污染进行中快照；擂台公开数据无法伪造最终属性或非法节点。
- UI 能解释每个节点为什么不可激活、将获得什么、是否不可逆，并覆盖只读/未知状态。
- 所有单元、属性、契约、迁移、Y3 冒烟和公共快照安全测试通过，P0/P1 为零。
