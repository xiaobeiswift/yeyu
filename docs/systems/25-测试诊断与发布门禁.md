# 测试、诊断与发布门禁系统工程规格

> 状态：待评审
>
> 遵循：[通用工程约定](./00-通用工程约定.md)

## 1. 目标与非目标

本系统定义全项目的自动测试、契约测试、引擎验收、故障注入、结构化诊断和发布门禁，使每个系统的完成状态可证实、可复现、可回归。

目标：纯 Lua 规则脱离 Y3 测试；同快照同种子可验证；配置错误在构建前失败；轻功跳跃/踏水与地图可达性可复现；存档、权益和擂台有故障路径；每个候选构建具备可追踪测试证据。

非目标：不以大样本统计替代精确规则测试；不把日志当作事务；不收集非必要个人数据；不允许人工“感觉能玩”替代硬门禁。

## 2. 质量分层

| 层级 | 目标 | 运行环境 |
|---|---|---|
| L0 静态校验 | 配置 Schema、断链、依赖方向、禁用 API | 生成/检查工具 |
| L1 领域单元 | 公式、状态机、迁移、AI、积分、保底 | Lua 5.1，无 Y3 |
| L2 属性/模型测试 | 大范围输入不变量、确定性、边界 | Lua 5.1 |
| L3 端口契约 | Fake 与 Y3 适配遵守同一语义 | Lua + 适配测试壳 |
| L4 系统集成 | 多系统事务、存档、任务奖励、战斗结算 | Y3 测试地图/模拟壳 |
| L5 E2E | 新档、完整首章、老档升级、双账号擂台 | Y3 客户端与平台测试环境 |
| L6 非功能 | 性能、稳定性、弱网、故障、安全与合规 | 目标设备/平台环境 |

建议测试组合以 L0–L2 为主体，L3–L4 覆盖所有端口和事务边界，L5–L6 覆盖关键旅程与平台真实行为。

## 4. 确定性测试

### 4.1 战斗黄金样本

输入：双方完整合法快照、Encounter、rules_version、seed、模式。输出：标准化事件流哈希、胜负、行动数、最终状态摘要。

标准化必须固定字段顺序、数字精度、列表顺序和空值表达；排除表现时间、Y3 句柄和日志时间。规则有意变化时，由评审确认黄金变更原因，不能批量无审查更新。

### 4.2 不变量

- 相同输入始终输出相同哈希。
- HP 不低于 0、不高于合法上限；资源在规则范围内。
- 已死亡单位不再获得普通行动。
- 事件 sequence 连续且引用存在的 actor/target。
- CombatEvent 满足统一信封专化：event_id 可由 combat_id/sequence 唯一重建，aggregate_id=combat_id，revision=sequence，occurred_at 为空。
- 完整结算第 99 个行动机会后仍无胜负即 TIMEOUT：PVE 失败，擂台判进攻方失败；不得执行第 100 个行动。
- 表现速度、日志开关和 UI 模式不改变结果。
- 集合插入顺序变化不改变有明确排序的规则结果。

| 格子覆盖层 | 陆地有效、水面有效、无效、悬停、选中落点、路线和不可达原因均显示；颜色之外有纹样/图标；与战斗 3×3 阵位完全隔离 |
| 输入 | 鼠标与键盘分别完成 OpenLightnessTargeting、MoveLightnessCursor、ConfirmLightnessTarget、CancelLightnessTargeting；文本输入、菜单、重复点击和右键普通移动不穿透 |
| 权威边界 | 悬停、绿色格、预览路径和本地点击均不移动角色；仅同步 Confirm 调用 `RequestTraversal`；确认前改变起点或来源向量任一分量必须拒绝旧候选并刷新 |

| 水面 | 入水后保留唯一踏水总会话；每段以 parent 匹配的嵌套选点和新 command_id 移动，取消只回 ON_WATER_IDLE 且不释放父 WorldControl/普通移动禁用；覆盖连续寻路、转向、离水、无出口、父会话失配与区域失效；只有 `WaterWalkEntered`、`WaterWalkExited` 改变踏水事实 |
| 动态阻挡 | 打开选点后生成/移除阻挡、任务改变连接、昼夜切换、spatial_revision/world_revision 更新；不逐帧全图重算，但失效通知后必须刷新 |
| 隐藏内容 | reveal policy 未满足的格、秘密出口、隐藏 link 和其不可达轮廓均不进入 UI payload、日志截图或候选哈希的玩家可见部分 |
| 能力换装 | TraversalSession 进行中禁止换下所需轻功；水面外换装立即更新候选；非法外部状态导致失去 WATER_WALK 时进入受控安全恢复，不留在水中 |
| 中断恢复 | 起跳、空中、落地前、入水、水面移动、离水各点断线/切图/句柄失效；26 编排、12 解析后只能恢复到已保存 `last_safe_marker_id`，不能复制位移收益或卡死 |
| 大量格 | 密集格、超长视距和不同相机角度下只实例化预算内可见 marker；候选计算按打开/revision 更新触发，marker pool 可完全回收 |
| 分辨率/可访问性 | 16:9、16:10、21:9、低分辨率、DPI、色弱、高对比、低特效下光标、落点、路径、有效/无效与取消提示均可辨认 |

专项属性测试还必须证明：候选集不包含超过 Profile 距离/高度/clearance 的格；普通烘焙边与 TraversalLink 手工覆盖顺序稳定；每个安全落点都有 SAFE_GROUND marker；水面入口、水格、出口 cost 只累计扣除 `water_range_cells` 且每个候选保留预算内出口；同一逐段 command_id 重放只返回原 RequestTraversal 结果，不同段不得复用 ID。

## 6. 存档与迁移测试

- 为每个已发布 Schema 保存不可修改的代表性夹具。
- 每个夹具执行“读取 → 迁移 → 校验 → 再迁移”，第二次不得改变结果。
- 逐槽注入读取失败、写入失败、上传未知、旧修订和类型错误。
- 验证任何失败都不会用默认值覆盖仍可能有效的云档。
- 对槽 2–5 每个写前/写后、所有数据槽完成后以及槽 1 写前/写后注入崩溃；只有 Manifest 的 checkpoint_id/完整 revision-checksum 向量最后写入并回读后才算提交。
- 构造数据槽 revision/checkpoint/checksum 未被 Manifest 引用的 ORPHAN_SLOT_WRITE；验证不会静默采用，只有匹配 PendingTransaction 目标向量时可用同 checkpoint_id 前向完成。
- 验证跨槽部分成功不触发虚构的 ACID rollback；旧 Manifest 始终是提交边界，恢复只按有序步骤、结果哈希和收据前向进行。
- 验证 SectionOwnerRegistry 覆盖全部持久化路径；未注册、重复 owner、同槽路径重叠和非 owner 写入全部失败。
- 验证新版本写档回滚到上一兼容版本时的预期行为；不可逆迁移必须有发布门禁和回滚策略。
- 关键奖励在保存前后崩溃点分别注入，重进后只能得到一次。

## 7. 端口契约与故障注入

每个端口的 Fake 支持脚本化结果：成功、明确失败、超时、迟到成功、重复回调、顺序错乱、部分结果和未知字段。

故障点至少包括：

- 云档读/写/上传每个边界。
- 服务器时间不可用、回退和跨日瞬间。
- 公开档案缺失、陈旧、超大和非法。
- OpenArchiveService 必须保持只读；槽 100 发布只通过 SaveCoordinator，并进行写后回读确认。
- 排行发布成功但查询延迟、缺 AID 和整数越界。
- 商城取消、扣款后断线、重复成功回调和补单。
- 随机池消耗成功但结果未知、未知奖励 Key 和权益写入失败。
- 随机池同 request_id 重试与 query_pool_request 返回同一原结果，不能重新抽样；能力缺失时真实付费门禁失败。
- 平台整数 compare-and-add/set 的 CAS 冲突、响应未知、重复幂等键与 query_integer_request 原结果；paid counter 负增量、无条件 add 和余额镜像均必须被拒绝。
- ClockService 仅暴露 now；服务器周期和擂台赛季分别由 17/20 纯规则计算。

涉及真实平台的未知结果不得通过 Fake 推定已解决，必须在平台测试环境留下验证证据。

### 7.1 Y3 轻功适配风险验证

- Point SceneUI 在实际斜俯视镜头下验证世界点定位、始终朝镜头、点击/悬停命中、遮挡、缩放和所有玩家可见语义；首发单人实例可接受，多人场景不得把它当作私有信息边界。
- 用低、中、高密度 TraversalCell 灰盒记录 Point SceneUI 创建、池化复用、批次显隐、帧时间和内存基线；若超过候选构建预算，必须验证低成本地面特效或标记单位 fallback。
- 进入选点态关闭 `RIGHT_MOUSE_UNIT_MOVE`，覆盖确认、取消、拒绝、页面销毁、切地图、断线、脚本错误和恢复的输入锁释放；任何路径均不得残留无法移动或右键双重触发。
- Y3 单位位移、碰撞、寻路层、水面区域检测、动画中断和句柄失效均在最小验证地图实测；表现到达不等于权威落地。
- 对落点临时占用、导航重烘焙、区域卸载和水面能力丢失注入故障，确认 26 请求恢复、12 返回安全 marker，且 19 只按事件校准。

平台/引擎能力未实测时不得以 Fake 通过替代 Y3 证据；未知项标记为未验证并阻止包含强制轻功路线的候选构建。

## 8. E2E 关键旅程

### E2E-01 新玩家首章

新档 → 引导 → 招募 → 四系任选 → 主支线 → 两名首领 → 章节结算 → 保存退出 → 重进核对。不得使用开发命令。

### E2E-02 老档升级

加载上一发布版本夹具 → 自动迁移 → 继续任务 → 战斗/领奖 → 保存 → 再重进。核对任务、装备、阵型、武学、教程和运营状态。

### E2E-03 双账号擂台

A/B 发布覆盖槽 3、槽 4、权益游标和规则/内容版本的公开阵容 → 排行发现 → 互读快照 → 持久化挑战 intent → 挑战 → 首次计分 → 重复挑战不计分 → 跨日 → 赛季边界。额外在 intent 保存前、ARMED 后、运行中和结算前强退，验证只会用固定 seed/ArenaRuleBundle 重放或按冻结规则判负一次。

### E2E-04 卡池沙盒

测试币抽取 → 普通结果 → 硬保底 → 重复转化 → 定向兑换 → 崩溃恢复 → 迁移。真实付费另走平台门禁，不因沙盒通过而自动开启。

### E2E-05 云档故障恢复

模拟下载失败、槽 2–5 部分写入、槽 1 Manifest 写前/写后失败和上传未知 → 识别孤儿槽并进入只读/恢复 → 服务恢复 → 按同 checkpoint_id 前向对账 → 不丢档、不重复奖励。

### E2E-06 首章轻功探索

正常取得首章轻功 → 打开世界格选点 → 鼠标完成一次跳跃 → 键盘完成一次跳跃并取消一次选点 → 进入可选踏水教学/支路并装备踏水轻功 → 水面选点/移动 → 安全离水 → 保存重进。沿途分别改变六项 `ReachabilitySourceVector` 的 `spatial_revision`、`world_revision`、`source_loadout_revision`、`source_progress_revision`、`profile_hash`、`rules_version`，并注入跳跃中断线、水面中失去能力和落点被占用；核对隐藏格不泄漏、陈旧预览被拒绝、恢复只到安全格、教程跳过不授予能力。

## 9. 性能与稳定性

先登记最低、推荐和高档目标设备，性能验收必须写设备、分辨率、画质、场景和采样方式。

测量项：8 单位战斗帧时间、事件队列积压、UI 打开耗时、地图单位数量、轻功候选计算耗时、密集 TraversalCell 覆盖层帧时间、marker pool 峰值/回收量、来源向量失效刷新耗时、内存增长、长时间循环、保存载荷大小、存档序列化耗时、首章加载和传送稳定性。

性能预算不在本文凭空给固定数值；首次可玩构建建立基线，之后候选构建不得出现未解释的显著回退。任何影响玩法稳定帧率的回退阻止发布。

## 10. 诊断与日志

### 10.1 日志级别

- `ERROR`：事务未知、坏档、非法权益、无法恢复的系统失败。
- `WARN`：可降级服务、陈旧快照、配置豁免、迟到回调。
- `INFO`：用例开始/结束、迁移、战斗摘要、功能开关状态。
- `DEBUG`：详细领域事件，仅开发/测试环境启用。

### 10.2 关键字段

`build_id`、`content_version`、`rules_version`、`session_id`、脱敏玩家标识、`correlation_id`、`idempotency_key_hash`、`use_case`、`result_code`、`save_revision`、`combat_hash`。

不得输出完整订单凭证、平台密钥、未脱敏 AID 或可还原个人身份的数据。

## 11. 缺陷等级

| 等级 | 定义示例 | 发布要求 |
|---|---|---|
| P0 | 丢档、重复付费权益、非法扣款、严重安全/合规问题 | 零容忍 |
| P1 | 主线阻断、确定性漂移、排行榜污染、普遍崩溃 | 零容忍 |
| P2 | 有明确绕过路径的系统错误、明显体验破坏 | 必须评审并有修复计划 |
| P3 | 轻微表现、文本或低频非阻断问题 | 可带已知问题发布 |

无法稳定复现不降低等级；应先增加诊断和保存现场。

## 12. 发布门禁

### 通用门禁

- 配置生成零 error，warning 全部有有效豁免。
- L0–L4 必跑测试全部通过，无未知跳过。
- P0/P1 为零。
- 固定战斗黄金与大范围种子回归无非预期漂移。
- 所有历史存档夹具迁移通过且幂等。
- 新档、老档升级和云档恢复 E2E 通过。
- 功能开关、content manifest、rules version 与候选构建一致。
- SectionOwnerRegistry 无未注册/重复/重叠 owner；业务系统无整槽旁路写入，槽 1 Manifest 最后提交故障矩阵全部通过。

### 轻功探索门禁

- TraversalGrid/Cell 烘焙零 error；普通边、TraversalLink 覆盖、WaterSurfaceZone、落点/recovery 和强制路线能力来源校验全部通过。
- 首章强制目的地在对应能力检查点可达；JUMP_BASIC/JUMP_LONG/JUMP_HIGH/WATER_WALK 不存在后置、随机、付费或可错过的唯一能力来源。
- 可达集黄金测试、确认时权威重校验、同 command_id 重放、`TraversalLanded`、`WaterWalkEntered`、`WaterWalkExited` 契约全部通过。
- 动态阻挡、能力换装禁止、隐藏格不泄漏，以及跳跃/踏水断线安全恢复 E2E 通过。
- Point SceneUI 或已选 fallback 在登记目标设备、地图密度和分辨率下完成性能实测；marker pool 关闭/刷新后回到基线，无持续创建增长。
- `RIGHT_MOUSE_UNIT_MOVE` 与 InputActionRouter lock 在所有退出/故障路径恢复；鼠标和键盘均可打开、移动、确认、取消，且不与 3×3 阵位输入串线。
- 任一项失败时，不得发布包含强制特殊通行路线的首章（首章设计中仅基础跳为必经）；可回退到经内容评审的普通地面替代路线，但不能用 UI 绕过权威规则。

### 擂台门禁

- 双账号公开档/排行实测通过。
- 快照 source_revision_vector 完整覆盖槽 3、槽 4、21 的平台权益游标与 rules/content version；任一来源变化立即 DIRTY，陈旧发布回调不能误置 CLEAN。
- ArenaRuleBundle 发布后不可变；seed 可由 challenge_id、双方 snapshot_hash 和 bundle_hash 唯一重建。
- ARMED intent 在退出、崩溃和断线后只能以固定 seed 重放，或按 intent 冻结的 loss delta 结算一次，不能通过退出规避 -6。
- 非法快照、规则执行错误、非权威结果和事件 hash 不一致均 delta 0，且不写/不消耗每日首次胜利记录。
- 重复结算、每日首次计分、完整结算第 99 个行动机会和赛季边界通过。
- 不满足时关闭正式擂台不阻塞离线版本。

### 真实付费门禁

- 平台唯一事务或完整可恢复对账能力已验证。
- 重复/迟到/未知回调故障注入不吞单、不重发。
- 概率、由 total_draws-last_highest_draw_ordinal 派生的保底和由 earned_total-spent_total 派生的兑换规则精确校验。
- credential granted/consumed/refunded、total_draws、last_highest ordinal、token earned/spent 均为平台单调 totals；CAS、幂等键和原请求查询实测通过，不存在可递减余额镜像。
- EntitlementStore/CounterStore 仅作为 SaveStore 整数 CAS 门面，且 I/O 由 SaveCoordinator 编排；权益倒退统一返回 ENTITLEMENT_COUNT_REGRESSED，凭证不足统一返回 GACHA_CREDENTIAL_INSUFFICIENT。
- 21 是 PaidEntitlementCursor 唯一 owner；角色/武学只幂等消费固定 child receipt，同一 receipt 重放不会重复授予。
- 匿名抽取记录、公示和至少 90 天审计导出已确认。
- 实名、防沉迷、未成年人消费限制和素材合规完成审查。
- 任一项失败，`paid_gacha_enabled` 必须保持 false。

## 13. 测试数据管理

- 测试账号、商品和随机池使用独立测试环境标识。
- 黄金文件和存档夹具纳入版本控制，禁止包含真实个人数据。
- 随机测试记录失败 seed，失败用例自动收缩后固化为回归夹具。
- E2E 产生的权益和排行记录必须可识别并与正式数据隔离。
- 测试清理不能使用不受限递归删除；清理目标必须显式验证。

## 14. 验收标准

- 每个系统文档的测试矩阵都有对应测试位置或明确平台手工项。
- 任意战斗漂移能通过 seed、快照和 rules version 复现。
- 任意存档/权益事务能通过 correlation ID 追踪完整路径。
- 任意私人检查点能通过 checkpoint_id 证明槽 1 最后提交；任意部分写入都能识别为孤儿候选并在不假设跨槽回滚的前提下恢复。
- 任意排位 intent 能证明固定双方快照、ArenaRuleBundle、seed 与唯一积分收据；无效结果不会污染积分或每日首次胜利。
- 任意付费交易能证明平台单调 counter CAS、原请求结果、唯一 PaidEntitlementCursor 与下游 child receipt 链。
- 候选构建自动生成门禁报告并列出开关与已知问题。
- 任意轻功位移可由 traversal_session_id、起始/目标 TraversalCell、完整六项 `ReachabilitySourceVector`、candidate_set_hash、落地收据和最终安全格还原；预览层不能伪造成功。
- 平台能力不足时能安全关闭依赖功能并继续离线首章。
