# 《雾州侠行》悬赏、委托与可信周期系统工程规格

> 状态：工程实施规格候选稿；仅描述未来实现，不代表 Lua、Y3 触发器、任务内容或 UI 已经制作。
>
> 上位约束：[00-通用工程约定](./00-通用工程约定.md)、[ADR-0001 系统所有权矩阵](../architecture/ADR-0001-系统所有权矩阵.md)、[ADR-0002 跨槽可恢复事务](../architecture/ADR-0002-跨槽可恢复事务.md)。

## 1. 目标与非目标

### 1.1 目标

- 将 Y3 `ClockService.now()` 返回的可信服务器时间转换为稳定的日、周、活动和赛季周期，向其他领域提供唯一 `TrustedPeriodPort`。
- 为悬赏板和门派委托板生成“本玩家、本周期固定”的候选 Offer；同一档案种子、周期、配置版本与资格快照必须得到相同结果。
- 冻结本周期已经展示的候选、任务定义版本、参数和奖励引用，避免周期中热更导致任务板变化。
- 负责 Offer 的生成、预留、接取链接、过期和展示投影；真正的任务运行、目标进度、完成、放弃和领奖只由 14 任务系统负责。
- 使用跨槽前向恢复 Saga，把槽 5 Offer 与槽 2 QuestRun 可靠连接；重复点击、断线和保存结果未知不能创建两个 QuestRun。
- 给关卡、世界采集、商店等系统提供周期身份，但不集中保存它们的次数、节点状态或奖励收据。
- 周期内容只提供轻量长期循环，不形成主线、普通野怪或基础副本的行动力门槛。

### 1.2 非目标

- 不实现任务目标、目标事件消费、任务完成判断、交付消耗或任务奖励；这些属于 14 与 10。
- 不拥有采集节点刷新或采集奖励；12 世界系统以 `TrustedPeriodPort` 为输入保存节点状态。
- 不拥有副本周期次数、周期额外奖励或结算；07 关卡系统以周期身份校验并保存自己的计数。
- 不拥有商店限购数量；16 制作与商店系统保存自己的周期库存。
- 不实现体力、行动点、付费刷新、离线挂机收益、玩家发布悬赏、多人协作委托或实时世界事件。
- 不从客户端本地时间、UI 倒计时或 Y3 表现触发器推导权威周期。
- 不允许 `QueryBoard` 隐式生成并保存任务板；查询和写入必须分离。

## 2. 依赖、所有权与跨系统接口

### 2.1 依赖关系

| 系统 | 本系统读取/调用 | 本系统输出 |
|---|---|---|
| 01/02/15 角色、伙伴、门派 | 等级、解锁、门派身份等只读资格事实 | Offer 锁定原因；不修改养成 |
| 10 奖励与经济 | 只读取 reward 引用是否合法 | 不发奖励、不保存余额 |
| 12 世界 | 任务板交互上下文 | 周期身份；不保存节点采集状态 |
| 14 任务 | QuestDefinition 可接条件、创建 QuestRun、查询 run 终态 | `offer_id`、冻结版本和接取事务 |
| 16 商店 | 无反向写入 | 周期身份与 LIVE/CACHED 状态 |
| 18 存档 | SaveCoordinator、槽 5 修订、恢复队列 | BoardSnapshot、Offer、接取 Saga 收据 |
| 22 Y3 服务 | `ClockService.now()` 的 UTC 秒值和错误 | 不向 ClockService 回写周期 |
| 23 配置生成 | Cycle/Board/Candidate Schema、可达性报告 | 冻结配置版本和断链错误 |

### 2.2 唯一权威边界

| 数据/行为 | 唯一权威系统 | 本系统处理方式 |
|---|---|---|
| 服务器当前时间 | 22 `ClockService` | 读取一次，校验后计算周期 |
| 周期定义与周期 ID | 17 | 通过 `TrustedPeriodPort` 输出 |
| 任务板候选与接取配额 | 17 | 槽 5 权威保存 |

| 周期采集节点 | 12 | 只提供 cycle_id |
| 周期关卡次数/奖励 | 07 | 只提供 cycle_id |
| 周期商店库存 | 16 | 只提供 cycle_id |

| 端口 | 契约 |
|---|---|

## 4. 领域模型

### 4.1 `CycleDefinition`

| 字段 | 类型/范围 | 说明 |
|---|---|---|
| `cycle_def_id` | `cycle_*` | 稳定 ID，发布后不复用 |
| `definition_version` | 正整数 | 计算规则版本 |
| `kind` | `SERVER_DAY/SERVER_WEEK/EVENT/SEASON` | 周期种类 |
| `timezone_offset_seconds` | `-43200..50400` | 固定偏移，不读取设备地区 |
| `reset_offset_seconds` | `0..86399` | 日内重置点 |
| `week_start` | `1..7` 或空 | SERVER_WEEK 必填 |
| `event_start_at/event_end_at` | UTC 秒或空 | EVENT/SEASON 必填，左闭右开 |
| `parent_cycle_def_id` | 可空 | 如赛季内日周期；必须无环 |
| `grace_seconds` | 非负整数 | 只用于展示/已声明结算宽限，不改变周期 ID |
| `deprecated` | bool | 旧状态可读，新内容不可引用 |

日周期序号：

```text
normalized = server_time + timezone_offset_seconds - reset_offset_seconds
cycle_number = floor(normalized / 86400)
cycle_id = cycle_def_id + ":" + decimal(cycle_number)
```

周、活动和赛季必须先转换为整数序号，再生成 ID；业务代码不得通过字符串大小比较周期。

### 4.2 `Period`

| 字段 | 说明 |
|---|---|
| `cycle_def_id/definition_version` | 使用的定义 |
| `cycle_id/cycle_number` | 稳定身份和整数序号 |
| `starts_at/ends_at` | UTC 左闭右开边界 |
| `observed_server_time` | 本次可信时间 |
| `trust_state` | `LIVE/CACHED/UNAVAILABLE` |
| `observation_revision` | 槽 5 周期观察修订 |

`CACHED` 只能表示“最后一次已确认周期”，不能根据设备流逝时间推到未来。

### 4.3 `BoardDefinition`

| 字段 | 类型/约束 | 说明 |
|---|---|---|
| `board_id` | `board_*` | 稳定任务板 ID |
| `definition_version` | 正整数 | 进入生成种子和快照 |
| `category` | `BOUNTY/FACTION_COMMISSION` | 显示与资格类别 |
| `cycle_def_id` | 有效 ID | 刷新周期 |
| `generated_slots` | `1..20` | 每周期固定候选数 |
| `max_accepts_per_cycle` | `1..generated_slots` | 本周期可接数量，不是体力 |
| `max_active_runs` | `1..20` | 来自该板的并行 run 上限 |
| `candidate_pool_id` | `board_pool_*` | 候选集合 |
| `selection_namespace` | 稳定 ASCII 字符串 | PRNG 流隔离 |
| `duplicate_policy` | `NO_SAME_QUEST/ALLOW_PARAMETER_VARIANT` | V1 默认 NO_SAME_QUEST |
| `visibility_condition_id` | 可空 | 面板显隐 |
| `acceptance_condition_id` | 可空 | 接取时必须复核的硬条件 |
| `abandon_releases_quota` | bool | V1 固定 false，防刷候选 |
| `empty_slot_policy` | `SHOW_EMPTY/HIDE_EMPTY` | 候选不足表现 |

### 4.4 `BoardCandidateDefinition`

| 字段 | 说明 |
|---|---|
| `candidate_id` | `candidate_*`，任务板内稳定 |
| `board_id` | 所属任务板 |
| `quest_id/quest_definition_version` | 14 中允许 BOARD 接取的任务及兼容版本 |
| `parameter_set_id` | 可空；V1 只允许生成器校验过的静态参数集 |
| `weight` | 正整数，最大值由 23 冻结 |
| `eligibility_condition_id` | 生成时资格条件 |
| `hard_accept_condition_id` | 接取时再次验证的条件，可比展示资格更严格 |
| `reward_snapshot_ref` | 14/10 可解析的奖励引用；本系统不发奖 |
| `deadline_policy` | `CYCLE_END/FIXED_PERIOD_COUNT` |
| `deadline_period_count` | FIXED 时正整数 |
| `tags` | 门派、区域、难度等稳定标签 |
| `deprecated` | 已生成快照可读，新板过滤 |

### 4.5 `BoardSnapshot`

| 字段 | 说明 |
|---|---|
| `board_snapshot_id` | 由 player profile、board、cycle 唯一派生 |
| `board_id/cycle_id` | 来源 |
| `board_definition_version/content_version` | 冻结版本 |
| `eligibility_snapshot_hash` | 参与筛选的规范化事实哈希 |
| `selection_seed_hash` | 只保存不可逆诊断哈希，不暴露档案种子 |
| `offer_ids` | 按展示槽位排序 |
| `generated_at` | 可信服务器时间 |
| `generation_receipt_id` | 幂等提交收据 |
| `revision` | 槽 5 状态修订 |

已保存快照是本周期权威。资格变化不会重抽本周期候选，只会让某 Offer 在接取时显示新的锁定原因。

### 4.6 `BoardOffer`

| 字段 | 说明 |
|---|---|
| `offer_id` | board snapshot + slot 的确定性 ID |
| `candidate_id/quest_id` | 冻结引用 |
| `quest_definition_version/parameter_set_id` | 创建 QuestRun 的精确输入 |
| `reward_snapshot_ref` | 交给 14 保存到 run；不在 17 结算 |
| `status` | `AVAILABLE/RESERVED/ACCEPTED/SETTLED/ABANDONED/EXPIRED/RECOVERY_REQUIRED` |
| `deadline_cycle_id` | 最后合法周期边界 |
| `reservation_transaction_id` | RESERVED/恢复时必填 |
| `quest_run_id` | ACCEPTED 后必填 |
| `quest_status_projection` | 只读投影，可由 14 重建 |
| `accepted_at` | 可信时间 |
| `revision` | 乐观并发修订 |

`quest_status_projection` 不是 QuestRun 权威；其丢失或过期不影响任务完成和领奖。

### 4.7 `BoardAcceptanceTransaction`

字段：`transaction_id`、`command_id`、`offer_id`、`expected_offer_revision`、`input_hash`、`state`（PREPARED/QUEST_CREATED/OFFER_CONFIRMED/COMMITTED/RECOVERY_REQUIRED/FAILED）、`quest_child_receipt_id?`、`quest_run_id?`、`last_error?`、`attempt_count`、`created_at/updated_at`。同一 `command_id` 输入哈希不同必须返回 `IDEMPOTENCY_KEY_REUSED`。

## 5. 配置表与生成校验

### 5.1 配置表

- `cycle_definitions`
- `board_definitions`
- `board_candidate_pools`
- `board_candidates`
- `board_parameter_sets`
- `board_condition_dependencies`
- `board_migration_maps`

生成后的 Lua 表必须只读，按稳定 ID 建索引，并输出 `content_version` 和每表哈希。

### 5.2 资格事实白名单

生成时只允许读取：章节、玩家等级区间、已解锁区域、门派身份/职阶、永久功能开关和已完成任务集合。背包实时数量、货币余额、设备时间、随机 UI 状态不得参与抽选，以免同周期列表漂移。

接取时硬条件可以读取当前等级、门派身份、任务互斥、活动 run 上限和内容开关，但不能改变已经冻结的候选顺序。

### 5.3 静态校验

- ID 唯一，所有 cycle、quest、condition、reward 与 parameter 引用存在。
- BOARD 类型 QuestDefinition 的接取策略、重复策略和版本兼容声明有效。
- 每个任务板在生成器列举的最低资格组合下满足 `empty_slot_policy`；候选不足必须形成显式报告。
- `NO_SAME_QUEST` 时不得通过多个 candidate 绕过同 quest 去重。
- 权重和权重总和不得溢出确定性 PRNG 的整数范围。
- 周期父子图、条件依赖图和迁移图必须无环。
- 任务板不得引用付费刷新成本或影响主线进入的资源字段。
- 当前发布仍可能存在的旧 BoardSnapshot 所需 QuestDefinition 版本必须可加载或有显式迁移。

## 6. 运行时状态与不变量

### 6.1 会话状态

- `ClockObservationState`：`UNAVAILABLE/CACHED/LIVE`、最近观察时间、异常原因。
- `PeriodCache`：按 cycle_def_id 缓存纯计算结果，可随时重建。
- `BoardSession`：已加载 BoardSnapshot、Offer 索引和投影修订。
- `AcceptanceRecoveryQueue`：未完成接取事务 ID；不保存第二份 QuestRun。
- `BoardViewProjection`：可丢弃 UI DTO。

### 6.2 强制不变量

1. 同一玩家、board_id、cycle_id 最多一个 BoardSnapshot。
2. 同一 BoardSnapshot 的 offer_id、槽位顺序和冻结输入终身不变。
3. 每个 Offer 最多关联一个 QuestRun；每个 BOARD QuestRun 必须反向引用唯一 offer_id。
4. `AVAILABLE` 才能进入 RESERVED；RESERVED 只能由同 transaction 继续或由确认“QuestRun 未创建”的恢复流程释放。
5. QuestRun 一旦创建，接取事务只能前向确认，不能删除 run 来模拟跨槽回滚。
6. 周期回退不得让 EXPIRED/ACCEPTED Offer 恢复 AVAILABLE，也不得减少已消耗配额。
7. CACHED 只允许查询已保存任务板；生成、接取和跨周期状态推进要求 LIVE。
8. 任务进度、完成和奖励均不能由 Offer 投影决定。
9. 17 不保存采集节点、关卡奖励次数或商店库存。
10. 任一存档写失败未知时，UI 不得换 command_id 重试接取。

## 7. 周期、生成与状态规则

### 7.1 观察可信时间

1. 应用层调用 `ClockService.now()`，得到 UTC 秒值和服务响应标识。
2. 拒绝非整数、超范围或早于档案 `last_observed_server_time` 的值；后者返回 `CLOCK_ROLLBACK_DETECTED`。
3. 若向前异常跃迁超过配置诊断阈值，标记告警但仍以平台时间为准；阈值不能改变周期结果。
4. 计算所有被请求的 Period，并先在槽 5 保存观察时间、周期 ID 与修订。
5. 保存成功后状态为 LIVE；网络失败且有历史观察时为 CACHED，无历史为 UNAVAILABLE。
6. CACHED 不运行本地倒计时跨界；UI 可显示“等待校时”，不得声称已刷新。

### 7.2 确定性任务板生成

`EnsureBoardGenerated` 必须是写用例：

1. 要求周期状态 LIVE，读取 `BoardDefinition` 与当前 Period。
2. 按 `board_snapshot_id` 查询；已存在则校验输入并返回原收据。
3. 读取白名单资格事实，按字段名排序编码，生成 `eligibility_snapshot_hash`。
4. 过滤 deprecated、不兼容版本、不满足资格和 QuestDefinition 不可加载的候选。
5. 候选按 `candidate_id` 升序排序，不能依赖 Lua table 遍历顺序。
6. PRNG 独立流输入固定为 `profile_seed_hash + selection_namespace + board_id + cycle_id + board_definition_version + content_version`。
7. 执行无放回加权抽选；每次抽选的整数算法和取模规则由 00 约定并纳入黄金测试。
8. 为每个槽冻结 candidate、quest 版本、parameter、reward 引用和 deadline。
9. 在槽 5 单事务写 BoardSnapshot、Offer、generation receipt；成功后发布事件。

生成过程不消耗战斗、掉落或制作 PRNG 计数器。

### 7.3 Offer 状态机

```text
AVAILABLE -> RESERVED -> ACCEPTED -> SETTLED
                       \              -> ABANDONED
                        \             -> EXPIRED
                         -> RECOVERY_REQUIRED -> ACCEPTED
AVAILABLE ------------------------------------> EXPIRED
```

- SETTLED 表示关联任务已完成/已领奖的展示终态，不承载奖励事实。
- ABANDONED/EXPIRED 从 14 的 QuestRun 终态投影；是否占用周期配额按已冻结策略处理。
- RESERVED 超过诊断超时不能自动释放；必须查询 `QuestCommand` 的子收据与 `QuestQuery.get_by_offer_id`。
- 周期边界到来时，仅尚未接取的 AVAILABLE Offer 可转 EXPIRED；已接任务是否过期由 14 的 repeat policy 判断。

### 7.4 配额规则

- `max_accepts_per_cycle` 统计本周期已成功创建 QuestRun 的唯一 offer 数，不是可购买资源。
- `max_active_runs` 通过 14 实时查询 ACTIVE/READY/COMPLETING run 数；投影过期时接取失败为 `QUEST_STATUS_UNAVAILABLE`，不能猜测。
- V1 放弃不返还周期接取配额，避免反复接取筛选最优任务。
- 配额只限制对应任务板，不限制主线、支线、世界探索、普通战斗或副本进入。

### 7.5 热更与迁移

- 本周期已保存快照继续使用其冻结版本；新 BoardDefinition 只影响下个尚未生成的周期。
- 紧急下线候选时可设置内容 kill switch：AVAILABLE Offer 显示不可接，但不能静默替换成另一个候选。
- 已 ACCEPTED 的 Offer 由 QuestDefinition 兼容层或迁移表处理，不能仅删除。
- 周期定义边界变更必须新建 definition_version，并提供旧 cycle_id 到新展示周期的迁移规则；不得原地改变已观察周期身份。

## 8. 应用用例

| 用例 | 输入 | 前置 | 成功输出 | 主要错误 | 幂等键 |
|---|---|---|---|---|---|
| `ObserveTrustedTime` | correlation_id、请求 cycle IDs | ClockService 可调用 | LIVE Period 列表和观察修订 | CLOCK_UNAVAILABLE、CLOCK_INVALID、CLOCK_ROLLBACK_DETECTED | service response ID/correlation_id |
| `GetPeriod` | cycle_def_id、requirement | 定义存在 | Period DTO | PERIOD_UNAVAILABLE、PERIOD_LIVE_REQUIRED | 只读 |
| `EnsureBoardGenerated` | command_id、board_id、expected_cycle_id | LIVE、面板可见 | 固定 BoardSnapshot | BOARD_LOCKED、CYCLE_CHANGED、CANDIDATE_POOL_INVALID | command_id/board+cycle |
| `QueryBoard` | board_id | 已生成 | BoardView DTO | BOARD_NOT_GENERATED、BOARD_DEFINITION_MISSING | 只读 |
| `AcceptBoardOffer` | command_id、offer_id、expected_revision、expected_cycle | LIVE、AVAILABLE、配额和硬条件合法 | quest_run_id、事务收据 | OFFER_STALE、OFFER_LOCKED、ACCEPT_LIMIT_REACHED、TRANSACTION_RECOVERY_REQUIRED | command_id |
| `ReconcileOfferProjection` | command_id、offer_id 或 quest event | Offer 已关联 run | 更新投影/终态 | QUEST_RUN_NOT_FOUND、REVISION_CONFLICT | event_id 或 command_id |
| `RecoverBoardAcceptance` | transaction_id | PREPARED/RECOVERY_REQUIRED | COMMITTED 或明确 FAILED | CHILD_RECEIPT_UNAVAILABLE、SAVE_CONFLICT | transaction_id |

### 8.1 接取 Saga

接取遵循 ADR-0002，固定步骤如下：

1. 重新取得 LIVE 周期，校验 expected cycle、Offer revision、配额、任务互斥和硬资格。
2. 槽 5 写 `BoardAcceptanceTransaction=PREPARED`，同时把 Offer 置 RESERVED；记录规范化输入哈希。
3. 调用 14 `QuestCommand.accept_from_offer`，传 transaction_id、offer_id、冻结 QuestDefinition 版本/参数/奖励引用；14 在槽 2 写唯一 QuestRun 与 child receipt。
4. 获得 child receipt 后，槽 5 写 quest_run_id、Offer=ACCEPTED、transaction=COMMITTED。
5. 若第 3 或第 4 步结果未知，置 RECOVERY_REQUIRED；恢复器先按 transaction_id/offer_id 查询 14。若 run 已存在，只能前向完成第 4 步。
6. 只有 14 明确证明没有创建 run 且子命令明确失败，才能将 RESERVED 释放回 AVAILABLE；该失败收据永久保留输入哈希。
7. 发布 `BoardOfferAccepted` 只能发生在槽 5 COMMITTED 后；14 的 `QuestAccepted` 独立发布并可先到达，消费者按 ID 去重。

不存在“跨槽整体原子回滚”的承诺。

## 9. 领域事件

全部事件使用 00 的通用信封：`event_id,event_type,schema_version,occurred_at,source_system,source_occurrence_id,correlation_id,causation_id,payload`。

| event_type | payload 关键字段 | 消费者 |
|---|---|---|
| `TrustedPeriodObserved` | cycle_def_id、cycle_id、starts_at、ends_at、observation_revision | 07/12/14/16；20 的竞技赛季由其自身规则计算 |
| `BoardGenerated` | board_snapshot_id、board_id、cycle_id、offer_ids、content_version | UI/诊断 |
| `BoardOfferReserved` | offer_id、transaction_id、offer_revision | 恢复器/诊断 |
| `BoardOfferAccepted` | offer_id、quest_run_id、transaction_id | UI/引导 |
| `BoardOfferProjectionChanged` | offer_id、quest_run_id、projected_status、quest_revision | UI |
| `BoardOfferExpired` | offer_id、cycle_id、reason | UI/诊断 |
| `BoardAcceptanceRecoveryRequired` | transaction_id、offer_id、failed_step、error_code | 恢复页/遥测 |

本系统只消费 14 的 `QuestRunStatusChanged` 更新投影；奖励领取状态需要展示时通过 QuestQuery 组合读取，绝不据此再次发奖或改变任务目标。

## 10. 存档 DTO 与槽位

权威状态位于槽 5 的 `refresh_section`，由 SaveCoordinator 写入：

| DTO 字段 | 说明 |
|---|---|
| `schema_version/content_version` | DTO 与内容版本 |
| `last_observed_server_time` | 最近成功提交的可信 UTC 秒值 |
| `cycle_observations` | cycle_def_id、definition_version、cycle_id、边界、revision 的扁平表 |
| `board_snapshots` | BoardSnapshot 基础字段；按保留策略裁剪终态历史 |
| `board_offers` | Offer 冻结输入、状态、run 链接和 revision |
| `board_generation_receipts` | board+cycle 与 command 收据 |
| `acceptance_transactions` | Saga 状态和子收据；未终结记录不得裁剪 |
| `projection_cursors` | 最近消费的 Quest 事件游标；可重建 |
| `section_revision/checkpoint_id` | 乐观并发与 Manifest 检查点 |

槽 5 不保存 `objective_progress`、任务领奖收据、`refreshable_nodes`、副本周期计数、商店库存或奖励余额。对应权威位置分别是槽 2/4 及其所有者系统。

### 10.1 裁剪与恢复

- 当前周期、含非终态 Offer 的快照、所有未完成 Saga 必须保留。
- 终态 Offer 历史只为 UI 保留配置周期数；幂等收据按 18 的安全窗口与高水位裁剪。
- 读取到 ACCEPTED Offer 但缺少 quest_run_id 时自动进入恢复队列。
- 读取到 QuestRun 引用 offer_id、而槽 5 仍 RESERVED 时，以 QuestRun 和 child receipt 为证据前向确认。
- DTO 未知字段按 18 迁移策略处理，不能清空整个 refresh_section。

## 11. Y3 适配与 UI 状态

### 11.1 Y3 适配

- Y3 时钟适配器只返回平台 UTC 秒值、响应标识和错误；周期计算留在纯 Lua。
- 地图任务板交互只提交 `board_id` 与当前交互凭据，不携带候选、奖励或周期权威值。
- 服务器时间请求可合并，但每个写用例必须记录它实际验证的 observation revision。
- Y3 定时器只刷新倒计时显示，不能触发周期切换或生成任务板。

### 11.2 UI 状态

任务板页面至少覆盖：`LOADING_TIME`、`TIME_UNAVAILABLE`、`NOT_GENERATED`、`GENERATING`、`READY`、`ACCEPTING`、`RECOVERY_REQUIRED`、`READ_ONLY`、`ERROR`。

- NOT_GENERATED 时由明确用户进入/系统流程调用 Ensure，不由 Query 暗写。
- CACHED 时可查看已生成候选与关联任务状态，接取按钮禁用并显示“正在校准服务器时间”。
- Offer 卡展示类别、目标摘要、奖励预览、截止周期、接取锁定原因和任务状态；目标与奖励数据来自 14 的版本化 View DTO。
- 接取超时显示“正在确认接取”，保留同 command_id；不得把按钮恢复为可用并生成新键。
- 周期边界到来时先校时、再重新查询；本地倒计时归零不能自行清空列表。
- 空槽是配置允许的明确状态，不能用上一周期候选填充。

## 12. 边界、错误与降级

| 场景 | 处理 |
|---|---|
| 首次进入且 ClockService 不可用 | UNAVAILABLE；不生成、不接取，主线继续 |
| 有缓存周期但无法校时 | 只读查看；不跨周期、不接取 |
| 平台时间回退 | 记录 P0 诊断，维持最后周期，拒绝写用例 |
| 面板打开时发生日切 | 旧 expected_cycle 接取返回 CYCLE_CHANGED，重新生成新周期板 |
| 本周期配置热更 | 继续读已冻结 Snapshot；kill switch 可禁用但不替换 |
| 候选 QuestDefinition 缺失 | Offer=锁定，生成诊断；不得换候选或创建空 run |
| 创建 QuestRun 成功、槽 5 确认失败 | RECOVERY_REQUIRED，查询子收据后前向确认 |
| 槽 5 RESERVED、14 明确无 run 且明确失败 | 写失败收据后释放；不消耗配额 |
| 重复 `QuestRunStatusChanged` | event_id/source_occurrence_id 去重，仅更新一次投影 |
| 伪造 offer_id/revision/cycle | 从槽 5 与 LIVE Period 重读，返回明确错误 |
| 存档只读或 Manifest 不一致 | 停止写入，进入 18 恢复流程 |

错误码至少包括：`CLOCK_UNAVAILABLE`、`CLOCK_INVALID`、`CLOCK_ROLLBACK_DETECTED`、`PERIOD_LIVE_REQUIRED`、`CYCLE_CHANGED`、`BOARD_NOT_GENERATED`、`BOARD_LOCKED`、`CANDIDATE_POOL_INVALID`、`OFFER_NOT_FOUND`、`OFFER_STALE`、`OFFER_NOT_AVAILABLE`、`OFFER_LOCKED`、`ACCEPT_LIMIT_REACHED`、`QUEST_STATUS_UNAVAILABLE`、`IDEMPOTENCY_KEY_REUSED`、`TRANSACTION_RECOVERY_REQUIRED`、`SAVE_READ_ONLY`。

## 13. 测试与诊断

### 13.1 纯 Lua 单元测试

- 日切前后一秒、周起点、闰日、负时间偏移、活动左闭右开边界。
- 相同输入生成同 BoardSnapshot 哈希；Lua table 插入顺序改变不影响结果。
- 权重 1、最大权重、候选数等于/少于槽位、无放回去重和整数溢出。
- 资格快照字段排序、无关事实变化不影响结果、硬资格变化只锁定不重抽。
- Offer 全部合法状态转换和非法反向转换。
- 配额：重复命令、放弃不返还、活动 run 上限、跨周期隔离。

### 13.2 故障注入与集成测试

| 注入点 | 必须结果 |
|---|---|
| PREPARED 后进程退出 | 重进恢复，最多一个 QuestRun |
| QuestRun 已写、响应丢失 | 查询 child receipt，Offer 前向变 ACCEPTED |
| Offer 确认写超时 | UI 保持确认中，同 transaction 恢复 |
| 重放相同 command_id | 返回原 quest_run_id 和结果 |
| 同 command_id 换 offer | IDEMPOTENCY_KEY_REUSED |
| 周期切换与接取并发 | 仅一个明确结果，无旧周期越界接取 |
| Quest 终态事件重复/乱序 | 投影最终与 QuestQuery 一致，不影响奖励 |
| 槽 5 Manifest 孤儿写 | 18 检出并恢复，不将半状态当已提交 |

### 13.3 诊断字段

日志必须带：`profile_id_hash,board_id,cycle_id,board_snapshot_id,offer_id,quest_run_id,command_id,transaction_id,checkpoint_id,content_version,observation_revision,error_code`。不得记录真实付费信息或可反推玩家档案种子的原值。

## 14. 验收标准

- 修改电脑本地时间、暂停客户端计时器或改变系统时区均不能产生新周期。
- 同一档案、任务板、周期和冻结配置重复生成，offer 顺序与快照哈希完全一致。
- 已展示的本周期候选不因等级、背包或热更变化被静默重抽。
- 任意保存失败点和重复点击下，每个 Offer 最多创建一个 QuestRun。
- 任务目标、完成、放弃和奖励状态由 14/10 权威决定；17 删除投影后能从 QuestQuery 重建。
- 12、07、16 能消费同一 Period 契约，但各自的节点/次数/库存状态不出现在槽 5 的 17 section。
- ClockService 不可用只冻结周期写操作，不阻断主线、支线、世界移动或基础副本。
- 所有 PREPARED/RECOVERY_REQUIRED 事务重进后可自动前向收敛或给出可诊断的明确失败。
