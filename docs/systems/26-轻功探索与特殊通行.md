## 1. 目标与非目标

### 1.1 目标

- 把当前装备轻功转换为可验证的地图能力：基础跳跃、长距离跳跃、高差跳跃与水面通行。
- 玩家在探索模式主动使用轻功时进入选点态，地面显示当前可跳跃、可踏水行走或可上岸的离散格范围。
- 选点使用连续 `TraversalGrid/TraversalCell` 图，不退化成几个固定触发点，也不复用战斗 3×3 `Formation` 阵位。
- 纯 Lua 依据 `LightnessTraversalProfile + 地图空间事实 + 世界条件` 确定性计算候选；相同输入得到相同排序、路径和哈希。
- 预览永远不等于授权。确认时按最新来源向量重校验，Y3 点击、模型坐标和动画结束均不能自行判定成功。
- 跳跃、入水、水上移动、离水、取消与异常恢复具有明确状态机、幂等边界、安全落点和输入锁释放路径。
- 第一章包含一处必经基础跳、两处可选高级跳和一处可选踏水区；必经能力保底获得，高级轻功与踏水不成为主线唯一门槛。

参考作品把轻功距离、跨地形和水面移动用于地图探索；本系统只借鉴这一通用交互方向，全部能力名、地图、参数、任务和视觉保持原创。[雁行功](https://wiki.biligame.com/yanyu/%E6%AD%A6%E5%AD%A6/%E9%9B%81%E8%A1%8C%E5%8A%9F)、[水上漂](https://wiki.biligame.com/yanyu/%E6%AD%A6%E5%AD%A6/%E6%B0%B4%E4%B8%8A%E6%BC%82)

### 1.2 非目标

- V1 不做任意世界坐标起落的自由物理跳、攀爬、游泳、飞行、空中改向或坠落伤害。
- V1 不做轻功体力、耐力、每日次数、随机失败、真气/货币消耗或付费通行次数。
- `water_range_cells` 是一次踏水会话的路线预算，不是可购买、可恢复或持久化的角色资源。
- V1 不在水面开始普通 Encounter，不允许水面换轻功、换主角、传送、交互或进入构筑页面。
- V1 世界通行只检定主角；伙伴在成功提交后做跟随表现，不逐个检定，也不产生额外任务事实。
- V1 不做二段/三段空中选点；`max_chain_segments` 兼容位固定为 1，不写玩家存档。
- 本系统不拥有武学学习/装备、地图几何、世界位置、任务进度、UI 样式或 Y3 资源句柄。

## 2. 所有权、依赖与稳定接口

### 2.1 唯一所有权

| 状态/规则 | 唯一所有者 | 26 的权限 |
|---|---|---|
| 已学轻功、装备、等级、能力参数 | 04 | 只读 `LightnessTraversalProfile`；不保存第二份能力 |
| Grid/Cell/Link、表面、高度、阻挡、marker、当前位置与 last safe | 12 | 只读空间快照；成功复验后经端口请求位置提交 |
| 可达规则、选点会话、候选哈希、TraversalSession、踏水剩余路线预算 | 26 | 唯一运行时所有者；不生成或持久化世界落地收据 |
| 覆盖层、悬停、键鼠焦点、动画、残影、水花 | 19 | 只读 ViewModel/事件；不反写结果 |
| QuestRun 与教程进度 | 14/24 | 只发布已提交事实；不直接推进 |
| 槽 2 `world_position/last_landing_receipt_id` 与 `landing_receipt_id` 结果身份 | 12 | 由逐段 command 与规范输入确定性生成并幂等提交世界位置；通过 18 写入 |
| 槽 5 保存恢复事务、迁移、outbox 与检查点 | 18 | 引用业务收据做跨槽恢复；只有 SaveCoordinator 直接调用 SaveStore |

### 2.2 输入端口

| 端口 | 提供方 | 用途 |
|---|---|---|
| `LightnessTraversalProfilePort` | 04 | 当前主角的能力、两项来源修订、Profile 哈希与规则版本 |
| `TraversalSpacePort` | 12 | 定位起点格，读取同一 `spatial_revision` 的 Cell/Link/Region |
| `TraversalWorldFactPort` | 12 | 读取 `world_revision`、条件白名单、当前 marker 和 last safe |
| `TraversalWorldControlPort` | 12 | 排他锁定普通移动，防止并发改位置 |
| `WorldPositionCommitPort` | 12 | 使用逐段 command 与规范输入复验并幂等提交安全落点，返回 12 生成的 `landing_receipt_id` |
| `SaveCoordinatorPort` | 18 | 登记引用该收据的恢复事务/关键检查点，恢复结果未知事务 |
| `TraversalPresentationPort` | Y3 适配层 | 执行已授权路径，以匹配 token 回报完成或失败观测 |

### 2.3 输出接口

- `OpenTraversalTargeting`：创建只读候选快照和选点 token。
- `CancelTraversalTargeting`：关闭尚未提交的选点态。
- `RequestTraversal`：确认目标格；跳跃、入水、水上移动和离水共用。
- `ReportTraversalPresentationFinished`、`ReportTraversalPresentationFailed`：接受 Y3 非权威执行观测并触发领域复验/恢复。
- `RecoverTraversal`：丢弃临时会话，由 12 解析并回到安全 marker。
- `TraversalGuard`：供 04 在更换或升级当前轻功前确认主角位于稳定地面。

## 4. Canonical 领域模型

### 4.1 `LightnessTraversalProfile`

由 04 派生，26 不持久化。字段以 04 为准：`character_id`、来源轻功/等级、`source_loadout_revision`、`source_progress_revision`、`rules_version`、按固定顺序输出的 `capability_specs`、`range_query_radius_cells`、`presentation_profile_id` 和 `profile_hash`。

`TraversalCapabilitySpec` 固定字段：

| 字段 | 规则 |
|---|---|
| `capability_id` | 仅 `JUMP_BASIC/JUMP_LONG/JUMP_HIGH/WATER_WALK` |
| `rank` | 正整数；规则档位，不等于武学重数 |
| `jump_range_cells` | 跳跃最大整数格预算；不适用为 0 |
| `water_range_cells` | 一次踏水会话总路线预算；不适用为 0 |
| `max_rise_levels/max_drop_levels` | 离散高度上升/下降上限 |
| `max_route_cost` | 仅跳跃单段的 Link 规范 cost 上限；`WATER_WALK` 必须为 0，水面只使用 `water_range_cells` |
| `movement_speed_bp` | 表现速度基点；不改变拓扑 |

能力闭包：`JUMP_LONG/JUMP_HIGH` 均要求同时存在 `JUMP_BASIC`，`WATER_WALK` 独立。未解锁能力整项缺席；不能用 UI、伙伴或已学但未装备轻功补齐。

### 4.2 `ReachabilitySourceVector`

```text
ReachabilitySourceVector = {
  spatial_revision: integer,
  world_revision: integer,
  source_loadout_revision: integer,
  source_progress_revision: integer,
  profile_hash: string,
  rules_version: integer
}
```

前两项来自 12，后四项原样来自 04。不得折叠成未定义的单一 Profile revision，也不另建权威或写存档。六项中任一变化，旧候选、选点 token 和未授权命令立即失效。

### 4.3 `TraversalGrid/TraversalCell/TraversalLink`

空间字段由 12 拥有，26 只消费：

- `TraversalGrid`：`grid_id/area_id/cell_size_cm/origin_mapping_id/layer_ids/bake_version/spatial_revision`。
- `TraversalCell`：格坐标、层、整数 world anchor、`height_level`、`surface_type`、普通可走性、阻挡、净空、`landing_safety`、安全 marker、region、揭示策略和 region revision。
- `TraversalLink`：起终格、方向、`link_type`、整数水平 cost、rise/drop、净空、条件、落点 marker、`source_type` 和 link revision。

稳定前缀只能是 `traversal_grid_`、`traversal_cell_`、`traversal_link_`。探索格与战斗 3×3 阵位不共享 ID、原点、距离公式、序号、存档字段或转换 API。

### 4.4 `TraversalRuleDefinition`

26 拥有 Link 到能力语义的规则，不把能力判断塞回地图系统：

| 字段 | 说明 |
|---|---|
| `rule_id` | `traversal_rule_*` |
| `applies_to_link_types` | 有序 Link 类型集合 |
| `required_capability_any/all` | 可选任一/必须全部能力集合 |
| `allowed_from_surfaces/allowed_to_surfaces` | 表面转换白名单 |
| `distance_budget_policy` | 仅 `JUMP_DUAL_LIMIT/WATER_SESSION_COST`；前者同时检查 `jump_range_cells` 与 `max_route_cost`，后者只累计扣除 `water_range_cells` |
| `height_policy` | rise/drop 检查与能力档选择 |
| `landing_policy` | `SAFE_GROUND/WATER_SESSION/SHORE_EXIT` |
| `condition_policy` | 只读 12 白名单世界事实；禁止本地时间/UI 条件 |

开放地面 `JUMP_DIRECT` 可由烘焙器生成；跨沟、屋顶、高差、单向落差和剧情门由手工 Link 覆盖。两者进入同一图和 `RequestTraversal`，不能另建固定跳点旁路。

### 4.5 `WaterSurfaceZone`

| 字段 | 约束 |
|---|---|
| `water_zone_id` | `water_zone_*` |
| `grid_id/region_id` | 引用 12 空间 |
| `cell_ids` | 排序后的 WATER Cell；可由 region 烘焙 |
| `entry_link_ids/exit_link_ids` | 至少各一个，端点与岸线一致 |
| `safe_shore_marker_ids` | 非空；只指向 SAFE_GROUND |
| `rule_id` | 必须最终要求 `WATER_WALK` |
| `availability_condition_id` | 可空；只读世界事实 |
| `route_role` | `MAIN_OPTIONAL/SIDE_ROUTE/HIDDEN_ROUTE/TUTORIAL`；V1 无主线唯一踏水门 |

### 4.6 `TraversalCandidate`

| 字段 | 说明 |
|---|---|
| `target_cell_id` | 当前空间修订中的目标格 |
| `target_role` | `LANDING/WATER_STEP/SHORE_EXIT/NEIGHBOR_INVALID` |
| `surface_type` | 与 12 一致的 `GROUND/WATER/HAZARD/VOID` |
| `validity/invalid_reason` | `VALID/INVALID` 与稳定原因 |
| `link_ids/path_cell_ids` | 规范路径，按前进顺序 |
| `route_cost/rise_levels/drop_levels` | 非负整数规则值 |
| `remaining_water_cells_after` | 非水路线为空 |
| `world_anchor_cm` | 只给表现定位，不供 UI 自行判定 |

排序固定为：`validity → target_role → route_cost → target_cell_id → canonical_path_key`。候选哈希包含 scope、起点、完整来源向量和可见候选规则字段；水面嵌套选点还必须包含 parent traversal_session_id、预期父 segment_sequence、water_zone_id 与 `water_remaining_before`。它不包含颜色、悬停、动画或本地时间。

### 4.7 `TraversalTargetingSession`

字段：`targeting_session_id`、player/actor、`scope`、可选 `parent_traversal_session_id/expected_parent_segment_sequence/water_remaining_before`、`origin_cell_id`、完整来源向量、候选列表、`candidate_set_hash`、当前选中格、入口原因、状态和创建序号。`scope` 仅 `GROUND_OR_ENTRY/WATER_SEGMENT`；后者的三个 parent 快照字段必填，并绑定当前处于 `ON_WATER_IDLE` 的父 TraversalSession。它只存在内存，不写存档；选中格和键盘焦点属于 presentation，可丢失重建。

### 4.8 `TraversalSession`

| 字段 | 说明 |
|---|---|
| `traversal_session_id`、`entry_command_id` | 整段跳跃或踏水总会话身份；入水后保持不变 |
| `active_segment_command_id`、`segment_sequence` | 每次入水、水格移动或离水的独立命令身份与递增段序号 |
| `actor_id` | V1 必须是当前世界主角 |
| `mode/state` | `JUMP/WATER_ENTER/WATER_STEP/WATER_EXIT/RECOVERY` 与第 7 节状态 |
| `origin_cell_id/current_cell_id/target_cell_id` | 规范 Cell |
| `path_cell_ids/link_ids` | 当前已授权段的路径；完成该段后清空，不替代水面总预算 |
| `source_vector/candidate_set_hash` | 授权快照 |
| `movement_token/active_targeting_session_id?` | 当前执行 token；水面空闲时可绑定唯一嵌套选点会话 |
| `last_safe_marker_id` | 只读复制；恢复目标仍由 12 复验 |
| `water_zone_id` | 仅踏水会话存在 |
| `water_budget_total/remaining` | 非负整数；上岸后销毁 |
| `landing_receipt_id` | 仅在 12 安全地面提交成功/结果已存在后，由其结果回填；26 不预生成，18 只引用 |

落地收据的 canonical tuple 固定为 `{player_save_scope, traversal_session_id, active_segment_command_id, segment_sequence, target_cell_id, rules_version}`，字段顺序、UTF-8/整数规范化和哈希算法跟随 ADR-0003 的收据版本。26 提供 tuple，12 是唯一生成者/结果 owner，18 只保存引用；任何层都不能增删字段生成另一种 ID。

同一玩家最多一个 TraversalSession 和一个 TargetingSession。通常二者互斥；唯一例外是活动踏水总会话处于 `ON_WATER_IDLE` 时，可拥有一个 `scope=WATER_SEGMENT` 且 parent ID 完全匹配的嵌套 TargetingSession。执行任一水面段时先关闭该选点会话；04 的 TraversalGuard 与两者全部互斥。

## 5. 配置 Schema 与生成约束

26 只拥有 `traversal_rules` 与 `water_surface_zones`。04 拥有 Profile/等级行，12 拥有 Grid/Cell/Link，19 拥有 `TraversalPresentationProfile/LightnessTargetOverlayDefinition`；23 统一生成但不取得领域所有权。

生成时必须检查：

- 能力只来自固定枚举并满足闭包；范围、route cost 和高差为非负整数。跳跃能力使用 `JUMP_DUAL_LIMIT`；`WATER_WALK` 使用 `WATER_SESSION_COST`、`max_route_cost=0`，两种预算不能交叉引用。
- Grid 坐标唯一；每个可见 Cell 有稳定 ID、合法层、表面、净空与揭示策略。
- BAKED 跳跃边和 MANUAL_OVERRIDE 不冲突；BLOCK 能明确指出被屏蔽边。
- 每个安全地面候选拥有合法 safe marker；WATER/HAZARD/VOID 永远不能成为 last safe。
- WaterSurfaceZone 连通、一入一出且有安全岸点；每个可停留水格按 `water_range_cells` 对入口、内部和出口 cost 的同一累计口径存在出口。
- 静态索引不得包含未揭示 Cell、隐藏出口或会泄密的不可达原因。
- 主线必经 Link 的保证能力来源位于此前，且不依赖随机、付费或可错过支线。

## 6. 可达集算法

### 6.1 打开选点

1. 校验 GameMode 为 EXPLORE、无对话/战斗/传送/恢复锁，actor 为当前主角。若传入 `parent_traversal_session_id`，它必须是当前唯一踏水会话且处于 `ON_WATER_IDLE`；此时创建 `scope=WATER_SEGMENT` 的嵌套选点，否则创建 `GROUND_OR_ENTRY` 选点。
2. 从 04 读取 Profile，把两项来源修订、Profile 哈希和规则版本原样放入来源向量。
3. 顶层选点从 12 已提交世界位置定位 `origin_cell_id`，无法定位返回 `TRAVERSAL_ORIGIN_UNKNOWN`。嵌套水面选点不得调用已提交位置定位：它直接取父 TraversalSession.current_cell_id，并要求 12 在父会话已持有的 WorldControlLease 下复验该 Cell 仍属于同一 WaterSurfaceZone、为 WATER 表面且处于当前空间修订。
4. 顶层取得 WorldControl 读租约；嵌套水面选点复用父会话的排他 lease，不另取会把起点校回岸边的租约。两者都在同一读视图读取 `spatial_revision/world_revision`。
5. 按 `range_query_radius_cells` 查询 Cell/Link/Region/条件；响应来自同一空间修订。
6. 过滤 reveal policy；隐藏 Cell 不进入有效格、无效格、轮廓或原因列表。
7. 运行跳跃与踏水候选算法，规范排序并计算 `candidate_set_hash`。
8. 返回 TargetingSession/ViewModel；UI 此时才可画格。

打开是只读操作，不移动、不发任务事实、不扣资源、不写存档。

### 6.2 跳跃候选

- 起点必须是已提交地面格，Profile 至少含 `JUMP_BASIC`。
- 只遍历 BAKED/手工 Link；禁止 UI 用世界直线距离临时补边。
- 路线同时满足能力、`jump_range_cells`、`max_route_cost`、rise/drop、净空、方向、世界条件与 SAFE_GROUND 目标。
- 多个能力均可满足时，按 `route_cost → 能力固定顺序 → path key` 选择，不能依赖 table 遍历顺序。
- 普通地面也可作为轻功落点；跨越阻挡只允许烘焙/手工明确授权的轨迹。
- V1 一次路线只有一个空中段；中途 path cell 只描述轨迹/净空，不能二次选点。

### 6.3 踏水候选

- 从合法 entry Link 入水，或从活动 Zone 的 current water Cell 继续。入水段接受后，原地面选点关闭并创建唯一踏水总会话；每个水上移动/离水段都从该总会话的 `ON_WATER_IDLE` 打开一个嵌套 `WATER_SEGMENT` 选点。
- 入水时 `water_budget_total = WATER_WALK.water_range_cells`；入口 Link、水格 Link 和出口 Link 的规范整数 cost 全部从此预算累计扣除。`WATER_WALK.max_route_cost` 固定为 0 且不得参与水面判断；水上不能重复激活或换装刷新。
- 使用整数 cost 的确定性 Dijkstra；平手为 `total_cost → hop_count → cell_id → path_key`。
- 水格合法条件：`到目标 cost + 目标到任一当前可用安全出口的最小 cost <= remaining`，不显示必然困住玩家的假绿格。
- 岸格只要出口 Link 与总 cost 合法；提交后销毁水上预算和总会话。水面段完成但未离水时回到 `ON_WATER_IDLE`，自动刷新嵌套选点/覆盖层；取消嵌套选点只回到该空闲态，不等价于离水。
- 动态条件令全部出口失效时停止猜路，进入 RECOVERING，回 12 复验后的 safe shore/last safe。

### 6.4 无效格与防剧透

可按表现预算返回范围边缘的已揭示无效格。原因优先级：`STATE_LOCKED → CAPABILITY_MISSING → OUT_OF_RANGE → HEIGHT_EXCEEDED → PATH_BLOCKED → LANDING_UNSAFE → NO_SAFE_WATER_EXIT`。隐藏内容完全不返回，不能显示“任务未完成”泄露秘密机关。

### 6.5 确认时重校验

`RequestTraversal` 不信任候选列表。地面/入水请求必须携带顶层 TargetingSession；水上移动/离水请求必须携带 `scope=WATER_SEGMENT` 的 TargetingSession，且其 parent 与当前 `ON_WATER_IDLE` 总会话匹配。它重新读取 actor、起点、Profile、六项来源向量、目标 Cell/Link、动态阻挡、条件、父会话剩余预算和安全出口，并重算规范路径。以下任一情况拒绝旧 token 并建议刷新：

- 来源向量任一项变化；
- origin/current Cell 变化；
- 嵌套选点的 parent ID、预期 segment_sequence、water zone 或 `water_remaining_before` 与父会话不一致；
- candidate hash 与同源重算不一致；
- 目标揭示、阻挡、净空、落点或水面出口变化；
- 同一 command_id 携带不同输入哈希。

成功时获取或复用踏水总会话持有的世界移动排他租约，关闭当前 TargetingSession，为该段登记新的 `active_segment_command_id/segment_sequence/movement_token`，再调用 Y3 适配器。地面跳跃创建短期 TraversalSession；入水创建可跨多个段存活的踏水 TraversalSession。高亮本身从不授权位移。

## 7. 状态机与不变量

### 7.1 选点状态机

```text
IDLE -> QUERYING -> TARGETING -> SUBMITTING
              |          |          |-> ACCEPTED -> IDLE
              |          |          |-> STALE -> QUERYING
              |          |          `-> REJECTED -> TARGETING/IDLE
              |          `-> CANCELLING -> IDLE/ON_WATER_IDLE
              `-> QUERY_FAILED -> IDLE
```

相机移动可保留选点。顶层选点遇到区域卸载、开战、对话、过场、传送、主角/Profile 变化或世界恢复必须取消；嵌套水面选点遇到父会话失配或能力非法消失时，关闭选点并令父会话进入 RECOVERING，不能只返回水面空闲态。存读档不恢复 TARGETING。

### 7.2 跳跃状态机

```text
STABLE_GROUND -> VALIDATING -> AUTHORIZED -> EXECUTING
      ^                                         |
      |                                  LANDING_VERIFY
      |                                  /            \
      `---------------- COMMITTED <-----              RECOVERING
```

动画完成只触发 `LANDING_VERIFY`。26 以原逐段 command 和规范输入调用 12；12 生成/复用 `landing_receipt_id` 并幂等提交安全 marker，返回结果后，26 才进入 COMMITTED 并发布 `TraversalLanded`。

### 7.3 踏水状态机

```text
STABLE_GROUND -> WATER_ENTERING -> ON_WATER_IDLE
                                         |
                                         v
                                  WATER_TARGETING
                                   /           \
                           WATER_MOVING     WATER_EXITING
                                  |               |
                                  v               v
                           ON_WATER_IDLE    LANDING_VERIFY
                                                  |
                                                  v
                                           STABLE_GROUND

任一执行/复验失败 -> RECOVERING -> STABLE_GROUND
```

入水段验证完成后发布 `WaterWalkEntered` 并进入 `ON_WATER_IDLE`；水格间发布内部 `WaterWalkAdvanced`，扣除本段 cost 后回到 `ON_WATER_IDLE`；安全岸点提交后依次发布 `TraversalLanded` 与 `WaterWalkExited`。每段使用独立 command_id，全部归属同一 traversal_session_id；恢复到岸边不伪造成功事实。

### 7.4 硬性不变量

1. V1 actor 永远是当前世界主角。
2. 同时最多一个可改世界位置的 TraversalSession 或轻功变更 Guard；活动踏水会话可附带一个只读嵌套 TargetingSession，但它不取得第二把世界写锁。
3. 只有 12 已提交 SAFE_GROUND marker 才更新 last safe。
4. Y3 句柄、坐标、动画、候选 UI、token 和水上预算不写存档。
5. 迟到、重复、错误 session/sequence/token 观测只记录并忽略。
6. TraversalSession 的完成/恢复等终态必须释放其 WorldControl lease、19 父级通行输入锁、`RIGHT_MOUSE_UNIT_MOVE` 覆盖和 marker pool。仅取消嵌套水面选点时只释放该覆盖层/焦点租约，必须保留父踏水会话的 WorldControl 与普通移动禁用状态。
7. 普通移动、传送、对话、战斗和换轻功不能与活动 TraversalSession 并发提交位置。
8. 伙伴只在 COMMITTED 后校准；伙伴动画失败不回滚主角结果。

## 8. 应用用例契约

| 用例 | 输入 | 成功输出 | 主要错误 | 幂等/重试 |
|---|---|---|---|---|
| `OpenTraversalTargeting` | request_id、player、actor、入口原因、可选 parent traversal session | 顶层或嵌套 TargetingSession、候选、来源向量、hash | ORIGIN_UNKNOWN、NO_CAPABILITY、INPUT_LOCKED、PARENT_SESSION_INVALID | request_id 只读去重 |
| `CancelTraversalTargeting` | targeting_session_id | 顶层返回 EXPLORE；嵌套返回父会话 `ON_WATER_IDLE`；释放覆盖层锁 | TARGETING_NOT_FOUND | 重复取消成功 |
| `RequestTraversal` | 每段 command_id、targeting session、可选 parent session、origin/target、可选 link、完整来源向量、candidate hash | 新/既有 traversal session、段序号、mode、path、movement token | STALE、UNREACHABLE、BUSY、PARENT_SESSION_INVALID、IDEMPOTENCY_KEY_REUSED | 每段 command_id |
| `ReportTraversalPresentationFinished` | session/token/segment sequence/adapter result | 触发领域复验；可能提交或恢复 | TOKEN_INVALID、NOTICE_STALE | session+sequence |
| `ReportTraversalPresentationFailed` | session/token、稳定失败原因 | 校准或 RECOVERING | TOKEN_INVALID | session+sequence |
| `RecoverTraversal` | recovery_id、reason、可选 session | 12 返回的安全 marker、释放全部锁 | SAFE_MARKER_INVALID、RECOVERY_REQUIRED | recovery_id |
| `AcquireTraversalGuard` | command_id、预期 profile hash | guard token | TRAVERSAL_ACTIVE | command_id |

19 的 `OpenLightnessTargeting/MoveLightnessCursor/ConfirmLightnessTarget/CancelLightnessTargeting` 是 input action_id；Open/Confirm/Cancel 分别调用上述用例，Move 只改本地焦点。踏水总会话在每段结束后自动打开或刷新绑定自身的嵌套 TargetingSession；水面点击/WASD 先解析为该嵌套会话的候选水格/岸格，再以新的逐段 command_id 调用同一个 `RequestTraversal`，不存在权威旁路。

## 9. 事件契约

| event_type | 关键 payload | 消费方 |
|---|---|---|
| `TraversalCandidateSetInvalidated` | targeting session、旧/新来源摘要、reason | 19 刷新/关闭 |
| `TraversalLanded` | session、from/to cell、`traversed_link_ids[]`、marker、landing receipt、source vector | 14、24、19、诊断；12 已在此前完成位置提交 |
| `WaterWalkEntered` | session、zone、entry cell、remaining、sequence | 14、24、19 |
| `WaterWalkAdvanced` | session、zone、from/to water cell、remaining、sequence | 19/诊断；V1 不推进普通任务 |
| `WaterWalkExited` | session、zone、shore cell/marker、landing receipt、sequence | 14、24、19 |
| `TraversalRecoveryRequired` | session?、reason、last safe marker | 18、19、诊断 |
| `TraversalRecoveryCompleted` | recovery_id、safe marker、fallback used | 19、诊断；不是成功通行事实 |

`RequestTraversal` 的接受/拒绝只通过该命令 Result 返回，不能再发同义 Authorized/Rejected 事件驱动第二次表现。持久事实使用通用 DomainEvent 信封和唯一 event_id。任务只消费 `TraversalLanded`、`WaterWalkEntered`、`WaterWalkExited`；命令结果、动画、候选、Advanced 和 Recovery 均不能完成任务或教程。

## 10. 存档、迁移与恢复

- TargetingSession、TraversalSession、水上 current Cell、剩余预算、路径、token 和动画状态全部不持久化。
- `RequestTraversal` 接受结果与 command/session 去重表只覆盖当前进程；安全落点提交前崩溃不存在跨进程位移权益，重进回 last safe。
- 26 调用 12 时传入完整 canonical tuple `{player_save_scope, traversal_session_id, active_segment_command_id, segment_sequence, target_cell_id, rules_version}` 与位置复验输入，不传 receipt。12 作为世界位置 owner 按该 tuple 生成/复用 `landing_receipt_id`，并在槽 2 `world_position` 保存已提交 `current_marker_id/last_safe_marker_id/last_landing_receipt_id`；空中和水面不覆盖。
- 18 的槽 5 `save_recovery_transactions` section 只保存引用同一 receipt 的检查点意图/结果，由 18 拥有；它不生成 receipt、不复制位置权威。提交结果未知时用原 receipt 前向确认，不能换 command_id 再落一次。
- `TraversalLanded` 或 `WaterWalkExited` 的安全地面提交完成后请求关键检查点；打开/取消选点和水上中间步不保存。
- 重进丢弃临时态。落地收据证明目标已提交时采用该安全 marker，否则恢复 last safe；不读取残留 Y3 坐标。
- 旧档若保存跳跃次数、轻功体力、水上位置或动画阶段，迁移删除并回安全 marker，不伪造任务事件。
- Grid/Cell/Link 是只读生成物，不写玩家档；内容更新通过 marker 映射/fallback 链迁移位置。

## 11. Y3 适配与表现

### 11.1 覆盖层

- 灰盒首选池化 Point SceneUI 格标记；它可固定世界点并响应点击/悬停，但始终朝镜头、点实例默认对所有玩家可见，必须在单人实例实测。
- 密集区使用 `max_visible_cells`、视距/视锥裁剪、分批租借和统一回收；超预算降级为低成本地面特效或标记单位，选中格/路径终点不能被裁掉。
- 陆地有效、水面有效、无效、悬停、已选、路径和落点同时使用颜色与纹样/边框/图标，不能只靠颜色。
- 本地鼠标只更新悬停/路线；确认进入同步应用用例。
- 进入选点时暂停普通移动并关闭 Y3 内置 `RIGHT_MOUSE_UNIT_MOVE`；所有退出路径走同一 finally 清理。

### 11.2 位移表现

- Y3 只接收已授权 anchors、路径、movement token 与 `traversal_presentation_` Profile；不得自行换落点或把失败改成成功。
- 跳跃可用原创弧线/Bezier，踏水用原生路径或预烘焙 waypoint；每帧物理坐标不回传为领域事实。
- 动画提前结束时等待领域结果；超时、句柄失效或表现不可达时上报失败，由 26 校准/恢复。
- 领域提交后若模型偏差，淡出/瞬时校准到权威 marker 并记录误差；不能反向修改 marker。
- 主角提交后伙伴在安全点附近重排；伙伴不生成通行事件。

## 12. UI 行为

1. HUD 轻功按钮或绑定键触发 `OpenLightnessTargeting`。
2. 覆盖层显示已揭示可达格；可选显示邻近无效格及单一原因。
3. 鼠标/键盘移动焦点，显示目标、路径、所需能力、水上剩余格数和上岸结果。
4. Confirm 后进入 BUSY 并吸收重复输入；陈旧时说明原因并刷新，不沿旧绿格移动。
5. ESC/取消只在 TARGETING 生效；AUTHORIZED 后不能由 UI 强停，只能完成或恢复。
6. 水上重新选点时显示剩余预算内水格/岸格；始终提供返回安全岸点的恢复入口，但不算任务成功。
7. 低特效、色弱、高对比和 UI 缩放均不得改变候选集。

## 13. 失败、错误码与恢复

| 错误码 | 处理 |
|---|---|
| `TRAVERSAL_INPUT_LOCKED` | 显示当前模式原因，不打开覆盖层 |
| `TRAVERSAL_ACTOR_NOT_PROTAGONIST` | 拒绝，不借伙伴能力 |
| `TRAVERSAL_ORIGIN_UNKNOWN` | 尝试 12 校准，仍失败则恢复 |
| `TRAVERSAL_CAPABILITY_MISSING` | 显示所需能力，不临时授予 |
| `TRAVERSAL_SOURCE_STALE` | 废弃候选并刷新 |
| `TRAVERSAL_TARGET_HIDDEN` | 不返回目标详情，关闭旧选择 |
| `TRAVERSAL_OUT_OF_RANGE/HEIGHT_EXCEEDED` | 显示范围/高差原因，不改成普通寻路 |
| `TRAVERSAL_PATH_BLOCKED/LANDING_UNSAFE` | 刷新空间；已执行则安全恢复 |
| `TRAVERSAL_NO_SAFE_WATER_EXIT` | 禁止该水格；会话中无出口则恢复 |

## 16. 验收标准

- 使用轻功后明确显示当前可跳跃/可踏水到达的格子范围、目标、路线和确认/取消状态。
- 鼠标与键盘均可完成首章教学；探索格与战斗 3×3 阵位无串线。
- 同一 Profile、起点和空间/世界修订生成字节级相同候选排序/哈希。
- 旧绿格遇到能力、世界或阻挡变化会拒绝并刷新，不能穿模或落危险格。
- 水面不能靠反复激活刷新范围；每个合法水格有预算内出口，异常可回岸。
- Y3 动画、SceneUI、本地点击、模型坐标和帧率均不能推进位置、任务或教学。
- 空中/水面退出重进，只位于已提交安全目标或 last safe；不坏档、不重复进度、不锁输入。
- 第一章必经基础跳有不可错过的免费能力；高级跳与踏水不封死主线。
- 密集覆盖层通过目标设备 marker pool、输入锁、帧率和回收门禁。
