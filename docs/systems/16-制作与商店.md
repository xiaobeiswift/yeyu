# 《雾州侠行》制作与商店系统规格

> 状态：规划冻结候选稿
>
> 本文只定义未来实现契约，不代表代码已经存在。

## 1. 目标与非目标

### 1.1 目标

- 提供材料加工、消耗品制作、装备锻造以及 NPC 商店的统一交易规则。
- 所有制作、购买、出售和限购均为可恢复、可去重的库存事务。
- 以数据配置配方、价格、货币、库存周期、解锁条件和产物，不在 UI 或 Y3 触发中硬编码。
- 让门派权限、任务进度、章节、服务器周期和运营开关可组合控制配方与商品。
- 让装备实例创建沿用统一物品工厂，确保随机词条可重放、可校验。

### 1.2 非目标

- 不实现玩家交易、拍卖行、摆摊、邮件交易、跨服市场或动态玩家经济。
- 首版不实现现实时间制作队列、离线挂机产出、商店议价和买回列表。
- NPC 商店不得售卖真实货币商品；付费内容只进入平台商城与卡池系统。
- 本系统不自行修改任务、门派或角色状态，只调用其公开条件与奖励接口。

## 2. 依赖与跨系统接口

| 依赖 | 用途 |
|---|---|
| 09 背包、08 装备 | 09 预留材料/容量并维护所有权；装备产物调用 08 的纯 `EquipmentCreationPort` 生成实例草案 |
| 货币账本 | 铜钱、贡献等非付费货币扣减与增加 |
| 奖励事务 | 制作产物和购买物品的统一授予 |
| 条件求值器 | 章节、任务、门派、配方和商品资格 |
| 17 `TrustedPeriodPort` | 日、周和活动库存周期及 LIVE/CACHED 状态 |
| 门派系统 | 门派贡献消费和权限标签 |
| 角色/技艺 | 制作等级、技艺标签和品质加成读取 |
| 18 `SaveCoordinator` | 槽 4 单槽交易提交、收据查询和未知结果恢复 |

对外提供：

- RecipeCatalogQuery：查询可见、可制作及锁定原因。
- CraftItem：消费材料并创建产物。
- ShopCatalogQuery：按当前周期生成价格和剩余库存。
- BuyShopOffer、SellInventoryItem：执行幂等交易。

普通堆叠物创建归 09 的 InventoryMutationPort；装备实例内容通过 08 `EquipmentCreationPort.prepare_instance(source_spec,seed_context)` 纯函数得到 `EquipmentInstanceDraft`，所有权索引、锁定和收藏归 09。最终调用 `CreateOwnedEquipment`，由 `Slot4TransactionCoordinator` 同时提交 08 实例行、09 所有权索引、成本、库存计数和经济收据；实例 ID 按 created_receipt_id + creation_ordinal 稳定派生。16 不建立第二套实例 ID、所有权或保护状态。

## 5. 配置字段

### 5.1 制作配置

- RecipeDefinition 全字段。
- output_spec 包含 item_id、quantity、instance_policy、affix_pool_id、quality_floor 和绑定策略。
- recipe_unlock_source 指向任务、消耗型配方书或门派权限。
- craft_skill_bonus 只能影响文档明确允许的产量或词条池，不能改变付费结果。

### 5.2 商店配置

- ShopDefinition、ShopOffer。
- SellRule：允许出售的 item tag、禁止 tag、基础回收率 permille、单价上下界。
- PriceModifier：来源、permille、适用商店和互斥组。
- `cycle_def_id`：引用 17 的 CycleDefinition；商店配置不得复制时区、日切偏移或活动边界。

生成后配置必须携带 config_version；交易收据保存发生时的 offer_version，避免热更后重放得到不同结果。

## 6. 运行时状态

- catalog_version：当前内容版本。
- active_shop_id：当前打开商店，仅表现状态。
- resolved_periods：从 17 获得的 Period DTO 缓存；不是周期权威，可随时重建。
- stock_ledger：当前相关库存计数。
- pending_transactions：正在执行的 command_id。
- receipt_cache：近期交易结果。
- crafting_rng_counter：制作装备随机序列计数，属于槽 4 权威状态。
- read_only：存档不可写时为 true。

关闭 UI 不得取消已经进入提交阶段的交易。

## 7. 规则、公式与状态机

### 7.1 制作

制作数量 batch 必须为 1 至 batch_limit。总消耗和总产出使用检查溢出的整数乘法，先完成以下验证：

1. 配方可见且已解锁。
2. 技艺、任务、门派和章节条件满足。
3. 背包持有全部材料与货币。
4. 产物可放入背包；装备实例按最大可能槽数预留空间。
5. command_id 未被其他输入使用。

然后在同一领域事务中扣除材料、推进 crafting_rng_counter、创建全部产物、写入收据。任何产物创建失败均不扣材料。

装备词条随机种子由玩家存档种子、recipe_id、command_id 和原 crafting_rng_counter 规范化派生。使用独立 `crafting` PRNG 流，不得复用战斗、掉落、任务板或卡池随机序列，也不得使用本地时间或 `math.random`。

### 7.2 价格

所有修正以千分数表示。最终买价：

final_buy_price = max(1, floor(base_price × 所有允许修正的乘积 / 对应的 1000 次幂))

实现必须使用防溢出的固定顺序或有理数约分。修正按 modifier_id 排序，同一互斥组只取优先级最高者。最终卖价：

final_sell_price = max(0, floor(item_base_value × sell_rate_permille / 1000))

绑定、任务、付费权益、临时和明确禁止出售的物品卖价为 0 且不能提交。

### 7.3 库存周期

- UNLIMITED 不保存计数。
- LIFETIME 的 cycle_id 固定为 lifetime。
- SERVER_DAY 和 SERVER_WEEK 只接受 17 `TrustedPeriodPort` 返回的 cycle_id；16 不自行计算。
- 周期变化采用惰性切换：新 cycle_id 查询时视为新库存，不修改旧收据。
- 活动周期必须同时验证运营开关和 LIVE Period；CACHED 仅允许查看已知目录，不能提交限购交易。

### 7.4 交易状态

VALIDATING → RESERVED → COMMITTED。

在 COMMITTED 前发生明确失败必须释放内存预留。槽 4 保存结果未知时进入 PENDING_CONFIRMATION，通过原 command_id 向 SaveCoordinator 查询收据，不得换键重做。NPC 商店事务不跨平台商城，也不得调用 21 的付费权益接口。

## 8. 应用用例

| 用例 | 输入 | 前置 | 事务/输出 | 错误 | 幂等 |
|---|---|---|---|---|---|
| QueryRecipes | category、过滤条件 | 配置已加载 | 返回可见项、可制作数和锁定原因 | CONFIG_UNAVAILABLE | 只读 |
| UnlockRecipe | command_id、recipe_id、source | 来源可信 | 写解锁并返回目录变化 | RECIPE_ALREADY_UNLOCKED | command_id |
| CraftItem | command_id、recipe_id、batch | 可写、材料与空间足够 | 扣成本、建产物、写收据 | MATERIAL_INSUFFICIENT、INVENTORY_FULL | command_id |
| QueryShop | shop_id | 条件满足；周期商品至少有 CACHED Period | 返回价格、库存、周期信任状态和锁定原因 | SHOP_LOCKED、PERIOD_UNAVAILABLE | 只读 |
| BuyShopOffer | command_id、shop_id、offer_id、quantity、expected_cycle_id、expected_price | 周期商品要求 LIVE、快照仍有效 | 槽4单槽扣货币、增物品、增购买数和收据 | PRICE_CHANGED、STOCK_INSUFFICIENT、PERIOD_LIVE_REQUIRED | command_id |
| SellInventoryItem | command_id、instance/stack、quantity、expected_price | 物品可售 | 减物品、增货币 | ITEM_NOT_SELLABLE、ITEM_CHANGED | command_id |

客户端传入的 expected_price 只用于发现界面陈旧，权威价格必须重新计算。

## 9. 领域事件

| event_type | 关键 payload |
|---|---|
| RecipeUnlocked | recipe_id、source_id |
| CraftCompleted | recipe_id、batch、consumed、created_instance_ids |
| ShopOfferPurchased | shop_id、offer_id、quantity、cycle_id、paid_amount |
| InventoryItemSold | shop_id、item_id、quantity、received_amount |
| ShopCycleObserved | shop_id、cycle_id |

任务系统可以消费 CraftCompleted 和 ShopOfferPurchased，但必须按 event_id 去重。

## 10. 存档 DTO 与槽位

制作与 NPC 商店的权威状态统一位于槽 4。Inventory/Economy/Equipment/Crafting/Shop 作为槽 4 的 section owner，由 SaveCoordinator 一次提交货币、材料、物品实例、库存计数、随机计数和结果收据：

| DTO 字段 | 说明 |
|---|---|
| crafting_unlocks | 扁平 recipe_id 列表或布尔映射 |
| crafting_rng_counter | 非负整数 |
| shop_stock_entries | shop_id、offer_id、cycle_id、purchased_quantity 的扁平记录 |
| trade_receipts | command_id、输入哈希、结果摘要 |
| inventory_revision | 与背包事务共同递增 |
| section_revision/checkpoint_id | 乐观并发与 Manifest 检查点 |

槽 5 不保存第二份库存或交易成功结果。只有槽 4 写结果未知时，SaveCoordinator 可在槽 5 的全局 `RecoveryIndex` 保存 transaction_id、owner_slot=4、command_id 和查询状态；恢复时以槽 4 `trade_receipts` 为唯一事实。

日刷新 UI 可缓存 cycle_id，但重进后必须由 17 Period 与槽 4 对应 cycle_id 的库存计数重建。旧周期计数不改写为新周期，也不能被 UI 清零动作替代。

## 11. Y3 适配与 UI

- Y3 交互点只传 shop_id 或 station_id，不能传权威价格和奖励。
- 制作 UI 展示材料持有/需求、批量上限、产物范围、背包空间和明确锁定原因。
- 商店 UI 展示服务器周期、LIVE/CACHED 状态、剩余库存、单价、总价、货币余额和价格变化提示；CACHED 周期商品按钮禁用。
- 购买、出售和制作按钮提交期间禁用；超时进入“确认交易中”状态。
- 配置热更导致报价变化时要求玩家确认新价格，旧 command_id 不再提交。
- 背包已满、只读、服务器时间失败、配置下线和存档冲突均有独立错误状态。
- 动画、音效和制作进度条只是表现，不能延迟或决定领域提交。

## 12. 边界与失败

- 数量为 0、负数、非整数或乘法溢出时整笔拒绝。
- 同一 command_id 使用不同配方、商品或数量时拒绝，不返回旧结果伪装成功。
- 周期切换发生在商店打开期间时，提交返回 SHOP_CYCLE_CHANGED 并刷新目录。
- 商品热更下线后，旧界面提交返回 OFFER_UNAVAILABLE。
- 制作产物配置缺失时不得扣材料。
- 背包槽足够但唯一物品冲突时视为容量校验失败。
- TrustedPeriodPort 不可用时允许无周期配方和永久商店；禁止周期限购交易。CACHED 只能查看已有周期目录，不能推算刷新。
- 存档结果未知时保留 pending 状态，查询确认前不发第二份物品。

## 13. 生成与静态校验

- 配方、商店、offer 和 modifier ID 唯一且引用有效。
- 输入与产出数量为正整数；禁止同一配方无成本地产出可回售的正价值闭环。
- 所有价格和最坏批量总额不超过整数上限。
- 概率词条池总权重合法，品质上下界可达。
- 周期库存商品必须声明 stock_limit 并引用 17 中有效的 cycle_def_id，禁止复制 CycleDefinition 字段。
- 付费货币、付费权益物品和禁止出售 tag 不得进入 NPC 回收规则。
- 配方解锁条件不得依赖该配方产物自身形成死循环。
- 商品的权限来源必须在首章内容图中可达。

## 14. 测试矩阵

| 类别 | 必测场景 |
|---|---|
| 制作 | 单件、最大批量、材料不足、空间不足、唯一物品冲突 |
| 随机 | 同存档种子与计数产物一致；失败不推进计数 |
| 价格 | 多修正排序、互斥组、取整、最低价和溢出 |
| 库存 | 永久、日、周、跨周期旧界面提交 |

| UI | 加载、空目录、锁定、只读、价格变化和重复点击 |

## 15. 验收标准

- 所有制作和交易均能从配置生成，无 UI 硬编码价格或产物。
- 任意失败点均不会造成材料、货币、库存和物品实例不一致。
- 同一命令重复提交只产生一份产物或一次库存变化。
- 日切后库存正确重建，修改本地系统时间无效。
- 装备制作在相同权威输入下产生一致实例，并通过装备合法性校验。
- NPC 商店与平台商城边界明确，NPC 商店无法发放付费权益。

## 16. 实施任务拆分

1. 冻结配方、商店、报价、库存和出售规则 Schema。
2. 定义背包、货币、门派、条件求值与 TrustedPeriod 跨系统接口。
3. 实现价格计算、库存账本、制作与交易领域事务规格对应测试。
4. 定义物品实例工厂与确定性制作随机契约。
5. 定义槽 4 DTO、SaveCoordinator 单槽提交、槽5 RecoveryIndex、收据裁剪和失败恢复。
6. 规划 Y3 交互映射、制作 UI 和商店 UI 状态。
7. 完成经济闭环静态分析、集成测试和引擎验收。
