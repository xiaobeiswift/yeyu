# 《雾州侠行》门派与声望系统规格

> 状态：规划冻结候选稿
>
> 本文只定义未来实现契约，不代表代码已经存在。

## 1. 目标与非目标

### 1.1 目标

- 建立“结识门派—满足入门条件—加入—积累声望与贡献—完成晋升—解锁武学、商店和剧情”的长期成长线。
- 将门派身份、声望、职阶、晋升条件和权限定义为可校验的领域状态；可消费的门派贡献是经济系统中的 `currency_faction_<id>`，不在本系统复制余额。
- 让任务、委托、商店、武学、剧情和擂台只通过稳定接口读取门派结果，不直接修改门派存档。
- 区分永久成长指标“声望”和可消费资源“门派贡献”，避免一个数值同时承担进度与货币职责。
- 支持后续增加多个原创门派，但首个发布版本同一时间只允许一个有效门派身份。

### 1.2 非目标

- 不实现玩家公会、实时门派战、玩家职位竞选、门派领地经营或玩家间捐赠。
- 首章不实现叛门、逐出、多门派并行身份和跨服门派排行。
- 门派系统不直接执行战斗、发物品或教授武学；这些动作分别委托战斗、奖励、背包和武学用例。
- 不在领域层保存 NPC、Y3 单位、UI 节点或物编数字 Key。

## 2. 依赖与跨系统接口

### 2.1 依赖

| 依赖 | 用途 |
|---|---|
| 玩家档案 | 玩家稳定 ID、章节进度和新档状态 |
| 任务与剧情 | 入门、晋升、专属剧情和条件判断 |
| 角色与武学 | 武学学习资格和角色成长读取 |
| 经济、背包与奖励事务 | 查询/预留 `currency_faction_<id>`、晋升材料和奖励发放 |
| 制作与商店 | 门派商店权限、折扣和配方解锁 |
| 14 任务 / 17 任务板 | 17 只提供门派委托 Offer 与周期资格；14 完成后以可信奖励事务请求声望与贡献 |
| 17 `TrustedPeriodPort` | 服务器日与周期资格；本系统不自行计算日切 |
| 22 `ClockService.now()` | 未来离门/回归冷却所需可信 UTC 时间戳，不生成周期 ID |
| SaveCoordinator | 槽 2 门派 section 与跨槽可恢复事务 |

### 2.2 对外提供

- FactionQuery：查询当前身份、职阶、声望和已解锁权限；展示 DTO 通过 EconomyQuery 合并贡献余额。
- FactionRequirementEvaluator：判断任务、武学、商店、对话和配方所需门派条件。
- GrantFactionProgress：由可信奖励编排器增加声望，并把贡献奖励作为经济子事务提交。
- FactionContributionFacade：按门派映射贡献 currency_id，并委托 EconomyQuery/EconomyTransactionPort 查询或消费。
- PromoteFactionMember：完成一次职阶晋升。

### 2.3 依赖方向

- 任务和委托只能发出“门派进度奖励请求”，不能写门派字段。
- 商店、武学和对话只读取权限标签，不根据 UI 显示状态推断资格。
- 门派晋升可调用奖励事务，但奖励失败时晋升不得部分提交。
- 声望变化不自动触发晋升；它只使晋升条件可能满足。

## 4. 领域模型

### 4.1 FactionMembership

| 字段 | 类型 | 约束 |
|---|---|---|
| faction_id | string | 稳定 ID，前缀 faction_ |
| status | enum | CANDIDATE、MEMBER、SUSPENDED、LEFT |
| rank_id | string | 必须属于当前 faction_id |
| reputation | integer | 0 至 2,147,483,647；永久进度，不可消费 |
| contribution_currency_id | string | 固定映射 `currency_faction_<faction_id>`；余额由经济槽 4 权威保存 |
| joined_at | integer | 可信服务器时间；未知时不得加入 |
| promoted_at | integer | 最近晋升服务器时间 |
| left_at | integer? | 未离门时为空 |
| revision | integer | 每次权威变化递增 |

### 4.2 FactionRank

| 字段 | 类型 | 说明 |
|---|---|---|
| rank_id | string | 稳定职阶 ID |
| faction_id | string | 所属门派 |
| order | integer | 从 1 递增，不允许重复 |
| min_reputation | integer | 晋升所需最低声望 |
| promotion_quest_id | string? | 晋升任务；首阶可为空 |
| contribution_cost | integer | 晋升消耗 |
| required_item_costs | list | 物品 ID 与数量 |
| granted_permission_tags | list | 晋升后拥有的权限标签 |
| reward_bundle_id | string? | 晋升奖励 |

### 4.3 FactionProgressReceipt

| 字段 | 类型 | 说明 |
|---|---|---|
| receipt_id | string | 全局唯一幂等键 |
| faction_id | string | 目标门派 |
| source_type | enum | QUEST、COMMISSION、STORY、ADMIN_RECOVERY |
| source_id | string | 来源实例 ID |
| reputation_delta | integer | 非负 |
| economy_receipt_id | string? | 贡献奖励/消费对应的经济子收据；本系统不保存余额 |
| resulting_revision | integer | 首次提交后的修订 |

收据只保存必要去重窗口；永久唯一奖励还必须由来源系统保存其已领取状态。

## 5. 配置字段

### 5.1 FactionDefinition

| 字段 | 必填 | 规则 |
|---|---:|---|
| id | 是 | 唯一 faction_ ID |
| name_key、description_key | 是 | 本地化键存在 |
| initial_rank_id | 是 | 指向本门派 order=1 的职阶 |
| join_requirement_id | 是 | 指向可求值条件集合 |
| join_quest_id | 否 | 存在时必须可达 |
| rank_ids | 是 | 至少一个，order 连续递增 |
| permission_tags | 是 | 本门派可产生的权限白名单 |
| shop_ids | 否 | 指向门派商店 |
| martial_unlock_ids | 否 | 仅用于索引，权威条件仍在武学配置 |
| ui_theme_id | 是 | 指向有效 UI 主题 |
| deprecated | 是 | 默认 false |

### 5.2 FactionRequirementDefinition

条件项允许：章节完成、任务完成、角色等级、前置对话选择、物品持有、门派状态、职阶、声望和权限标签。一个条件组必须显式声明 ALL 或 ANY，不允许隐式默认。

## 6. 运行时状态

FactionSessionState 包含：

- load_state：UNLOADED、READY、READ_ONLY、ERROR。
- active_membership：当前有效身份；首版最多一个。
- pending_command_ids：正在提交的入门、进度或晋升命令。
- evaluated_permissions：按 membership_revision 缓存的权限标签集合。
- receipt_cache：近期幂等收据索引。
- dirty：是否存在待保存变化。

缓存不得写入存档；membership revision 改变时必须整体失效。

## 7. 核心规则与状态机

### 7.1 身份状态机

允许转换：

- 无记录 → CANDIDATE：首次接触或开始入门流程。
- CANDIDATE → MEMBER：入门条件满足且入门事务成功。
- MEMBER → SUSPENDED：仅为未来剧情预留，首章无入口。
- SUSPENDED → MEMBER：可信剧情用例恢复。
- MEMBER → LEFT：未来离门用例；首章禁止。

禁止直接从无记录进入高阶职阶，也禁止 LEFT 自动恢复 MEMBER。

### 7.2 声望与贡献边界

- 声望只能增加；内容回滚需要专用迁移，不允许普通玩法扣减。
- 贡献余额、上限、预留和扣减只由 10 经济系统校验；本系统只提供 faction_id→currency_id 映射和合法用途。
- 同时奖励声望与贡献时，使用同一 transaction_id：槽 5 写 PREPARED，槽 4 提交贡献子收据，槽 2 提交声望子收据，再前向恢复到 COMMITTED。
- 任何结果未知都进入恢复，不得把槽 2 或 UI 中的贡献显示值当成余额。
- UI 可显示达到下一职阶还差多少声望，但不能自动晋升。

### 7.3 晋升

晋升必须同时满足：

1. 当前状态为 MEMBER。
2. 目标职阶是当前 order+1。
3. 声望达到阈值。
4. 晋升任务和额外条件完成。
5. 贡献及物品足够。
6. 同一 promotion_command_id 未处理。

事务遵循 [ADR-0002](../architecture/ADR-0002-跨槽可恢复事务.md)：验证来源修订 → 写 PREPARED 意图 → 由经济/背包预留并提交成本子收据 → 更新槽 2 职阶子收据 → 发放奖励子收据 → 标记 COMMITTED。任一步未知时停止普通重试并前向恢复，不能承诺多个 Y3 云槽整体回滚。

## 8. 应用用例

| 用例 | 输入 | 前置 | 事务与输出 | 主要错误 | 幂等 |
|---|---|---|---|---|---|
| QueryFaction | faction_id? | 存档已加载 | 返回身份、下一职阶和权限 DTO | FACTION_NOT_FOUND | 只读 |
| BeginFactionCandidacy | command_id、faction_id | 无其他有效门派 | 建立 CANDIDATE | FACTION_ALREADY_JOINED、REQUIREMENT_MISSING | command_id |
| JoinFaction | command_id、faction_id | 入门条件及任务完成 | 建立 MEMBER、初始职阶、事件 | CLOCK_UNAVAILABLE、SAVE_READ_ONLY | command_id |
| GrantFactionProgress | transaction_id、来源、声望增量、贡献奖励项? | 来源可信、身份有效 | 增加声望；贡献委托经济子事务；返回组合结果 | FACTION_NOT_MEMBER、VALUE_OVERFLOW、TRANSACTION_RECOVERY_REQUIRED | transaction_id |
| SpendFactionContribution | transaction_id、用途、数量 | EconomyQuery 返回余额足够 | 只编排 `currency_faction_<id>` 经济消费，不写 Membership | ECONOMY_BALANCE_INSUFFICIENT | transaction_id |
| PromoteFactionMember | command_id、target_rank_id | 全部晋升条件满足 | 扣费、升阶、发奖 | PROMOTION_NOT_READY、REVISION_CONFLICT | command_id |

所有写用例在 SaveCoordinator 为只读或恢复中时返回 SAVE_READ_ONLY 或 TRANSACTION_RECOVERY_REQUIRED。超时后调用方必须用原幂等键查询结果，不能换新键盲目重试。

## 9. 领域事件

| event_type | 关键 payload |
|---|---|
| FactionCandidacyStarted | faction_id |
| FactionJoined | faction_id、rank_id、joined_at |
| FactionProgressGranted | faction_id、source_id、reputation_delta、economy_receipt_id? |
| FactionRankPromoted | faction_id、from_rank_id、to_rank_id |
| FactionPermissionChanged | faction_id、added_tags、removed_tags |

奖励、任务、商店和武学消费者按 event_id 去重。权限事件是结果通知，不可被消费者当作重新授予职阶的命令。

## 10. 存档 DTO 与槽位

权威门派进度位于槽 2：

| DTO 字段 | 说明 |
|---|---|
| schema_version、revision | 槽信封版本与修订 |
| faction_active_id | 当前有效门派 ID 或空 |
| faction_records | 按 faction_id 扁平记录 status、rank_id、reputation、contribution_currency_id 和时间 |
| faction_receipts | 近期 receipt_id、来源和 resulting_revision |

门派贡献的唯一权威余额位于槽 4 的经济账本。槽 2 不保存余额；门派页通过 EconomyQuery 组合展示。门派专属武学和物品仍分别归槽 3、槽 4。

## 11. Y3 适配与 UI

- Y3 适配器只负责读取服务器时间、保存 DTO、映射 NPC 交互和发送 UI 数据。
- 门派大厅 NPC 的物编 Key 只出现在 mappings；领域层只识别 faction_id 和 interaction_id。
- 门派页展示身份、职阶、声望进度、贡献、权限、晋升条件和关联委托入口。
- 未加入、可加入、条件不足、可晋升、忙碌、只读和保存失败必须有不同状态。
- 晋升与贡献消费按钮提交期间禁用；超时显示“正在确认”，不得直接再次扣费。
- 门派商店和武学页展示逐项锁定原因，原因来自 RequirementEvaluator。

## 12. 边界与失败处理

- 配置下线的门派记录仍可读取；只禁止新加入，不删除玩家历史。
- 当前职阶配置缺失时进入只读恢复，不能自动降为初阶。
- 声望溢出由本系统拒绝；贡献上限由经济子事务拒绝，组合事务进入明确失败或恢复状态。
- 任务奖励事件重复投递时返回原收据，不重复增加进度。
- 服务器时间不可用时允许查询，但禁止首次加入和时间相关状态转换。
- 多槽奖励事务无法保证提交时，晋升先保持 PENDING_RECOVERY，不向 UI 宣布成功。
- 旧档出现多个 MEMBER 时由迁移规则明确选定 active_id；运行时不得自行猜测。

## 13. 生成与静态校验

- faction_id、rank_id 和 permission tag 全局唯一。
- 每个门派恰有一个 order=1，职阶 order 连续且声望阈值严格递增。
- 晋升任务、奖励包、商店、武学和 UI 主题引用有效。
- 晋升任务不得依赖尚未获得的目标职阶权限，防止循环锁死。
- contribution_cost、声望阈值和增量均为合法整数；每个门派恰有一个有效贡献 currency_id，且经济来源/消耗白名单包含晋升用途。
- 所有权限需求必须由至少一个可达职阶或剧情来源提供。
- deprecated 门派不能被新任务配置为可加入目标。

## 14. 测试矩阵

| 类别 | 必测场景 |
|---|---|
| 单元 | 身份合法转换、声望单调、贡献 currency 映射、职阶相邻晋升 |
| 条件 | ALL/ANY、缺失引用、任务与职阶循环、锁定原因 |
| 幂等 | 重复入门、重复奖励、重复晋升、超时后同键重试 |
| 事务 | 扣费成功后后续步骤失败、存档冲突、按子收据前向恢复后余额与职阶一致 |
| 迁移 | 无门派旧档、旧职阶 ID、多个 MEMBER 异常档 |
| UI | 未加入、条件不足、可晋升、只读、保存失败和重复点击 |
| 集成 | 委托发贡献、晋升解锁商店、武学权限即时刷新 |

## 15. 验收标准

- 玩家可通过完整任务链加入一个原创门派并看到正确初始职阶。
- 声望达到阈值不会自动晋升；完成晋升后权限、奖励和贡献扣除一致。
- 相同奖励或晋升命令重复提交不会产生第二次变化。
- 门派商店、武学、任务和对话对同一权限给出一致结果。
- 保存重进后身份、职阶、声望与经济系统组合出的贡献余额一致，事务收据可恢复。
- 配置断链、循环晋升条件和非法阈值在生成阶段被阻止。

## 16. 实施任务拆分

1. 冻结门派、职阶、权限和条件 Schema。
2. 实现纯领域身份状态机、进度账本和条件求值规格对应测试。
3. 定义门派应用用例及奖励事务接口。
4. 定义槽 2 DTO、迁移和异常档恢复规则。
5. 接入任务、委托、商店、武学和奖励跨系统契约。
6. 规划 Y3 NPC 交互映射与门派 UI 状态。
7. 完成配置生成校验、无引擎测试和引擎验收。

## 17. 待决项

- 首个可加入门派及各职阶正式命名、剧情条件和数值阈值。
- 后续版本是否开放离门、回归、逐出及对应服务器日冷却。
- 是否存在跨门派通用声望；首版按“不存在”实现。
- 各门派贡献余额上限由经济 `CurrencyDefinition` 冻结，本系统只决定晋升用途与显示。
- 多槽事务长时间停留在恢复状态时采用的最终 UI 文案与人工处理边界。
