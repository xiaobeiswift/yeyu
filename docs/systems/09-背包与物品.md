# 《雾州侠行》背包与物品系统工程规格

> 状态：工程实施规格候选稿；仅描述未来实现，不代表代码、配置或 Y3 物编已经存在。
>
> 上位约束：[00-通用工程约定](./00-通用工程约定.md)。

## 1. 目标与非目标

### 1.1 目标

- 为堆叠物品、唯一装备实例、任务物品、消耗品、材料、兑换凭证和普通杂物提供统一的所有权与容量规则。
- 定义可事务化发放、消耗、战斗外使用、锁定、收藏、丢弃、拆分展示和排序查询的背包聚合。
- 背包满时不吞战斗/任务关键奖励：预检失败应进入奖励待领取流程或阻止领取，具体由奖励系统显式选择。
- 保证任务、制作、装备、商店、奖励和 UI 只能经稳定端口改变物品数量，不能各自维护副本。
- 在 Y3 云存档三层嵌套限制内稳定保存，并能检测负数、超上限、未知物品和重复实例。

### 1.2 非目标

- 货币不作为背包堆叠物；余额和账本由 `10-经济奖励与掉落` 管理。
- 装备属性、强化、淬炼、穿戴与随机词条由 `08-装备强化与淬炼` 管理，本系统只管理实例所有权、占用和保护状态。
- 不实现玩家交易、拍卖、邮件、仓库、地面丢包、死亡掉落、重量负重或付费扩容。
- 不允许“背包满则自动出售/分解”这种隐式行为。
- 任务物品 V1 不可主动丢弃或出售；如剧情需要移除，必须由任务授权命令完成。
- V1 不支持战斗内使用任何背包道具；战斗快照、命令流和结算均不读取或扣除实时背包。`COMBAT` 使用上下文保留为未来版本占位，但当前配置生成和运行时都必须拒绝。

## 2. 依赖、所有权与跨系统接口

### 2.1 依赖关系

| 系统 | 关系 |
|---|---|
| 08 装备 | 本系统拥有装备实例所有权索引、容量、锁定与收藏；装备系统拥有实例内容、强化/词条和穿戴规则 |
| 10 经济/奖励 | 奖励以批次请求发放；背包返回容量计划与提交结果 |
| 11 经脉 | 消耗指定材料必须经 `ConsumeItems` |
| 12 世界探索 | 采集/宝箱只产生奖励请求，不直接改背包 |
| 13 对话 | 对话效果可查询/消耗物品，但必须经白名单用例 |
| 14 任务 | 监听获取/消耗事件；任务授权移除任务物品 |
| 16 制作/商店 | 原料扣除、成品入包、购买预检 |
| 18 存档 | 槽 4 权威读取写入与只读恢复 |
| 19 UI | 背包视图、快捷栏输入，不直接持有权威数量 |
| 23 数据生成 | 物品定义、使用效果、堆叠规则校验 |

### 2.2 稳定端口

| 端口 | 输入/输出语义 | 保证 |
|---|---|---|
| `InventoryQuery.get_count(item_id, include_reserved)` | 返回非负整数 | 不含装备实例；任务条件必须声明是否计预留 |
| `InventoryQuery.has_items(cost_list)` | 返回逐项缺口 | 输入先合并同 ID，避免重复行绕过校验 |
| `InventoryQuery.list_view(filter,sort,page)` | 返回视图 DTO | 排序稳定，分页不改变权威顺序 |
| `InventoryCapacityPort.plan_grant(grant_batch)` | 返回占用变化与是否可放入 | 纯计算，不预留、不修改 |
| `InventoryMutationPort.reserve/commit/release` | 供跨系统事务使用 | 预留有可恢复状态和命令收据，不能超卖；跨槽步骤遵循 18 Saga |
| `InventoryCommand.use_item` | 仅在 WORLD/NO_COMBAT 执行白名单使用效果 | 跨 owner 效果与扣除用子收据前向恢复；战斗上下文稳定拒绝 |
| `EquipmentOwnershipPort` | 装备系统查询/移动实例 | 由 `Slot4TransactionCoordinator` 在一个 change set 中维护实例内容、所有权索引、占用和收据；事件只通知 |
| `InventoryProtectionPort` | 装备、商店、制作查询保护状态 | 锁定/收藏的唯一写入口在本系统；其他系统只能查询并拒绝危险操作 |
| `QuestItemAuthorityPort` | 任务系统移除任务物品 | 必须带任务 ID、阶段与幂等键 |

## 4. 领域模型

### 4.1 `ItemDefinition`

| 字段 | 类型/范围 | 必填 | 说明 |
|---|---|---:|---|
| `item_id` | `item_*` | 是 | 发布后不可复用 |
| `category` | 枚举 | 是 | `CONSUMABLE/MATERIAL/QUEST/TOKEN/EQUIPMENT/MISC` |
| `name_key/description_key` | 本地化 Key | 是 | 配置不存最终中文文本 |
| `icon_id` | 稳定资源 ID | 是 | Y3 映射到图片 Key |
| `rarity` | `COMMON/FINE/RARE/EPIC/LEGEND` | 是 | 展示和保护策略 |
| `max_stack` | 整数 1–999999 | 是 | `EQUIPMENT` 必须为 1 |
| `capacity_policy` | `NORMAL/KEY_ITEM_FREE` | 是 | `QUEST` 默认不占普通容量 |
| `bind_policy` | V1 固定 `ACCOUNT_BOUND` | 是 | 不支持交易 |
| `use_rule_id` | `itemuse_*` 或空 | 否 | 只有可使用类别允许 |
| `discard_policy` | `DENY/CONFIRM/ALLOW` | 是 | 任务物品必须 `DENY` |
| `sort_group/sort_order` | 整数 | 是 | 稳定默认排序 |
| `source_hint_keys` | 有序本地化 Key | 否 | UI 获取途径 |
| `deprecated` | 布尔 | 是 | 旧档可读，新产出禁用 |

### 4.2 `Inventory`

| 字段 | 类型 | 说明 |
|---|---|---|
| `owner_id` | 玩家稳定内部 ID | 不保存平台敏感明文 |
| `stack_counts` | `item_id -> 非负整数` | 0 数量不持久化 |
| `equipment_instance_ids` | 排序后的唯一 ID 集合 | 实例详情由装备子表保存 |
| `capacity_limit` | 整数 1–9999 | V1 默认 60，可由非付费进度配置增加 |
| `reserved_units` | 运行时整数 | 不直接长期持久化；由恢复收据重建 |
| `favorite_flags` | `ownership_key -> 布尔` | 堆叠物使用 item ID，装备使用实例 ID |
| `lock_flags` | `ownership_key -> 布尔` | 库存保护锁唯一权威；08 不复制到 EquipmentInstance |
| `inventory_revision` | 非负整数 | 任意权威所有权变化加 1 |

### 4.3 容量单位

- 普通堆叠物占用 `ceil(count/max_stack)` 格。
- 每件未穿戴的装备实例占 1 格；已穿戴装备不占背包格，但仍属于玩家。
- `KEY_ITEM_FREE` 物品占 0 格，数量仍受最大总量约束。
- 同一 `item_id` 的多个逻辑堆叠在领域层合并为总数，UI 按 `max_stack` 虚拟拆格；不得把 UI 格序号写入存档。
- 默认容量 60，V1 通过剧情奖励最多扩至 100；具体扩容节点配置于玩家成长，不从本地 UI 直接修改。

### 4.4 命令与预留模型

`InventoryReservation` 字段：`reservation_id`、`command_id`、合并后的物品增减列表、装备实例增减列表、计划占用、基础修订、状态、创建服务器时间（若可用）、恢复策略。

状态为 `PLANNED/RESERVED/COMMITTED/RELEASED/UNKNOWN`。`COMMITTED` 与 `RELEASED` 为终态。未知状态必须查询业务收据，不能按本地超时直接释放并重做。

### 4.5 快捷栏

快捷栏只保存最多 8 个 `item_id` 引用，不预留物品、不改变排序。数量为 0 时保留引用并灰显；物品被废弃或不可使用时自动清空该引用并发 UI 通知。

## 5. 配置表与字段

### 5.1 `item_definitions`

使用 4.1 字段。附加校验字段：`ownership_cap`（单玩家最大总数，1–2,000,000,000）、`confirm_threshold`（丢弃数量达到此值需二次确认）、`usage_contexts`（V1 只允许 `WORLD/NO_COMBAT`）。生成器发现 `COMBAT` 必须报 `ITEM_COMBAT_USAGE_UNSUPPORTED`，不能静默降级。

### 5.2 `item_use_rules`

| 字段 | 约束 | 说明 |
|---|---|---|
| `use_rule_id` | `itemuse_*` | 规则 ID |
| `target_mode` | `SELF/ALLY/NO_TARGET` | 目标模式 |
| `allowed_context` | 枚举集合 | V1 只允许 `WORLD/NO_COMBAT`；`COMBAT` 配置非法 |
| `effect_request_type` | 白名单枚举 | 如恢复、解除状态、增加世界时间；禁止脚本字符串 |
| `effect_ref_id` | 对应稳定 ID | 交给效果系统处理 |
| `consume_count` | 1–9999 | 单次消耗 |
| `cooldown_group` | 稳定字符串或空 | 战斗冷却由战斗系统权威管理 |
| `condition_set_id` | 条件集合或空 | 角色状态/任务条件白名单 |
| `consume_on_no_effect` | V1 固定 `false` | 无有效效果不消耗 |

### 5.3 `inventory_capacity_progression`

| 字段 | 约束 | 说明 |
|---|---|---|
| `upgrade_id` | 稳定字符串 | 一次性扩容来源 |
| `required_flag` | 世界/任务标记 | 权威解锁条件 |
| `capacity_delta` | 正整数 1–50 | 增量 |
| `max_total_after` | 1–9999 | 防重复叠加 |

## 6. 运行时状态与不变量

### 6.1 不变量

1. `stack_counts` 中所有数量为 `1..ownership_cap`；0 值删除，负值立即拒绝。
2. `EQUIPMENT` 不得出现在 `stack_counts`，非装备不得出现在实例集合。
3. 装备实例集合内 ID 唯一，且每个 ID 都能在装备子表找到；穿戴实例可以不占格但不能脱离所有权。
4. `used_capacity + reserved_capacity <= capacity_limit`。
5. 对同一 `command_id` 的已提交变更重复执行只返回原 `InventoryMutationResult`。
6. 任务物品和被锁装备不能由普通丢弃/拆解命令移除。
7. 视图排序、筛选和搜索不改变 `inventory_revision`。
8. 存档只读时允许查询和本地排序，不允许任何权威变更。

### 6.2 数量合并

所有输入批次先按 `item_id` 字典序归一化并合并；每项使用有符号宽整数检查求和，再验证边界。不得逐行校验后再合并，以免两个合法小增量合并后越界。

## 7. 规则与状态机

### 7.1 发放计划

`plan_grant` 按当前数量、已预留数量和批次增量计算新占用：

`stack_slots(count,max_stack) = floor((count + max_stack - 1) / max_stack)`。

所需增量为每种物品新旧格数差，加新增未穿戴装备实例数。`KEY_ITEM_FREE` 的格数恒为 0。若任一数量越过 `ownership_cap`，返回 `ITEM_OWNERSHIP_CAP_REACHED`，不允许以容量足够为由截断数量。

### 7.2 扣除顺序

- 消耗堆叠数量没有具体格序；从总数直接扣除。
- 一次命令的多项成本必须全有才可预留，禁止部分扣除。
- 对装备实例的移除必须提交明确实例 ID，不能“任意拆一件同名装备”。
- 使用物品时先验证目标和效果可执行，再预留物品；效果与消耗共同提交。

### 7.3 背包满策略

调用方必须在命令中声明 `overflow_policy`：

| 策略 | 允许调用方 | 行为 |
|---|---|---|
| `REJECT` | 购买、制作、拾取、普通领取 | 整批失败，不改变状态 |
| `PENDING_REWARD` | 战斗/任务/运营奖励 | 奖励系统保存完整待领取批次；背包不部分接收 |
| `KEY_ITEMS_ONLY` | 剧情强制关键物 | 仅当整个批次都是免容量任务物品时允许 |

V1 禁止自动放地面、自动出售、自动拆解和静默丢弃。待领取奖励由 10 系统管理，不是邮件。

### 7.4 丢弃与销毁

- `DENY` 永不允许普通丢弃。
- `CONFIRM` 需要 UI 生成的短期确认令牌，令牌绑定物品、数量、修订和本地化名称版本；服务仍重新校验。
- 稀有及以上物品默认二次确认；装备锁定或穿戴时拒绝。
- 丢弃不产生货币或材料；拆解属于经济奖励事务，调用装备的拆解奖励定义。
- 任务授权移除不视为丢弃，事件为 `QuestItemConsumed`，并带任务阶段收据。

### 7.5 使用物品状态机

V1 仅有战斗外状态机：`IDLE → VALIDATING → PREPARED → APPLYING_OWNER_EFFECT → COMMITTING_INVENTORY → COMMITTED`。跨槽时由 18 `PendingTransaction` 保存父事务与 owner 子收据；单槽效果可直接合并到槽 4 change set。

- 目标无效或效果为零且 `consume_on_no_effect=false`：回 `IDLE`，不消耗。
- 效果 owner 返回失败：在背包扣除前终止；若 owner 子收据状态未知则进入恢复，不得猜测重发。
- 提交结果未知：进入 `UNKNOWN`，禁用该命令影响的物品数量，按收据查询。
- 战斗会话存在时 `UseItem`、快捷栏和任何脚本调用统一返回 06 冻结的 `COMBAT_ITEM_USE_UNSUPPORTED`。V1 不定义、不发送 `ItemUseRequested`，战斗结束也不按战斗收据补扣实时背包。

### 7.6 稳定排序

默认顺序：类别配置序 → 稀有度降序 → `sort_order` 升序 → `item_id` 升序 → 装备实例 ID 升序。自定义排序只保存在本地 UI 设置，不作为云档权威进度。

## 8. 应用用例契约

| 用例 | 输入 | 前置 | 事务/幂等 | 输出 | 错误 |
|---|---|---|---|---|---|
| `GetInventoryView` | 筛选、排序、页游标 | 槽4已加载 | 只读 | 项目、容量、余额引用、修订 | `SAVE_NOT_READY` |
| `PlanInventoryGrant` | 标准化奖励批次 | 配置存在 | 纯计算 | 新占用、缺口、可用策略 | `ITEM_UNKNOWN`、`INVENTORY_FULL` |
| `GrantItems` | 批次、来源、溢出策略、`command_id` | 来源已授权 | 收据+所有权组成一个槽4 change set | 实际发放、修订 | `INVENTORY_FULL`、`ITEM_CAP_REACHED` |
| `ConsumeItems` | 成本列表、用途、`command_id` | 数量足、用途白名单 | 全有全扣，重复返回原结果 | 消耗摘要、修订 | `ITEM_INSUFFICIENT` |
| `UseItem` | 物品、数量/目标、`command_id` | WORLD/NO_COMBAT 且条件合法 | 同槽合并提交；跨槽按 18 Saga 和 owner 子收据恢复 | 效果摘要、剩余数量 | `ITEM_NOT_USABLE`、`ITEM_NO_EFFECT`、`COMBAT_ITEM_USE_UNSUPPORTED` |
| `DiscardItem` | ownership key、数量、确认令牌、`command_id` | 未锁、可丢弃 | 销毁与墓碑/收据提交 | 销毁摘要 | `ITEM_DISCARD_DENIED`、`CONFIRMATION_STALE` |
| `SetInventoryLock` | item/实例 ID、布尔、期望修订、`command_id` | 拥有 | 槽4所有权索引幂等设置 | 新锁定标记 | `ITEM_NOT_OWNED` |
| `SetFavorite` | item/实例 ID、布尔、期望修订 | 拥有 | 单槽提交；幂等设置 | 新标记 | `ITEM_NOT_OWNED` |
| `SetQuickSlot` | 槽1–8、item ID或空、`command_id` | 可使用类别 | 槽4提交 | 快捷栏 | `ITEM_NOT_USABLE` |
| `ExpandCapacity` | upgrade ID、`command_id` | 解锁条件满足且未领 | 一次性收据+容量提交 | 新容量 | `CAPACITY_UPGRADE_ALREADY_APPLIED` |
| `ClaimPendingReward` | pending ID、`command_id` | 奖励存在且容量足 | 按 10/18 的父收据与子收据可恢复提交，不承诺跨云槽 ACID | 发放与移除待领取 | `INVENTORY_FULL`、`PENDING_REWARD_NOT_FOUND` |

所有变更用例都接收 `expected_inventory_revision`。修订冲突返回最新轻量摘要，UI 刷新后再由玩家确认；不得自动重放可能销毁或消耗物品的命令。

## 9. 领域事件

| 事件 | payload | 主要消费者 |
|---|---|---|
| `ItemGranted` | `item_id,quantity,source_type,source_ref,receipt_id` | 任务、引导、统计 |
| `ItemConsumed` | `item_id,quantity,purpose_type,purpose_ref,receipt_id` | 任务、经济、统计 |
| `ItemUsed` | `item_id,quantity,target_id,effect_summary,receipt_id` | 任务、战斗外表现 |
| `ItemDiscarded` | `ownership_key,quantity,receipt_id` | 诊断 |
| `QuestItemConsumed` | `item_id,quantity,quest_id,objective_id,receipt_id` | 任务状态机 |
| `EquipmentOwnershipAdded` | `instance_id,equipment_id,receipt_id,slot4_revision` | 任务、UI；实例与所有权已由槽4协调器提交，事件不得触发补写 |
| `EquipmentOwnershipRemoved` | `instance_id,reason,receipt_id,slot4_revision` | 任务、UI；只通知已提交事实 |

## 10. 存档 DTO、槽位与迁移

### 10.1 槽 4 `InventorySaveDTO`

| 字段 | 形态 | 说明 |
|---|---|---|
| `schema_version/revision` | 整数 | 统一信封 |
| `inventory_meta` | 扁平记录 | `capacity_limit,inventory_revision` |
| `stack_counts` | `item_id -> count` | 不写 0 |
| `equipment_ownership_ids` | 排序后的实例 ID 列表 | 所有权唯一权威；08 的实例详情是同槽另一平行表 |
| `favorite_flags` | `ownership_key -> 1` | 只保存 true |
| `lock_flags` | `ownership_key -> 1` | 只保存 true；其他系统不得复制 |
| `quick_slots` | `slot_index -> item_id` | 最多 8 |

槽 4 的一次写入由 SaveStore 以整个槽修订处理。多个系统共享槽 4 时必须通过统一 `Slot4TransactionCoordinator` 合并变更，禁止装备、经济、制作分别读改写覆盖彼此。

### 10.2 槽 5 收据与预留恢复

- 保存未决事务 `command_id -> state/result_hash/slot4_revision`，嵌套不超过三层。
- 已提交关键一次性收据按业务命名空间永久保留或压缩成不可碰撞的稳定键；不得因容量限制删除仍可重放的任务/购买收据。
- 普通重复掉落收据可按内容周期归档，但归档前必须保证来源自身有唯一结算记录。

### 10.3 迁移

- 旧档若按 UI 格保存，迁移时合并同 item ID 数量，装备格转实例列表，排序不影响结果。
- 数量超过新 `ownership_cap` 不得截断；进入只读恢复并输出补偿迁移计划。
- 物品下线时保持定义兼容壳；若必须替换，以明确映射和迁移收据作为一个槽 4 change set 转换。
- 未知 item ID 不自动删除，隔离为 `orphan_items` 只读记录，待兼容配置恢复；UI 显示“待恢复物品”而非伪造名称。

## 11. Y3 适配与 UI

### 11.1 Y3 适配

- 图标、物编道具和快捷栏能力只作表现映射；权威数量仍在纯 Lua 背包聚合。
- 若使用 Y3 实体道具表现世界拾取，实体销毁必须发生在奖励提交成功之后；失败时保留或按来源恢复交互。
- UI 拖放只产生 `SetQuickSlot/UseItem/EquipItem` 命令，不直接操作 Y3 物品句柄。
- 存档适配器将平行表编码到槽 4，并在写后读取/校验修订。

### 11.2 背包 UI

必须有 `LOADING/EMPTY/READY/BUSY/READ_ONLY/ERROR/COMMIT_UNKNOWN` 状态。

- 顶部显示 `used/capacity`，任务免容量物品单独标记，不制造“占格”错觉。
- 分类：全部、消耗、材料、任务、凭证、装备、其他；搜索只匹配本地化显示文本与稳定别名，不修改权威数据。
- 项目详情显示数量、稀有度、用途、获取途径、是否锁定、可执行操作和禁用原因。
- 批量操作必须先列出精确对象与数量，再请求确认；穿戴装备、任务物品和收藏物默认排除。
- 背包满提示提供“整理/消耗/拆解/返回待领奖励”路径，不提供静默清理。
- 快捷栏数量实时订阅 `InventoryRevisionChanged`，0 时灰显；重复点击使用由命令幂等键和按钮忙碌态双重防护。

## 12. 边界、失败与恢复

| 场景 | 行为 |
|---|---|
| 发放批次部分能放 | 整批拒绝或完整转待领；不得部分发放，除非奖励定义明确拆分为独立批次 |
| 多行同物品成本 | 先合并再校验，防止负数/重复绕过 |
| 数量达到上限 | 明确返回上限错误，不截断、不转货币 |
| 实例存在但定义未知 | 隔离只读，禁止装备/拆解/丢弃 |
| 装备表与所有权集合不一致 | 整槽只读恢复，不自动删孤儿 |
| 预留后崩溃 | 根据槽5收据恢复为提交或释放；未知时继续禁用相关数量 |
| 本地 UI 认为有物但修订已变 | 服务按期望修订拒绝，刷新视图 |
| 任务物品满背包 | 免容量；仍受 ownership cap，异常则阻止任务推进并报告配置错误 |
| 使用品目标已满血 | 不消耗，返回 `ITEM_NO_EFFECT` |
| 世界拾取提交失败 | 不销毁世界交互；可安全重试同一拾取收据 |

## 13. 数据生成与校验

必须校验：

- ID 前缀/重复、类别与 `max_stack/capacity_policy/discard_policy/use_rule` 的组合合法性。
- 装备物品与 `equipment_id` 一一映射；非装备不能被装备定义引用。
- 任务物品不可丢弃、不可出售且默认为免容量；兑换凭证不可直接使用，除非有明确兑换用例。
- 使用规则的效果类型、目标类型、上下文、效果引用全部在白名单；V1 任一 `COMBAT` 上下文或战斗物品桥接引用均生成失败。
- 装备库存保护字段只出现在 `lock_flags/favorite_flags` 所有权索引；发现 08 实例或其他系统复制可写锁定/收藏字段即生成失败。
- `ownership_cap >= max_stack`，默认容量/扩容总量在硬上限内，扩容 ID 不重复。
- 已下线物品不再被新掉落、商店、配方、任务奖励引用；旧任务仍需兼容壳时生成警告和反向引用报告。
- 任何奖励批次的最坏格数、首章关键任务物品免容量性、教学所需物品可获得性。

生成报告输出所有物品来源/消耗去向、堆叠与占用包络、不可丢弃清单、未使用物品和循环兑换风险。

## 15. 验收标准

- 所有物品变更只有一个权威入口；代码扫描和集成测试不存在其他系统直接改数量。
- 发放/消耗的槽4 change set 不产生半状态；战斗外使用的跨槽 Saga 在任意失败点可按同一子收据恢复，幂等重试不增不减第二次。
- 容量计算覆盖堆叠边界、穿戴装备、免容量任务物品和预留。
- 背包满不会吞战斗、任务或采集奖励；待领批次可保存重进并领取。
- 保存重进后数量、装备所有权、锁定、收藏、快捷栏和容量一致，旧档迁移幂等。
- 任务物品不可误删，高品级/锁定/穿戴装备受到明确保护。
- Y3 世界拾取表现失败或保存失败都可恢复，不产生重复拾取或永久消失。
- UI 全状态、配置生成、无引擎测试、Y3 冒烟和故障注入通过，P0/P1 为零。
