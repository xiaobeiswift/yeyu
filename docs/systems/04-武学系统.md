# 《雾州侠行》武学系统工程规格

> 状态：实施候选稿；仅描述未来实现，不代表代码已经存在。
>
> 上位约束：[00-通用工程约定](./00-通用工程约定.md)。角色构筑与战斗编队分别见 [01-角色与属性](./01-角色与属性.md)、[03-队伍与阵型](./03-队伍与阵型.md)。效果执行见 [05-状态与效果](./05-状态与效果.md)，跨槽提交见 [18-存档迁移与恢复](./18-存档迁移与恢复.md)，平台权益唯一对账编排见 [21-卡池商城与权益](./21-卡池商城与权益.md)，地图跳跃、踏水、选格和安全恢复见 [26-轻功探索与特殊通行](./26-轻功探索与特殊通行.md)。

## 1. 目标与非目标

### 1.1 目标

- 建立套路、内功、轻功三类武学及拳、剑、刀、枪棍四条套路路线。
- 支持武学获取、学习、十重升级、角色装备、主动招式、被动招式、聚气消耗、行动冷却和 AI 元数据。
- 武学配置只描述规则和效果引用；伤害、治疗、状态、位移等统一交给效果系统与战斗内核执行。
- 已学状态、装备状态和付费权益状态分离，保证权益重复回调、重复武学转化和存档迁移可幂等处理。
- 武学构筑可被战斗和擂台快照安全重建，禁止信任公开快照中的最终威力、冷却或面板属性。
- 由当前世界主角已装备轻功及其当前重数确定性派生 `LightnessTraversalProfile`，向 26 提供跳跃、长跃、踏水及探索选格范围参数。
- 轻功探索能力按武学重数解锁；已学但未装备的轻功、队伍中非主角伙伴的轻功以及公开擂台负载均不得叠加到世界通行能力。

### 1.2 非目标

- 不负责卡池随机、商城扣费、权益真实性、物品背包、货币消耗、战斗行动调度、特效动画或武学文本创作。
- 首章不实现玩家自制招式、招式自由拼装、实时动作连招、PVP 中途换武学或武学交易。
- 武学“品阶”只决定内容标签、升级曲线和展示，不直接隐式套数值倍率。
- Y3 技能对象的等级、冷却和法力值不作为权威状态。
- 不负责地图格、跳跃连接、水域、阻挡、高度、安全落点、可达集算法、选格会话或跳跃/踏水表现；这些由 12 提供空间事实并由 26 执行通行规则。
- V1 探索轻功不消耗体力、聚气、真气、货币或次数，不建立“轻功耐力”存档；战斗招式的聚气成本与探索通行完全分离。

## 2. 依赖与跨系统接口

### 2.1 上游依赖

| 系统 | 输入契约 |
|---|---|
| 角色系统 | 角色拥有、等级、武器倾向、标签和标准 `StatContribution` |
| 背包/经济 | 武学秘籍、升级材料、阅历/真气/门派贡献的查询及带子收据消费步骤；由 18 `SaveCoordinator` Saga 前向恢复 |
| 任务/门派 | 已验证解锁事实或学习许可 |
| 卡池/权益系统（21） | 内部 `VerifiedMartialEntitlementGrant` 与逐份子收据；不传平台总计数或游标 |
| 效果系统 | `effect_`、`status_`、声明式战斗钩子注册表 |
| 配置注册表 | 武学、招式、升级曲线、兼容规则和 AI 标签 |
| 03 队伍/世界主角身份 | 返回当前账号唯一的世界主角 `character_id`；阵型中的伙伴不能替代或叠加探索轻功 |
| 26 轻功探索 | 提供 `TraversalGuard` 和当前通行会话状态；武学变更不能根据 Y3 坐标自行判断是否安全 |

### 2.2 下游接口

| 消费方 | 输出 |
|---|---|
| 角色属性 | 已装备武学在当前等级的 canonical `StatContribution[]`，`source_type=MARTIAL` |
| 战斗系统 | `MartialLoadoutSnapshot`、`MoveRuntimeSpec[]`、被动钩子和 AI 提示 |
| 队伍/擂台 | 构筑合法性、武学来源修订和可公开最小 DTO |
| UI | 武学图鉴、已学状态、升级成本、装备冲突、招式解锁和来源信息 |
| 任务/成就 | `MartialLearned`、`MartialLevelChanged` 等已发生事实 |
| 26 轻功探索 | `LightnessTraversalProfilePort`：当前世界主角装备轻功派生的能力、范围参数、来源修订与规范化哈希 |

### 2.3 跨系统边界

- 学习/升级涉及槽 3 武学、槽 4 资源和槽 5 收据时，由 18 `SaveCoordinator` 编排可恢复 Saga；武学聚合只计算不可变 change set，不承诺跨槽回滚。
- 武学被动只输出标准属性贡献或效果钩子，不能直接修改角色、背包、任务或 Y3 单位。
- 21 独占平台权益计数访问与唯一 `PaidEntitlementCursor`；武学系统只保存已经由逐份子收据提交成功的副本/账户解锁及学习状态，不从平台计数自行计算差额。
- Saga 固定执行“全量预检 → 槽 5 `PREPARED` → 按步骤写 owner 槽并回读 → 槽 5 `COMMITTED` → 发布事件”。任一步结果未知即进入 `RECOVERY_REQUIRED`，沿原 `transaction_id/child_receipt_id` 补齐，禁止换新命令重扣资源。
- 04 是探索轻功能力的唯一来源：只读取槽 3 中“当前世界主角 + 当前已装备轻功 + 当前重数”，实时派生 Profile；26 不保存另一份已解锁能力、范围或轻功等级权威副本。
- 26 是特殊通行会话的唯一所有者。04 在更换当前轻功或升级当前已装备轻功前必须持有 `TraversalGuard` 变更令牌；04 不读取水域触发器、单位高度或动画状态来绕过该令牌。
- `LightnessTraversalProfile` 只为 26 的 `TraversalCell` 范围查询和可达算法提供能力上限；04 不生成格子、不判断某格可达，也不决定地图高亮。

## 4. 领域模型字段

### 4.1 `MartialBookEntry`

| 字段 | 类型 | 约束/含义 |
|---|---|---|
| `martial_id` | string | `martial_` 前缀、已注册 |
| `ownership_state` | enum | `OWNED/LEARNED`；秘籍到手但未选角色时可为 `OWNED` |
| `owner_character_id` | string/null | `LEARNED` 必填；首章学习后不可转移 |
| `level` | integer | `OWNED` 为 0；`LEARNED` 为 `1..10` |
| `mastery_points` | integer | `0..2^53-1`；首章可仅由升级资源直接推进，字段保留 |
| `source_type` | enum | `QUEST/FACTION/SHOP/DROP/EVENT/ENTITLEMENT/COMPENSATION` |
| `source_reference` | string | 已验证来源事实或权益收据 |
| `acquisition_receipt_id` | string | 首次获得幂等键 |
| `revision` | integer | 成功变化加一 |

同一 `martial_id` 是否允许多人学习由 `learn_policy` 决定。首章默认 `SINGLE_COPY_PER_CHARACTER`：同一武学可由多个角色学习，但每次需要独立副本/权益；存档聚合键为 `character_id + martial_id`，未分配副本另存数量。

### 4.2 `UnassignedMartialOwnership`

字段：`martial_id`、`available_copy_count`、`bound_copy_count`、`source_counters[]`、`revision`。免费秘籍、已提交的权益领域发放和补偿来源分别计数，学习时按配置优先消耗来源，避免把付费专属副本错误当作免费副本。这里的 `source_counters[]` 是武学副本来源账，不是平台权益镜像、总计数或对账游标。

### 4.3 `MartialLoadout`

| 字段 | 类型 | 约束 |
|---|---|---|
| `character_id` | string | 已拥有角色 |
| `routine_martial_id` | string/null | 普通战斗必须非空；匹配武器路线 |
| `internal_martial_id` | string/null | 可空，空时使用系统基础内功占位 |
| `lightness_martial_id` | string/null | 可空，空时使用系统基础身法占位 |
| `enabled_move_ids` | ordered set<string> | 仅已装备武学当前等级已解锁招式；首章默认全部自动启用，不提供自由禁用 |
| `ai_profile_id` | string | 角色战斗 AI 配置引用 |
| `revision` | integer | 负载修订 |

### 4.4 武学属性输出：canonical `StatContribution[]`

武学系统不定义第二套属性贡献 DTO，唯一跨系统输出是 01 §4.3 的 canonical `StatContribution[]`，八字段必须完整为 `source_type/source_id/target_stat/operation/value/priority/condition_tags/stable_order_key`。固定 `source_type=MARTIAL`，`source_id` 规范为 `martial_id:level:contribution_id`，`stable_order_key` 规范为 `MARTIAL:source_id:target_stat:operation`；空条件也必须输出 `condition_tags=[]`。内部等级行的定值、相加倍率和独立乘区分别适配为 `ADD_FLAT/ADD_BP/MULTIPLY_BP`。适配后按 `(priority, stable_order_key)` 排序并拒绝重复稳定键，禁止把内部 `stat_id/flat_value/rate_basis_points` 直接跨边界传出。未装备武学默认不贡献战斗属性；明确标记 `knowledge_passive=true` 的全局技艺不属于武学系统，应迁移到技艺系统。

### 4.5 `MoveRuntimeSpec`

| 字段 | 类型 | 说明 |
|---|---|---|
| `move_id` | string | `move_` 前缀 |
| `source_martial_id` | string | 当前装备武学之一 |
| `move_type` | enum | `BASIC/ACTIVE/PASSIVE/REACTION` |
| `unlock_level` | integer | `1..10` |
| `qi_cost` | integer | `0..2000` |
| `action_cooldown` | integer | `0..99`；以使用者完成行动次数计 |
| `initial_cooldown` | integer | `0..action_cooldown` |
| `target_rule_id` | string | 战斗目标规则 |
| `effect_bundle_id` | string | 效果系统入口 |
| `priority` | integer | 同时触发时的稳定优先级 |
| `ai_tags` | ordered set<string> | `DAMAGE/HEAL/CONTROL/FINISHER/SAVE_QI` 等 |
| `once_per_combat` | boolean | 若真，使用后永久禁用至战斗结束 |

### 4.6 `MartialLoadoutSnapshot`

字段：角色 ID、套路/内功/轻功 ID 与各自等级、招式 ID、有版本的 canonical 属性贡献引用、AI 配置 ID、武学修订、`rules_version` 和规范化哈希。不得包含当前聚气、冷却、状态或战斗计算后的最终伤害。

### 4.7 `LightnessTraversalProfile`

该 DTO 仅由 `LightnessTraversalProfilePort.get_for_world_protagonist` 返回，是派生读模型而非新聚合：

| 字段 | 类型 | 约束/含义 |
|---|---|---|
| `character_id` | string | 必须等于当前世界主角，不接受任意阵型成员 |
| `source_martial_id` | string/null | 当前负载中的轻功；空值只返回基础地面步行，不授予特殊通行能力 |
| `source_martial_level` | integer | `0..10`；空轻功为 0 |
| `source_loadout_revision` | integer | 查询时槽 3 负载修订，用于提交前发现换装 |
| `source_progress_revision` | integer | 对应已学武学行修订，用于发现升级 |
| `rules_version` | integer | 轻功探索规则版本 |
| `capability_specs` | ordered `TraversalCapabilitySpec[]` | 按 `JUMP_BASIC/JUMP_LONG/JUMP_HIGH/WATER_WALK` 固定顺序输出的当前等级完整有效能力集 |
| `range_query_radius_cells` | integer | 26 向 12 请求候选 `TraversalCell` 的最大格半径，不等于全部候选可达 |
| `presentation_profile_id` | string | 26 使用的动作/轨迹风格逻辑 ID，不含 Y3 Key |
| `profile_hash` | string | 仅对角色、轻功 ID/等级、能力参数、表现逻辑 ID 和规则版本规范化哈希；不包含查询时间或 Y3 状态 |

`TraversalCapabilitySpec` 的 canonical Schema 由 26 拥有，04 只从配置构建。首发能力固定为 `JUMP_BASIC/JUMP_LONG/JUMP_HIGH/WATER_WALK`，并按该顺序输出；`JUMP_LONG/JUMP_HIGH` 必须显式包含 `JUMP_BASIC` 形成依赖闭包，`WATER_WALK` 独立。每项至少含 `capability_id`、`rank`、`jump_range_cells`、`water_range_cells`、`max_rise_levels`、`max_drop_levels`、`max_route_cost` 与 `movement_speed_bp`：不适用的能力专属值为 0，但未解锁的能力整项不输出。跳跃能力必须 `water_range_cells=0`，并同时以 `jump_range_cells` 限制水平格距、以 `max_route_cost` 限制单段 Link cost；`WATER_WALK` 必须 `jump_range_cells=max_rise_levels=max_drop_levels=max_route_cost=0`，整段入水、踏水和离水只累计扣除 `water_range_cells`。厘米只能由 12 的格 anchor 用于表现。26 使用这些上限与 12 的格坐标、高度、表面、阻挡和连接事实计算可达集；Profile 本身不包含格 ID、世界坐标或可达结论。

### 4.8 `TraversalGuard` 端口

| 操作 | 输入 | 输出/规则 |
|---|---|---|
| `acquire_profile_mutation` | player、主角、`command_id`、预期 Profile 哈希、变化原因 | 仅 26 确认角色位于稳定地面且不存在选格/跳跃/踏水/落地/恢复会话时返回短期 `guard_token` 和会话修订 |
| `validate_token` | `guard_token`、`command_id` | SaveCoordinator 提交前再次确认；令牌与玩家、命令和预期 Profile 绑定 |
| `release_profile_mutation` | `guard_token`、提交结果 | 成功后使 26 重新查询 Profile；失败/恢复完成后释放，不改变任何地图位置 |

令牌只解决同一游戏实例内“开始通行”和“改变 Profile”的竞态，不写入永久存档。进程中断时令牌自然失效；重进先由 26 按 12 的 `last_safe_marker_id` 完成安全恢复，之后才允许新的武学变更。

## 5. 配置字段

### 5.1 `MartialDefinition`

| 字段 | 必填/默认 | 校验 |
|---|---|---|
| `id` | 必填 | `martial_` 前缀、全局唯一 |
| `schema_version/rules_version` | 必填 | `>=1`；结构版本与规则版本含义分离，发布后版本兼容 |
| `name_key/description_key` | 必填 | 本地化存在 |
| `category` | 必填 | `ROUTINE/INTERNAL/LIGHTNESS` |
| `weapon_path` | 条件必填 | 套路为 `UNARMED/SWORD/BLADE/STAFF`；其他类为 `NONE` |
| `rarity` | 必填 | `BASIC/REFINED/PROFOUND/MASTER`；只作曲线和展示标签 |
| `learn_policy` | 必填 | `SINGLE_COPY_PER_CHARACTER/ACCOUNT_UNLOCK`；首章优先前者 |
| `level_curve_id` | 必填 | 恰有 1–10 重记录 |
| `move_ids` | 必填非空 | 引用存在、至少一个可用招式或被动 |
| `compatibility_rule_id` | 必填 | 角色等级、标签、武器倾向和互斥条件 |
| `contribution_set_id` | 可空 | 标准角色贡献集合 |
| `lightness_traversal_profile_id` | 条件必填 | `LIGHTNESS` 必须引用 5.6；其他分类必须为空 |
| `acquisition_tags` | 默认空 | 免费、门派、权益等来源标签；不等于实际拥有 |
| `y3_visual_set_id` | 必填 | 仅资源逻辑 ID |
| `deprecated` | 默认 `false` | 已学者仍可加载和战斗 |

`weapon_path` 是 01 的 canonical 四路线，不是装备形态。空手与 `FIST_WEAPON` 都只解析为 `UNARMED`；拳套不得产生 `FIST` 第五路线，也不得同时匹配其他路线。剑、刀、枪棍装备形态分别解析为 `SWORD/BLADE/STAFF`，兼容检查只比较解析后的 canonical 值。

### 5.2 `MartialLevelRow`

| 字段 | 约束 |
|---|---|
| `martial_id/level` | 组合唯一；等级 `1..10` 连续 |
| `required_character_level` | `1..100`，不递减 |
| `cost_bundle_id` | 一级学习成本可与获取分离；2–10 重必填或明确免费 |
| `mastery_required` | `0..2^53-1`，不递减 |
| `unlocked_move_ids` | 只引用本武学招式，随等级只能增加 |
| `level_contribution_set_id` | 可空；当前重数生效值，不与前级重复累加，除非贡献明确标 `cumulative` |
| `tooltip_scalars` | 仅展示从效果配置生成的只读数据，不可手填成另一套规则 |

### 5.3 `MoveDefinition`

字段包括：`id`、`schema_version`、`source_martial_id`、`move_type`、`name_key`、`description_template_key`、`unlock_level`、`qi_cost`、`action_cooldown`、`initial_cooldown`、`target_rule_id`、`effect_bundle_id`、`trigger_type`（主动招式为空）、`trigger_priority`、`trigger_limit_per_action`、`once_per_combat`、`ai_tags[]`、`presentation_cue_id`、`deprecated`。

描述中的数值占位必须从效果和等级配置生成，不能独立维护手写数值。

### 5.4 `MartialCompatibilityRule`

字段：`id`、`minimum_character_level`、`required_character_tags[]`、`forbidden_character_tags[]`、`minimum_weapon_aptitude`、`exclusive_martial_ids[]`、`exclusive_groups[]`、`required_faction_id`（学习时）、`equip_faction_required`（默认 false）。退出门派后，已学武学默认仍可装备，除非设计明确且 UI 预先告知。

### 5.5 `MartialAIProfile`

AI 规则由战斗文档定义。武学配置只提供默认招式排序、功能标签、建议最低目标数、保留聚气阈值、保命生命阈值和目标标签，不执行决策脚本。

### 5.6 `LightnessTraversalProfileDefinition`

探索能力配置与战斗 `MoveDefinition` 分表，避免把战斗聚气/冷却错误用于地图：

| 字段 | 约束 |
|---|---|
| `profile_id` | `traversal_profile_*`，全局唯一 |
| `source_martial_id` | 恰好一门 `LIGHTNESS` 武学，且反向引用本 Profile |
| `rules_version` | `>=1`，与 26 支持版本一致 |
| `level_row_ids` | 恰有 1–10 重完整有效行，不采用运行时累加 |
| `default_presentation_profile_id` | 26 已注册的原创动作/轨迹风格 ID |
| `deprecated` | 弃用后已有存档通过显式替代映射重建；不可静默借用另一轻功参数 |

每个 `LightnessTraversalLevelRow` 字段为：`profile_id`、`level`、按 canonical 能力顺序排列的 `capability_specs[]`、`range_query_radius_cells`、可选 `presentation_profile_override_id`。当前等级行必须描述该重数的完整有效能力；例如某能力在六重解锁，则一至五重不得输出，六至十重必须保留且 rank/范围不得无说明倒退。

每项能力参数直接使用 26 的 canonical `TraversalCapabilitySpec`。规则距离为整数格，高低差为整数高度级，倍率为基点；`range_query_radius_cells` 必须不小于该行所有能力中 `max(jump_range_cells, water_range_cells)` 和任何合法路线可能到达的最远格半径，但它只是向 12 请求候选格的查询上界。配置禁止出现 `stamina_cost`、`qi_cost`、`currency_cost`、`daily_count` 或本地倒计时字段；探索轻功没有使用成本和每日次数。

## 6. 运行时状态与生命周期

### 6.1 永久生命周期

武学副本状态：`UNOWNED → OWNED_UNASSIGNED → LEARNED_LEVEL_1 → … → LEARNED_LEVEL_10`。已绑定学习后首章不可退回、遗忘或转移。21 每提交一个新的权益序号，武学系统才以对应子收据创建一份未分配副本；平台计数回退由 21 进入对账异常，武学系统不撤销已确认副本。

### 6.2 装备生命周期

负载变化采用草稿：`CLEAN → DIRTY → VALIDATING → SAVING → CLEAN`。角色每类最多一门。完整 `MartialLoadout` 替换在槽 3 的同一 section change 中一次提交；旧武学先卸下、新武学后装备只是差异展示，槽 3 不得落盘中间空档。若同时写槽 5 命令收据，外层仍是两步 Saga，不能称跨槽原子操作。

### 6.3 战斗运行态

战斗开始后由战斗系统为每个招式创建 `MoveRuntimeState`：剩余行动冷却、已使用次数、是否本战禁用。该状态不回写武学槽；聚气由战斗角色状态持有。

### 6.4 探索 Profile 生命周期

`LightnessTraversalProfile` 不存在永久生命周期。查询时按“当前世界主角 → 当前 `MartialLoadout.lightness_martial_id` → 对应 `MartialBookEntry.level` → 当前等级完整 Profile 行”重建；可在内存缓存，但缓存键必须至少包含 `character_id/source_martial_id/source_loadout_revision/source_progress_revision/rules_version`。

装备轻功或升级当前已装备轻功后废弃旧缓存并发布 Profile 变化事实。学习、获得或升级未装备轻功不会改变当前 Profile。跳跃、踏水、选格和落地状态由 26 持有，不回写 04；04 也不保存“正在使用轻功”标记。

## 7. 规则与状态机

### 7.1 获得与学习

- 获得只增加未分配副本或账户解锁，不自动选择学习角色。
- 学习前校验角色拥有、兼容规则、角色等级、未重复学习、可用副本和成本。
- `ACCOUNT_UNLOCK` 可供任意兼容角色学习而不消耗副本，但每个角色仍各有等级进度。
- 付费独占只影响获取来源；一旦合法获得，学习、升级、装备与免费武学走相同领域规则。

### 7.2 十重升级

目标等级必须等于当前等级加一；批量升级由应用层依序计划为一个不可变 change set，成本为各级成本之和。任一级条件不满足时在 `PREPARED` 前失败且不扣资源；进入应用阶段后按槽 4 成本子收据、槽 3 最终等级步骤前向补齐，禁止用逆向回滚伪装跨槽原子。等级不能跳过、降级或超过 10。

### 7.3 装备兼容

- 套路必须匹配当前 canonical 武器路线；空手或拳套 `FIST_WEAPON` 都只匹配 `UNARMED`，不存在 `FIST` 路线。角色不得同时装备会解析为冲突路线的武器。
- 内功、轻功只受其兼容规则约束。
- 构建普通战斗快照时若套路为空，使用 `martial_system_basic_routine` 只作为开发/恢复兼容项；正式可操作角色必须在新手流程中学习合法基础套路，否则开战返回 `MARTIAL_ROUTINE_REQUIRED`。
- 同一武学若配置禁止和另一武学共存，负载整体非法，不自动卸下。

### 7.4 招式解锁和可用性

招式必须同时满足：来源武学已装备、当前重数达到解锁重数、战斗者存活可行动、目标合法、聚气足够、冷却为 0、未超过次数限制、未被状态封锁。主动失败不能先扣聚气或进入冷却。

成功使用的提交顺序固定为：锁定规范化目标 → 扣聚气 → 标记次数/冷却 → 执行效果包 → 结算触发 → 产出事件。效果包即使最终未造成伤害，只要成功施放也消耗聚气和冷却；若施放前目标全部失效则命令拒绝、不消耗。

### 7.5 被动和反应招式

- 触发点只能使用效果系统注册枚举，例如 `COMBAT_STARTED/BEFORE_DAMAGE/AFTER_DAMAGE/HP_THRESHOLD/ACTION_FINISHED`。
- 同触发点按 `trigger_priority, source_martial_id, move_id, owner_actor_id` 排序。
- 每个招式必须配置单行动触发上限；默认 1，最大 99。递归深度和事件预算由效果/战斗系统统一限制。
- 被动不能直接发永久奖励、改变武学等级或写存档。

### 7.6 武学属性贡献

只应用三门已装备武学当前等级的贡献。每个等级行给出该等级的完整有效贡献集，而非默认把 1–当前等级行全部相加；需累加的贡献必须显式声明。最终交给角色系统统一排序与取整。

### 7.7 探索轻功能力派生

1. 解析账号当前世界主角；调用方传入的其他角色 ID 一律返回 `MARTIAL_TRAVERSAL_PROTAGONIST_REQUIRED`，不在队伍四人之间择优。
2. 读取主角完整武学负载与对应已学进度，确认轻功分类、所有权、等级和引用完整。
3. 选择当前等级的完整 `LightnessTraversalLevelRow`，把能力项按 `capability_id` 排序、验证整数范围后构建 Profile。
4. 使用 canonical 序列化生成 `profile_hash`；相同槽 3 事实与 `rules_version` 必须得到相同结果。
5. 26 用 `range_query_radius_cells` 向 12 请求候选探索格，再结合跳跃/踏水格数、高度级和 route cost 计算可达集；04 不接收或缓存候选格，也不参与地面高亮。

已学未装备、伙伴装备、阵型位置、好感、战斗聚气和 Y3 单位当前法力均不进入派生。Profile 的能力不会因连续跳跃、踏水时长、现实日期或本地帧率衰减；V1 没有探索体力、使用次数或冷却。

### 7.8 通行中的 Profile 变更保护

- 更换主角 `lightness_martial_id`，或升级主角当前已装备轻功前，应用层必须向 26 获取 `TraversalGuard` 令牌。升级未装备轻功和不改变轻功 ID 的套路/内功换装不需要该令牌，也不得误打断通行。
- 26 在 `SELECTING/PREPARING/IN_FLIGHT/WATERBORNE/LANDING/RECOVERING` 等任何非稳定地面状态拒绝令牌，04 返回 `MARTIAL_TRAVERSAL_ACTIVE`；玩家必须先由 26 取消安全的选格会话或完成/恢复通行。
- `acquire → validate → 槽提交 → release` 期间，26 禁止同一玩家开始新通行，消除“校验在岸上、提交时已入水”的竞态。Guard 不代表存档事务成功，仍需遵循 18 的 Saga/修订规则。
- 槽提交成功后 04 发布 `LightnessTraversalProfileChanged`，26 丢弃旧可达集和旧选格 token；提交失败则保留旧 Profile。保存结果未知时 Guard 保持逻辑锁至原事务恢复到确定终态。
- 04 不提供强制卸下或紧急降级绕过。若配置迁移使当前轻功失效，先由 26/12 将玩家恢复至 `last_safe_marker_id`，再进入只读构筑修复。

## 8. 应用用例

### 8.1 `GetMartialBook`

输入玩家、可选角色和筛选。前置为槽 3 武学数据读取成功；只读允许。输出已经提交到领域档的图鉴、未分配副本、各角色已学等级、负载、合法性和来源提示。尚未由 21 对账完成的平台差额不是武学可用副本，可由 21 的独立状态投影提示。配置断链返回局部错误列表，禁止 UI 猜测数值。

### 8.2 `GrantMartialOwnership`

| 项 | 契约 |
|---|---|
| 输入 | 武学 ID、数量、来源类型/引用、收据 ID、预期修订 |
| 前置 | 来源已验证；数量 `1..9999`；武学可获取 |
| 事务 | 生成 change set → 槽 5 写 `PREPARED` → 槽 3 增加来源计数/账户解锁并回读 → 槽 5 `COMMITTED` → 发布事件；未知结果按原 transaction/子收据前向恢复 |
| 输出 | 前后数量、账户解锁状态、修订 |
| 错误 | `MARTIAL_SOURCE_UNVERIFIED`、`MARTIAL_DEPRECATED`、`SAVE_REVISION_CONFLICT` |
| 幂等 | 同收据不重复增加；不同载荷复用收据报错 |

### 8.3 `LearnMartial`

| 项 | 契约 |
|---|---|
| 输入 | 角色 ID、武学 ID、指定副本来源、成本确认、幂等键、武学/背包/货币预期修订 |
| 前置 | 角色兼容且未学；副本/账户解锁有效；一级条件与成本满足 |
| 事务 | 全量预演 → 槽 5 `PREPARED` → 槽 4 按成本子收据消费并回读 → 槽 3 在一个 section 步骤中消费副本并创建一级进度 → 槽 5 `COMMITTED`；部分成功只向前补齐 |
| 输出 | 学习状态、剩余副本、解锁招式、修订 |
| 错误 | `MARTIAL_ALREADY_LEARNED`、`MARTIAL_INCOMPATIBLE`、`MARTIAL_COPY_INSUFFICIENT`、`COST_INSUFFICIENT`、`SAVE_REVISION_CONFLICT` |
| 幂等 | 超时后按收据恢复；不得重复扣秘籍/资源 |

### 8.4 `UpgradeMartial`

输入角色、武学、目标等级（当前+1或批量最终级）、幂等键和跨槽预期修订。事务先生成完整成本计划；若目标是主角当前装备轻功，先计算升级前后 Profile，发生任何能力/范围/表现变化时获取并复验 `TraversalGuard`。随后由 18 Saga 执行“槽 5 `PREPARED` → 槽 4 成本子收据 → 槽 3 最终等级 section 步骤 → 槽 5 `COMMITTED`”；结果未知时沿原步骤恢复，不再次扣资源，并在确定终态前保持 Guard 逻辑锁。输出逐级解锁、贡献变化、探索能力变化和剩余资源。错误包括 `MARTIAL_LEVEL_MAX`、`MARTIAL_LEVEL_SEQUENCE_INVALID`、`CHARACTER_LEVEL_TOO_LOW`、`MASTERY_INSUFFICIENT`、`COST_INSUFFICIENT`、`MARTIAL_TRAVERSAL_ACTIVE`、`TRAVERSAL_GUARD_UNAVAILABLE`。同一收据只升级一次。

### 8.5 `CommitMartialLoadout`

| 项 | 契约 |
|---|---|
| 输入 | 角色 ID、完整套路/内功/轻功目标、AI 配置、预期负载修订、幂等键 |
| 前置 | 三门武学均已由该角色学习；兼容与互斥规则满足；非战斗锁定态；若主角轻功 ID 改变，26 已授予并锁定有效 `TraversalGuard` |
| 事务 | 规范化/全量校验 → 必要时获取/复验 Guard → 槽 5 `PREPARED` → 在槽 3 对完整负载执行一次 section 提交并回读 → 槽 5 `COMMITTED` → 发布负载/Profile 变化 → 释放 Guard |
| 输出 | 新负载、贡献摘要、构筑失效修订；若 Profile 改变则返回新 Profile 哈希和探索能力差异 |
| 错误 | `MARTIAL_NOT_LEARNED`、`MARTIAL_CATEGORY_MISMATCH`、`MARTIAL_LOADOUT_CONFLICT`、`CHARACTER_WEAPON_MISMATCH`、`MARTIAL_TRAVERSAL_ACTIVE`、`TRAVERSAL_GUARD_UNAVAILABLE`、`SAVE_READ_ONLY` |
| 幂等 | 相同目标/键返回原结果；不同目标复用键拒绝 |

### 8.6 `GrantMartialFromEntitlement`

只接受 21 内部端口提交的 `VerifiedMartialEntitlementGrant`，字段为 `entitlement_id`、`entitlement_ordinal`、`mapped_martial_id`、`mapping_version`、`child_receipt_id`、`reconciliation_id`。`child_receipt_id` 必须按 `entitlement_grant:{entitlement_id}:{entitlement_ordinal}` 稳定派生。前置为发布映射一致、武学可获得且子收据未被不同载荷使用；事务委托 `GrantMartialOwnership` 以 `source_type=ENTITLEMENT` 增加一份副本或确认账户解锁。输出领域发放结果、前后数量与修订。错误包括 `ENTITLEMENT_GRANT_UNVERIFIED`、`ENTITLEMENT_MAPPING_MISMATCH`、`IDEMPOTENCY_KEY_REUSED`、`SAVE_READ_ONLY`。本用例不接收平台计数/修订/游标，不读取槽 `200–299`，也不处理计数回退；21 在所有序号的子收据确认后推进唯一 `PaidEntitlementCursor` 并发布 `EntitlementReconciled`。

### 8.7 `BuildMartialLoadoutSnapshot`

输入角色 ID、武学修订、`rules_version` 和战斗上下文。无写事务。全量校验并输出规范化快照、招式运行规格、canonical `StatContribution[]`、钩子和哈希。任何公开输入中的未知 ID、越界等级、未拥有副本、贡献八字段不完整/稳定键重复、伪造效果或 `rules_version` 不兼容均拒绝。

### 8.8 `GetLightnessTraversalProfile`

| 项 | 契约 |
|---|---|
| 输入 | `player_id`、当前世界主角 ID、可选 `expected_loadout_revision/expected_progress_revision` |
| 前置 | 角色身份由 03 验证；槽 3 可读；配置版本受支持 |
| 事务 | 纯读取与确定性派生，不写槽、不创建收据、不消耗任何资源 |
| 输出 | 4.7 的完整 Profile；若未装备轻功则返回空能力基础 Profile，而不是借用已学武学 |
| 错误 | `MARTIAL_TRAVERSAL_PROTAGONIST_REQUIRED`、`MARTIAL_TRAVERSAL_PROFILE_BROKEN`、`MARTIAL_SOURCE_REVISION_STALE`、`SAVE_UNAVAILABLE` |
| 缓存 | 只允许按来源修订和规则版本缓存；`MartialLoadoutChanged/MartialLevelChanged` 后失效 |

26 在打开选格、重新计算可达集和确认目标三个时点都必须以来源修订检查 Profile。确认时发现 Profile 哈希或来源修订变化，旧选择 token 失效并重新查询；不能沿用旧高亮结果。

## 9. 领域事件

| 事件 | 关键载荷 |
|---|---|
| `MartialOwnershipGranted` | 武学 ID、数量、来源、收据 |
| `MartialLearned` | 角色 ID、武学 ID、来源副本、一级招式 |
| `MartialLevelChanged` | 角色/武学 ID、旧/新等级、解锁招式、成本收据 |
| `MartialLoadoutChanged` | 角色 ID、旧/新负载哈希、分类差异 |
| `MartialBuildInvalidated` | 角色 ID、原因和来源修订；应用内事件 |
| `LightnessTraversalProfileChanged` | player/主角 ID、旧/新轻功 ID 与等级、旧/新 Profile 哈希、来源修订、原因、收据 |

权益来源沿用 `MartialOwnershipGranted`，载荷中的来源与子收据足以审计；武学系统不得发布带旧/新平台游标的“已对账”事件，最终 `EntitlementReconciled` 只由 21 在编排完成后发布。战斗中的 `MoveUsed/MoveRejected/MoveCooldownChanged` 属于战斗事件流，不持久化为武学永久事件。`LightnessTraversalProfileChanged` 只在当前世界主角的有效 Profile 真正改变并完成提交后发布；未装备武学升级、查询缓存重建或 Y3 表现切换不得伪造该事实。

## 10. 存档 DTO、槽位与迁移

### 10.1 槽位

- 槽 `3`：武学副本、角色学习进度和负载。
- 槽 `5`：获得、学习、升级、装备和权益领域发放子收据。
- 槽 `200–299`：由 21 独占读写与对账；武学系统既不读取也不写入。
- 槽 `100`：擂台公开最小负载快照，由擂台系统复制。

### 10.2 扁平 DTO

| 数组 | 行字段 |
|---|---|
| `martial_ownership_rows` | `martial_id/source_type/available_count/bound_count/last_receipt_revision` |
| `martial_progress_rows` | `character_id/martial_id/level/mastery_points/source_type/source_reference/acquisition_receipt_id/revision` |
| `martial_loadout_rows` | `character_id/routine_id/internal_id/lightness_id/ai_profile_id/revision` |
| `martial_move_rows` | 仅在未来允许禁用招式时使用；首章不保存，可从等级重建 |

槽子表带 `schema_version/revision`，写出按武学 ID、角色 ID 排序。不得保存效果定义、最终贡献、冷却、聚气、`LightnessTraversalProfile`、已解锁探索能力、范围、Guard token、通行状态、`last_observed_platform_count`、`delivery_cursor` 或 Y3 技能 Key。探索 Profile 必须从 `martial_progress_rows + martial_loadout_rows + 配置规则版本` 重建。

### 10.3 迁移

- 武学等级曲线变更不改变已保存等级，只按新规则版本重建贡献；若需要赛季冻结则由快照版本控制。
- 招式被弃用时已有武学可加载，但快照必须通过兼容替代映射；无映射则构筑不可开战，不静默删除。
- 从账户解锁/副本策略互转必须有逐来源计数迁移，禁止凭“已学”反推付费副本数。
- 旧存档中的最终技能威力、冷却或 Y3 Key 一律丢弃并记录诊断。
- 未知武学行进入隔离只读，保留原数据等待内容修复。
- 若旧候选 DTO 曾保存 `entitlement_cursor_rows`，必须先由 21 以迁移收据接管并回读确认；武学新 Schema 不读取该行，未确认接管时保留隔离原文而不是自行推进游标。
- 若旧候选版本保存过探索能力、体力、跳跃次数或水上剩余时间，这些字段一律丢弃；迁移后按当前装备轻功和等级重新派生。若无法派生，通知 26 先按 12 的最后安全 marker 恢复并锁定特殊通行入口，不猜测旧能力。

## 11. Y3 适配与 UI

### 11.1 Y3 适配

- `MartialVisualMapping` 把逻辑招式 ID 映射到 Y3 动画、特效、音效、弹道和图标；数字物编 Key 仅存在映射目录。
- Y3 技能可作为输入/表现壳，但施放许可、聚气、冷却、目标和结果由战斗域决定。
- 适配器收到 `MoveUsed` 后按表现 cue 播放；资源缺失可使用安全占位并记录错误，不重新执行效果。
- 云档适配器只转换槽 3/5 扁平 DTO，不读取或转换平台权益计数。21 通过内部应用端口提交已映射的逐份领域发放命令。
- 04 不创建地图跳跃 Y3 技能、不移动世界单位、不绘制格子。它只把 `presentation_profile_id` 和 Profile DTO 交给 26；动画、轨迹、格子高亮缺失不能改变能力判定。

### 11.2 UI

- 武学页按套路/内功/轻功和四路线筛选，显示未获得、可学习、已学、已装备、已满重和弃用兼容状态。
- 详情展示十重节点、每重成本、解锁招式、生成式准确数值描述、适配角色和获取来源。
- 轻功详情同时展示每重解锁的探索能力、跳跃/踏水格数和高低差上限，并明确“仅当前主角装备后生效、探索无体力消耗”；数值必须从 5.6 生成。
- 学习/升级/装备使用确认页，显示实际将消耗的资源与变更；提交中防重入，成功后以返回 DTO 刷新。
- 冲突时明确列出武器不匹配、分类占用、互斥武学、角色等级、秘籍不足等原因。
- 通行中尝试换轻功或升级当前轻功时显示 26 返回的稳定原因，例如“请先落地”或“请先离开水面”，不能自动把玩家传回岸边后偷偷提交。
- 只读可浏览和试配，不能学习/升级/保存；配置断链不显示猜测数值。

## 12. 边界、失败与恢复

- 学习成本步骤成功但进度步骤失败/未知：标记 `RECOVERY_REQUIRED`，通过同一 transaction 与子收据向前补齐进度；除显式配置且幂等的补偿步骤外，不逆向补回后换新命令重做。
- 批量升级任一条件在预检阶段失败时不创建应用步骤；保存部分成功则按原收据恢复到不可变计划的最终等级，不能把已确认槽步骤整体回滚。
- 装备后武器被换成不兼容类型：装备系统提交前应校验；若旧版本/迁移造成，构筑标记非法并要求修复。
- 收到伪造权益领域命令、映射版本不符或子收据载荷冲突时稳定拒绝；平台计数回退由 21 处理，不得触发武学副本删除或自动补偿。
- `deprecated` 武学可由已有角色继续使用，但不得新学习/获得；正式平衡若禁用须通过显式赛季/版本规则，而非删配置。
- 效果包执行异常属于战斗失败，不回滚永久武学等级；战斗结算不得保存运行时冷却。
- 配置描述数值与效果数值不一致时生成失败，禁止只修 UI 文案。
- `TraversalGuard` 不可用或状态未知时，当前轻功换装/升级稳定拒绝；不得假定单位模型看似在地面就安全。
- Profile 提交后 26 尚持有旧选择 token：旧 token 必须按 Profile 哈希/来源修订拒绝并重新显示范围，不能跳到旧目标格。
- 热更/迁移删除当前轻功 Profile：停止新的特殊通行；若玩家会话可能位于水上或空中，先由 26 请求 12 安全恢复，再允许构筑修复。04 不写世界位置。
- 武学槽写入未知时保留 Guard 逻辑锁并沿原事务恢复；确定旧/新 Profile 后才释放，避免通行按不确定能力开始。

## 13. 生成与静态校验

必须拒绝：重复 ID、分类/canonical 武器路线不匹配、`FIST` 第五路线、`FIST_WEAPON` 非 `UNARMED` 映射、等级缺行或不连续、解锁招式倒退、成本断链、招式归属错误、目标/效果断链、非 canonical 属性贡献、非法聚气/冷却、被动无触发上限、互斥规则自冲突、学习路径不可达、权益映射多义、描述占位无法解析、Y3 资源映射缺失，以及轻功 Profile 缺失/反向引用不唯一、1–10 重行缺失、未知能力、能力依赖不闭合、范围或高低差越界、解锁后无说明消失/倒退、查询半径小于能力上界、探索成本/次数/体力字段、26 表现 Profile 断链。

生成报告至少包含：12 门首章武学三类/四路线覆盖、1–10 重招式和贡献差异、各角色可学习矩阵、聚气成本分布、同类武学升级总成本、所有被动触发链及最大理论触发数、付费独占武学的确定性兑换路径，以及每门轻功 1–10 重探索能力/格数/高低差矩阵、首章每类特殊通行要求可由哪条可获得轻功路径满足。

## 14. 测试矩阵

| 类别 | 用例 | 通过条件 |
|---|---|---|
| 获得 | 免费/任务/权益、数量、重复收据、已弃用 | 计数准确且不重复 |
| 学习 | 兼容/不兼容、秘籍不足、账户解锁、每个 Saga 步骤故障 | 子收据不重扣，最终前向收敛 |
| 十重 | 单级、批量、缺成本、满重、跨等级门槛 | 不跳级、不部分扣费 |
| 负载 | 三分类、武器冲突、互斥、槽 3 完整负载一次提交 | 槽 3 无中间非法态；槽 5 收据可恢复 |
| 招式 | 解锁、聚气、冷却、次数、目标失效 | 使用许可与消耗顺序精确 |
| 被动 | 同优先级、递归、单行动上限 | 顺序稳定，预算生效 |
| 快照 | 输入乱序、伪造等级/效果、旧版本 | 哈希稳定，非法拒绝 |

## 15. 验收标准

- 首章至少 12 门武学覆盖套路四路线、内功和轻功，且生成器证明每门均有合法获得/学习路径。
- 任一角色只能装备一门套路、一门内功、一门轻功；所有冲突给出稳定原因。
- 1–10 重升级、跨槽 Saga、重复子收据和每个步骤的保存故障测试不丢资源、不重复升级且最终前向收敛。
- 相同负载来源和规则版本生成相同快照与招式列表；公开档伪造数值无法进入战斗。
- 聚气、冷却和次数完全由战斗运行态维护，存档不含这些字段。
- 武学 UI 的数值描述由权威配置生成，与实际效果黄金测试一致。
- 领域层不引用 Y3、系统时间或客户端随机；付费来源只接受 21 内部逐份子收据，武学模块无平台游标。
- 当前主角装备轻功的每一重都能派生唯一 `LightnessTraversalProfile`；已学未装备和伙伴轻功绝不改变地图能力或可达格显示。
- 探索能力按等级边界准确解锁，能力集合满足 `JUMP_BASIC/JUMP_LONG/JUMP_HIGH/WATER_WALK` 的 canonical 依赖；同一来源与规则版本产生相同 Profile 哈希。
- 跳跃、踏水和选格不消耗任何探索体力、聚气、货币或次数；存档中不存在 Profile/范围/水上剩余值的第二权威副本。
- 选格、起跳、空中、水上、落地和恢复期间无法更换当前轻功或升级当前已装备轻功；稳定落地后无需重启即可换装，并使旧选格 token 失效。

## 16. 实施任务拆分

1. 冻结分类、路线、品阶、学习策略、招式类型、触发点和错误码。
2. 建立武学/等级/招式/兼容/AI/探索 Profile Schema 与覆盖、能力闭包和断链校验器。
3. 实现武学副本、学习进度、十重规则、负载聚合及主角探索 Profile 纯派生器。
4. 定义效果、canonical 角色贡献、背包成本、21 权益领域发放、战斗快照和 26 `LightnessTraversalProfilePort/TraversalGuard` 契约及 Fake。
5. 实现招式解锁、使用许可规格、被动钩子、探索等级能力与两类规范化哈希。
6. 实现八个应用用例、18 `SaveCoordinator` Saga、Guard 临界区、派生子收据及部分成功前向恢复。
7. 实现不含权益游标/Profile/通行状态的槽 3/5 DTO、旧游标接管迁移与 Fake 领域发放端口。
8. 完成升级、互斥、确定性、恶意快照、探索 Profile、无体力、Guard 竞态和故障注入测试。

## 17. 待决项

- 同一武学采用“每角色消耗副本”还是“账户获得后全角色可学”；当前两种均有契约，首章默认前者。
- 熟练度是否参与升级；当前字段保留，但首章可仅使用资源与角色等级。
- 未装备武学是否提供知识型被动；当前不提供，应由独立技艺系统承接。
- 内功/轻功是否各自拥有主动绝招；架构允许，内容需在招式表明确。
- 玩家是否能禁用某些自动被动/主动招式；首章默认已解锁全部启用。
- 武器切换与套路切换是否允许一次复合提交；若允许，由构筑应用服务经 18 `SaveCoordinator` 执行槽 5 `PREPARED`、槽 4 装备子步骤、槽 3 武学负载子步骤和 `COMMITTED` 的前向恢复 Saga。不得承诺跨装备/武学原子回滚；恢复期间锁定继续编辑，避免玩家观察/提交新的中间冲突。
- 各轻功的探索能力具体在第几重解锁及格数成长曲线；接口已冻结为每重完整 Profile，内容表再决定数值，不得引入探索体力弥补平衡。
