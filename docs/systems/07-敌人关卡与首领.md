# 《雾州侠行》敌人、关卡与首领系统工程规格

> 状态：实施候选稿；仅描述未来实现，不代表代码已经存在。离线结算已支持可选 `first_clear_loot_table_id` / `repeat_loot_table_id`（优先于 reward bundle，走 `prepare_loot`）。
>
> 上位约束：[00-通用工程约定](./00-通用工程约定.md)。战斗输入与结果遵循 [06-确定性战斗与AI](./06-确定性战斗与AI.md)，机制效果遵循 [05-状态与效果](./05-状态与效果.md)。

## 1. 目标与非目标

### 1.1 目标

- 用统一 `Encounter` 配置表达普通怪、精英、首领、波次战、条件战、剧情战和可重复副本。
- 以稳定敌人 ID、等级/构筑配置、阵位、AI 和掉落引用构建可复算的防守方战斗快照。
- 支持首领阶段切换、蓄力与打断、召唤、环境机制、一次跨多阈值伤害和明确的触发顺序。
- 明确进入、开战、波次推进、胜负、重试、结算、首通和重复奖励的幂等事务。
- 同一关卡配置版本、玩家阵容快照和种子产生一致的敌人构筑、机制事件和战斗结果。

### 1.2 非目标

- 不负责地图美术制作、实时动作碰撞、战斗数值最终公式、任务文本、奖励包内部发放或 Y3 单位 AI。
- 首章不实现开放世界无缝刷怪生态、动态难度追踪玩家消费、多人副本、随机生成大地图或实时副本匹配。
- 敌人 Y3 物编属性、地图摆放单位当前生命和客户端触发器不作为权威关卡状态。
- 战斗内的临时敌人/首领状态不进入普通云存档；首发不支持中途续战。

## 2. 依赖与跨系统接口

### 2.1 上游依赖

| 系统 | 输入契约 |
|---|---|
| 世界/探索 | 已保存的地点、交互对象、遭遇触发事实和玩家安全点 |
| 任务/对话 | 进入条件、剧情分支、已提交选择；关卡不直接推进任务状态 |
| 队伍 | `FormationCombatInput` 和 `PartyConstraintSet` 校验结果 |
| 角色/武学/效果 | 敌人属性构建器、招式规格、状态/效果/机制引用 |
| 战斗 | `StartCombatSession`、波次/召唤/阶段端口和 `CombatResult` |
| 奖励/背包 | 奖励包、入场成本和结算收据 |
| `TrustedPeriodPort`（由 17 周期系统提供） | 可重复内容的可信 `period_id` 与 LIVE/CACHED/UNAVAILABLE 状态；关卡不直接调用 `ClockService`，故事关卡不依赖周期 |
| 配置注册表 | 敌人、构筑、Encounter、波次、首领、机制和掉落配置 |

### 2.2 下游输出

| 消费方 | 输出 |
|---|---|
| 战斗系统 | 规范化防守方快照、波次计划、首领阶段/环境机制规格 |
| 奖励系统 | 已验证 `EncounterResult`、首通/重复奖励引用和结算收据 |
| 任务/成就 | `EncounterCompleted`、特定首领/条件结果等完成事实 |
| 世界系统 | 清除路障、宝箱可开、NPC/传送变化等明确世界结果意图 |
| UI/表现 | 入场预览、波次、首领血条/阶段、机制提示和结算摘要 |
| 日常/副本 | 完成次数、17 提供的可信 `period_id` 和切换后的可进入状态 |

### 2.3 权威边界

- 关卡系统只接受战斗内核签名/哈希核对后的结果；UI 的胜利面板、Y3 单位死亡或动画事件不能结算。
- 关卡奖励由统一奖励事务发放；敌人定义中的掉落引用不直接修改背包。
- 世界变化通过结算用例向世界系统的唯一 owner port 提交；任务系统不由关卡直接改写，只消费结算提交后发布的 `EncounterCompleted` 完成事实。
- 周期计算、日切和可信时间降级全部归 17 的 `TrustedPeriodPort`；关卡只保存已经确认的 `period_id` 和来源修订，不自行读取 `ClockService` 或本地日期。

## 5. 配置与内容规则

### 5.1 敌人构筑

- 故事/普通/首领 Encounter 使用配置固定等级，禁止按玩家当前战力隐式缩放。
- 可重复副本若需要难度档，只能通过显式 `difficulty_tier_id` 选择已发布等级与倍率；玩家在入场预览可见。
- `rank_multiplier_set` 按属性键给倍率基点，固定顺序进入角色属性流水线，不能用 Y3 物编值二次放大。
- 敌人招式必须有至少一个合法基础行动；AI 无绝招可用时仍能普攻或明确跳过。

### 5.2 波次

- 任一时刻同侧最多 4 名可行动单位；召唤只能占空位或按机制替换，不允许静默超过上限。
- 波次清空判定只统计 `counts_for_victory=true` 的单位。装饰/机制物不阻塞清波。
- 前波最后效果任务、倒地触发和阶段信号全部排空后再判清波。
- 下一波进入顺序：发布清波 → 执行清波效果 → 执行间波策略 → 创建下一波单位 → 执行入场效果 → 发布波次开始 → 检查条件。
- 新波次继承攻方生命、状态、聚气和冷却，除非间波策略显式修改；不得重建攻方永久构筑。

### 5.3 首领阶段

阶段检查只在效果队列排空的安全边界进行。若一次伤害跨越多个 HP 阈值：

1. 只进入当前阶段的下一阶段。
2. 提交阶段标记和招式/AI/免疫变化。
3. 执行该阶段入场效果并排空队列。
4. 重新读取首领当前生命和条件；若仍满足再进入下一阶段。

阶段一旦进入不因治疗回退。若阶段效果令首领死亡，先处理死亡/胜负，不再进入后续阶段。每阶段每战只能进入一次。

### 5.4 蓄力与打断

- 蓄力由一个可见 `CASTING` 状态和待执行机制标记组成，声明预计在来源第 N 次行动时释放的效果包。
- 只有带配置 `interrupt_signal_tag` 的成功效果可增加打断进度；普通控制免疫不等于打断免疫。
- 进度达到阈值时按同一事件链取消待执行效果、移除蓄力状态并发布 `BossCastInterrupted`。
- 首领倒地、阶段切换或目标失效时的取消策略必须配置；默认倒地取消、阶段切换取消、目标失效按目标规则重选。
- UI 动画、点击时机和本地秒数不参与打断窗口。

### 5.5 召唤

- 召唤请求声明敌人 ID、等级/构筑变体、首选阵位、回退阵位顺序、每次数量、每战上限、存活上限和是否计入胜负。
- 阵位按配置回退顺序选择，第一个合法空位胜出；无空位返回明确拒绝，不替换现存单位，除非操作为单独的 `REPLACE_SUMMON`。
- 召唤 actor ID 由 `run_id + summon_sequence` 确定，不用随机 UUID。
- 召唤单位默认无独立掉落；需要奖励时由 Encounter 结算条件统一计算，防止反复召唤刷取。

### 5.6 条件战与判定优先级

每个安全边界固定判定：

1. 规则错误/预算超限。
2. 进攻方全灭或显式失败条件。
3. 双方同时全灭（进攻方失败）。
4. 当前波/全部防守方清空及显式胜利条件。
5. 阶段/波次/机制推进。
6. 第 99 个行动机会完整结算后仍无胜负，则超时并判进攻方失败。

配置不得让同一事实同时成为互相矛盾的胜负条件；生成器能证明冲突时拒绝。保护目标倒地与最后敌人同时倒地仍按失败条件优先。

### 5.7 奖励

- `first_clear_reward_bundle_id` 只在该 Encounter 首次合法胜利结算，收据 `encounter_first_clear:{encounter_id}`。
- 重复奖励按 `run_id` 收据发放；召唤/波次内部不直接掉落到背包。
- 若希望显示逐敌掉落，结算器必须从 run 根种子以固定命名空间派生独立 `reward_seed`，在战斗后计算并记录结果与收据。奖励随机流与战斗内核 PRNG 完全隔离，奖励抽取次数不得改变 `CombatEvent`；付费相关结果不得走此路径。
- 战败、放弃、超时和规则错误的奖励策略分别配置；默认只有正常胜利发放主奖励。

## 6. 运行时状态机

### 6.1 `EncounterRun` 状态

`AVAILABLE → PREPARING → ENTRY_COMMITTED → COMBAT_ACTIVE → RESULT_PENDING → SETTLING → COMPLETED`

从 `COMBAT_ACTIVE` 可到 `ABANDONED/FAILED/INVALID`; `FAILED/ABANDONED` 可按重试策略回到 `PREPARING`，但创建新战斗会话和新重试子收据。`COMPLETED` 为本次 run 终态。

### 6.2 战斗内关卡控制态

字段：当前波次、已清波次集合、已进入首领阶段集合、召唤计数、打断计数、机制标记、受保护 actor 状态、条件判定修订。它是战斗快照/运行态的一部分，不写普通存档。

### 6.3 进入锁定

点击进入只创建预览；确认后应用层用启动收据锁定入场成本、周期次数、队伍来源修订和种子，再进入 `ENTRY_COMMITTED`。保存/平台状态未知时不得同时创建第二个 run。

若入场成本、周期次数与 run 记录跨槽，启动流程同样使用 18 `PendingTransaction`：先保存启动意图，再按稳定子收据提交成本/次数与 run，最后确认 `ENTRY_COMMITTED`。任一物理步骤未知时只恢复原事务，不通过回滚已确认成本或创建第二个 run 处理。

## 7. 应用用例

### 7.1 `GetEncounterPreview`

| 项 | 契约 |
|---|---|
| 输入 | Encounter ID、可选难度档、17 返回的当前可信 `period_id`（若需要） |

| 事务 | 无写；评估进入条件、队伍限制、首通/次数、推荐信息和成本 |
| 输出 | 敌人/波次/首领公开信息、奖励预览、限制、可进入性和拒绝原因 |
| 错误 | `ENCOUNTER_CONFIG_MISSING`、`ENCOUNTER_ACCESS_FACT_UNAVAILABLE`、`CLOCK_UNAVAILABLE` |
| 幂等 | 相同来源修订与 `period_id` 返回相同结果 |

### 7.2 `StartEncounter`

| 项 | 契约 |
|---|---|
| 输入 | Encounter/难度、阵容上下文、启动收据、各槽预期修订、`TrustedPeriodSnapshot`（若需要） |
| 前置 | 非只读；进入规则满足；队伍合法；次数/成本足够；无同收据未决 run；周期内容的 period 状态为 LIVE |
| 事务 | 重校验 → 锁定/扣入场成本和次数 → 构建敌我快照 → 确定种子 → 记录安全点/收据 → 启动战斗会话 |
| 输出 | run ID、combat ID、快照哈希、入场结果、初始事件 |
| 错误 | `ENCOUNTER_LOCKED`、`ENCOUNTER_ATTEMPTS_EXHAUSTED`、`PARTY_CONSTRAINT_VIOLATION`、`COST_INSUFFICIENT`、`SAVE_REVISION_CONFLICT` |
| 幂等 | 重复启动收据返回同一 run/会话；不得再次扣成本或刷新种子 |

### 7.3 `ResolveEncounterTransition`

仅由战斗聚合内部安全边界调用。输入战斗状态、当前控制态和触发事件范围；输出下一阶段/波次/召唤/终局差异。预期战斗修订充当幂等保护，同一安全边界不得重复进入阶段或波次。

### 7.4 `RecordEncounterCombatResult`

输入 run、完整 `CombatResult`、快照/事件/命令哈希和命令 ID。前置为 combat ID、`rules_version` 均与 `EncounterRun` 冻结值匹配且结果终态。事务只把经验证结果写为 `RESULT_PENDING`，不发奖励。错误包括 `ENCOUNTER_RESULT_MISMATCH`、`COMBAT_RULES_VERSION_MISMATCH`、`COMBAT_RESULT_UNVERIFIED`。同一结果重放返回原状态；不同哈希冲突进入隔离。

### 7.5 `SettleEncounter`

| 项 | 契约 |
|---|---|
| 输入 | run ID、结算收据、预期世界/背包/Encounter 修订 |
| 前置 | `RESULT_PENDING`；战斗结果已验证；非只读 |
| 事务 | 解析胜负策略 → 首通判定 → 生成奖励/世界子收据 → 按 18 的 `PendingTransaction` 可恢复 Saga 逐 owner 提交并回读 → 更新完成次数/事实 → 标记终态 → 写入 outbox |
| 输出 | 结果、奖励、首通、世界变化、Encounter 修订、待补状态；不直接返回或写入任务进度 |
| 错误 | `ENCOUNTER_NOT_SETTLEABLE`、`REWARD_TRANSACTION_FAILED`、`SAVE_REVISION_CONFLICT`、`SAVE_READ_ONLY` |
| 幂等 | 同收据只结算一次；部分成功按子收据补齐，不重跑战斗/掉落 |

### 7.6 `RetryEncounter`

输入失败/放弃 run、重试确认、当前队伍修订和幂等键。按 `RetryPolicy` 决定是否保留入场成本、使用同种子或派生确定新种子、是否允许改阵容。首章故事战默认允许回安全点改阵容后新建 run；同一失败结算不重复扣成本。

### 7.7 `AbandonEncounter`

输入活动 run 和命令 ID；请求战斗放弃并记录失败/放弃结果，再走结算策略。不能只销毁 Y3 单位。重复放弃返回同一结果。

### 7.8 `RefreshRepeatableEncounterState`

输入由 17 `TrustedPeriodPort` 返回的 LIVE `period_id`、上次已确认 `period_id`、来源修订和幂等键；只对周期副本切换次数窗口，不清首通或历史完成数。CACHED/UNAVAILABLE、时间回退或来源修订冲突均返回可重试错误，不直接访问 `ClockService`，也不使用本地日期。

## 8. 领域事件

### 8.1 持久化事件

| 事件 | 关键载荷 |
|---|---|
| `EncounterDiscovered` | Encounter ID、世界事实来源 |
| `EncounterEntryCommitted` | run/Encounter、难度、周期键、队伍哈希、成本收据 |
| `EncounterCombatResultRecorded` | run/combat、结果、`rules_version`、三类哈希 |
| `EncounterCompleted` | `encounter_id`、`run_id`、`result`、`completion_fact_id`、完成次数、首通、`settlement_receipt_id`、`rules_version` |
| `EncounterFailed` | Encounter、run、原因、是否可重试 |
| `EncounterAbandoned` | Encounter、run、行动数 |
| `EncounterFirstCleared` | Encounter、首通奖励收据 |
| `RepeatableEncounterRefreshed` | 周期类型、旧/新周期键、重置项 |

`EncounterCompleted` 只能在 Encounter 权威状态、奖励/世界 Saga 及 `settlement_receipt_id` 均确认后从 outbox 发布。它是关卡完成目标的唯一事实；`CombatFinished`、胜利 UI、单位死亡和 `EncounterCombatResultRecorded` 都不能替代它。任务消费者按 `settlement_receipt_id`/`run_id` 去重，关卡不得同时再调用任务推进用例。

### 8.2 战斗内事件

下列事件属于 06 定义的 `CombatEvent` 信封专化，继承同一 `combat_id`、`sequence`、`event_id = combat_id + ":" + sequence`、`rules_version` 和规范序列化规则；不得另造第二种关卡事件信封。它们只驱动战斗内规则与表现，不是持久化结算事实。

| 事件 | 关键载荷 |
|---|---|
| `WaveStarted/WaveCleared` | 波次 ID/序号、生成 actor、进入/清波效果 |
| `EnemySpawned/EnemySpawnRejected` | spawn/actor/敌人/阵位或拒绝原因 |
| `BossPhaseChanged` | 首领 actor、旧/新阶段、触发条件、一次性序号 |
| `BossCastStarted` | 机制 ID、所需来源行动数、打断阈值 |
| `BossInterruptProgressChanged` | 当前/阈值、来源效果 |
| `BossCastInterrupted/Completed` | 机制、原因、执行/取消效果 |
| `EncounterConditionChanged` | 条件 ID、旧/新满足状态 |
| `EncounterVictoryConditionMet/FailureConditionMet` | 条件 ID 与优先级 |

事件按战斗序号进入事件哈希；持久消费者按统一 `event_id` 去重。

## 9. 存档 DTO、槽位与迁移

### 9.1 槽位归属

- 槽 `2`：Encounter 发现、首通、完成次数、永久世界结果和可进入解锁事实。
- 槽 `5`：周期次数/刷新键、启动/重试/结算幂等收据、待补奖励和异常 run 摘要。
- 槽 `4`：入场成本和奖励物品由背包系统保存，关卡系统只持有收据引用。
- 不把敌人运行生命、波次、首领阶段、PRNG 或 Y3 单位写入上述槽。

### 9.2 扁平 DTO

| 数组 | 行字段 |
|---|---|
| `encounter_progress_rows` | `encounter_id/discovered/first_clear/completion_count/last_completion_fact_revision/rules_version` |
| `encounter_choice_rows` | 若关卡永久分支需要：`encounter_id/choice_key/choice_value/revision` |
| `repeatable_rows` | `encounter_id/cycle_type/trusted_period_id/period_source_revision/attempts_used/completions/revision` |
| `pending_run_rows` | `run_id/encounter_id/state/start_receipt_id/combat_id/result_hash/settlement_receipt_id/retry_count`；仅安全恢复摘要 |
| `settlement_rows` | `run_id/sub_receipt_type/sub_receipt_id/status/result_digest` |

槽子表包含 `schema_version/revision`。所有行按 Encounter、周期、run ID 排序，保持最多三层嵌套。

### 9.3 恢复策略

- 读到 `ENTRY_COMMITTED/COMBAT_ACTIVE` 且无终局证明：首发视为异常中断，按重试策略返回安全点；不伪造胜负。
- `RESULT_PENDING/SETTLING`：核对结果哈希与子收据，继续幂等结算，不能重开战斗刷新掉落。
- 云档读取失败进入只读恢复页，绝不以“全部关卡未打”默认值覆盖。
- 弃用 Encounter 保留历史完成行；不再提供新入口。

### 9.4 迁移

- 波次/敌人平衡变化不重写历史次数；新挑战使用新 `rules_version`。
- 首通奖励变更不能对已首通玩家自动重发，除非有单独补偿收据政策。
- Encounter ID 不可复用。重制内容需新 ID 或显式版本兼容，不能把旧完成事实指向语义不同关卡。
- 旧存档若含敌人 HP/阶段等运行态，迁移丢弃并回安全点，保留启动成本/收据用于补偿判断。

## 10. Y3 适配与 UI

### 10.1 世界/战斗适配

- 地图区域、NPC、路障或菜单只映射 `start_interaction_id → encounter_id`，触发后先打开预览，不直接开战。
- 确认入场后把玩家镜头/单位切到独立战斗区；逻辑阵位映射为坐标，波次敌人仅按已确认战斗事件创建。
- Y3 单位死亡监听只用于动画/清理，不能触发 `WaveCleared` 或结算。
- 首领模型、阶段特效、召唤和环境对象按事件序号播放；资源缺失使用占位，不重跑机制。
- 离开战斗区先处理放弃/安全恢复，再清单位和镜头；清理失败不改变 run 状态。

### 10.2 Encounter 预览 UI

- 显示类型、波次数、已公开敌人/首领、推荐等级/路线（仅建议）、队伍硬限制、入场成本、次数、首通/重复奖励和可重试规则。
- 隐藏剧情敌人可用剪影/未知描述，但硬免疫、关键打断说明和会导致不可完成的机制必须在战前或教学中显著提示。
- 进入按钮覆盖加载、可进入、条件不足、次数不足、队伍非法、成本不足、服务器时间不可用、只读和提交中。

### 10.3 战斗 HUD 扩展

- 波次显示 `当前/总数`；首领显示专用血条、阶段标记、可见免疫和蓄力/打断进度。
- 机制提示来自领域事件与配置本地化键，不用 UI 计时器判定成功失败。
- 阶段切换可暂停表现队列播放演出，但领域结果不依赖演出结束；跳过后同步最终状态。
- 失败页明确区分战败、超时、保护目标失败、放弃、规则错误；规则错误不显示为普通实力不足。

### 10.4 结算 UI

结算页只展示 `SettleEncounter` 确认结果。奖励待补时显示“已记录，正在补发”，提供安全重试；不得先把预览奖励加入本地背包。首通和世界变化分别显示已确认/待补状态；任务提示只能在收到已提交的 `EncounterCompleted` 后刷新。

## 11. 边界、失败与恢复

- 同波重复阵位、敌人超过四名、召唤无空位：配置生成失败或运行返回明确拒绝，不挤占未知单位。
- 首领一次掉血跨多个阶段：严格逐阶段进入并重检；死亡后不再触发后续阶段。
- 首领阶段配置/效果断链、机制循环或事件预算超限：战斗规则错误，不发正常奖励、不扣擂台分。
- 保护目标与最后敌人同事件链倒地：失败条件优先。
- `TrustedPeriodPort` 非 LIVE 时，故事/普通无周期关卡仍可玩；会消耗或切换周期次数的内容暂停进入。
- 入场扣费成功但战斗会话创建失败：以启动收据恢复同会话或退回成本，不能再扣一次。
- 战斗胜利后存档只读/冲突：保留 `RESULT_PENDING` 和结果哈希，进入待结算恢复，不要求玩家重打。
- 掉落计算完成后保存失败：保存掉落结果摘要与子收据，重试不得重新抽取。
- Y3 敌人单位被意外删除：表现层重建/占位；领域 actor 仍按战斗状态存在。
- 重试不得成为刷种子入口：同一 run 重启政策固定；允许新种子时必须由新启动收据确定并承担正常成本。

## 12. 生成与静态校验

必须拒绝：

- 重复/错误前缀 ID、敌人/属性/招式/AI/效果/掉落/资源断链。
- 波次序号不连续、同波位置重复、初始在场超过 4、没有胜利条件或普通敌人无合法行动。
- 首领阶段序号/HP 阈值错误、阶段回退、同一触发歧义、入场效果循环、召唤上限缺失。
- 进入条件/任务/世界结果不可达或形成硬死锁，必选角色同时暂离/禁用。
- 胜负条件同边界矛盾、条件组合深度超限、99 行动理论上无法成功且未明确设计为生存战。
- 首通/重复奖励断链、付费结果混入普通掉落、周期内容未依赖 17 `TrustedPeriodPort` 或绕过它直接读取 `ClockService`。
- 任一配置/快照/结果仍使用 `rule_version/ruleset_version` 而非统一 `rules_version`，或 Encounter 与 Combat 冻结版本不一致。
- 任务完成来源配置为 `CombatFinished`/单位死亡而非含 `settlement_receipt_id` 的 `EncounterCompleted`，或关卡同时直接推进任务并发布完成事件。
- Y3 模型/动画/首领 UI 映射缺失或关键机制没有玩家可见说明。

生成报告至少输出：

- 首章 8 类敌人的角色路线/伤害类型覆盖、等级和构筑面板。
- 2 名首领的阶段图、阈值、招式变化、打断窗口、召唤上限和最坏事件预算。
- 每个 Encounter 的进入可达路径、至少一个合法队伍样例、波次/在场上限和胜负路径。
- 99 行动蒙特卡洛/枚举测试摘要只用于平衡诊断；正式结果仍由确定内核决定。
- 奖励来源/首通/重复/失败矩阵及所有收据键的唯一性。

## 13. 测试矩阵

| 类别 | 用例 | 通过条件 |
|---|---|---|
| 敌人构筑 | 普通/精英/首领、等级边界、输入乱序、未知来源 | 属性可复算，哈希稳定，非法拒绝 |
| 波次 | 1/多波、清波触发、间波恢复、装饰单位、同刻倒地 | 顺序严格且不提前结束 |
| 首领阶段 | 单阈值、跨多阈值、入场治疗、阶段中死亡、重复检查 | 阶段只进一次、不回退、不漏触发 |
| 打断 | 成功/失败、免疫、阈值边界、阶段取消、目标失效 | 只按领域行动/信号判定 |
| 召唤 | 空位、无空位、上限、重复请求、是否计胜负 | actor/位置稳定，无刷掉落 |

| 启动 | 条件/队伍/成本/次数、重复点击、部分成功 | 同收据唯一 run 和种子 |
| 结算 | 首通、重复、战败、超时、规则错误、部分奖励失败 | 不重发、不丢结果、规则错误无正常奖 |
| 时间 | 周期切换、不可用、回退、本地时间篡改 | 只信任服务器周期且不重复刷新 |
| 存档 | 活动中断、结果待结算、旧版迁移、未知 ID | 回安全点或补结算，不覆盖云档 |
| Y3/UI | 单位误删、演出跳过、资源缺失、按钮重入 | 表现不决定波次/胜负/奖励 |
| 内容 | 8 敌人、2 首领、所有首章 Encounter 全路线 | 无断链、死锁或不可通关配置 |

## 14. 验收标准

- 普通、精英、首领、波次和条件战都使用同一 Encounter 管线，无独立触发器直接发奖励。
- 首章至少 8 类敌人、2 名首领配置通过构筑、AI、效果、资源和可达性生成校验。
- 多波战只在效果/触发排空后换波；攻方战斗状态按配置正确继承或修改。
- 首领跨阈值、阶段治疗、召唤、打断和死亡边界均通过黄金事件测试，每阶段每战只进入一次。
- 启动、入场成本、重试、战斗结果与结算在超时/重复回调/修订冲突下不多扣、不重发、不要求重打已确认胜利。
- 服务器时间不可用只暂停周期内容，不阻断无时间依赖的主线和普通副本。
- Y3 单位/动画/区域异常不能伪造波次清空、胜负或奖励。
- 所有首章 Encounter 在四条武器路线的目标构筑下存在可通关样例，且没有全局体力门槛。

4. 实现 EncounterRun、波次控制、条件判定、首领阶段和机制状态机。
5. 接入战斗效果、AI、召唤/位移、结果哈希和规则错误契约。
6. 实现八个应用用例、入场/结算子收据、周期刷新和部分成功恢复。
7. 实现槽 2/5 扁平 DTO、迁移、隔离读取与 Fake 时钟/仓储。

## 16. 待决项

- 首章各区域具体 Encounter 数量和分布由内容清单冻结；本规格只冻结管线与最低内容基线。
- 可重复副本是否允许显式难度档；当前架构允许，故事战禁止自适应缩放。
- 战败重试使用同一种子还是新 run 新种子；默认同一 run 重启不换种，新建 run 按正常规则生成。
- 战斗后逐敌掉落是纯展示还是实际独立掉落表；建议统一结算后再展示，避免召唤刷取。
- 首领阶段切换是否清除特定减益；必须逐阶段在入场效果显式配置，默认不全清。
- 环境机制是否需要可点击场景对象；当前半自动战斗只支持由招式/目标规则交互，若加入点击机制需扩展命令流与重放契约。
