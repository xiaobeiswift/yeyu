# 《雾州侠行》世界探索系统工程规格

> 状态：工程实施规格候选稿；仅描述未来实现，不代表地图、触发器或 Lua 代码已经存在。
>
> 上位约束：[00-通用工程约定](./00-通用工程约定.md)。武学侧探索能力来源见 [04-武学系统](./04-武学系统.md)，跳跃、踏水、可达集和选格会话见 [26-轻功探索与特殊通行](./26-轻功探索与特殊通行.md)。

## 1. 目标与非目标

### 1.1 目标

- 在一个 Y3 2.5D 物理地图内，以稳定地区/地点/标记/交互物 ID 组织村镇、野外、门派、洞窟和独立战斗区。
- 支持点击移动与 WASD、固定斜俯视镜头、接近交互、搜索、采集、宝箱、区域进入、传送/马车、危险遭遇和剧情昼夜条件。
- 将世界规则与 Y3 区域/单位/可破坏物句柄隔离；纯领域层只处理 ID、条件、状态和事件。
- 一次性宝箱、搜索点、采集刷新、已发现地点和传送解锁可安全保存、迁移并防重复奖励。
- 移动/表现失败不改变奖励与任务权威事实；世界交互与奖励、任务、对话通过明确用例和收据衔接。
- 为 26 提供统一的离散探索格、特殊连接、标记、区域、坐标/高度/表面/阻挡、安全落点和空间修订事实，使地图可显示可达跳跃/行走格而不依赖战斗阵位。
- 保持世界位置、`last_safe_marker_id`、普通地面移动和地图空间注册的唯一所有权；特殊通行只有在 26 确认安全落地或离水上岸后才允许提交新位置。

### 1.2 非目标

- 不实现无缝开放世界分区、随机程序地图、多人同步、玩家碰撞、坐骑养成、物理模拟、破坏性地形或昼夜生态模拟。
- 不定义 NPC 对话图、任务状态、战斗内核、掉落抽取或商店；只提供世界位置和交互入口。
- V1 不实现自由攀爬、游泳、任意自由物理跳、潜行视野、天气影响、真实服务器时间驱动的剧情昼夜或实时交通班次；由 26 基于离散探索格实现的受控跳跃、长跃、高跃和踏水属于首章范围。
- 不允许配置直接执行任意 Lua；所有交互动作使用白名单类型和稳定引用。
- 12 不根据轻功等级计算可达集、不选择目标格、不拥有选格/空中/水上会话，也不绘制范围高亮；26 消费 12 的空间事实和 04 的 Profile 后完成这些职责。

### 2.1 稳定跨系统端口

| 端口 | 契约 |
|---|---|
| `WorldQuery.get_location(player_id)` | 返回地区/地点/标记 ID 和世界时间，不返回 Y3 坐标句柄 |
| `WorldQuery.get_interaction_context(interactable_id)` | 返回距离、可见性、可用性和条件缺口 |
| `WorldQuery.is_flag_set(flag_id)` | 查询世界事实；任务不能直接写 |
| `WorldCommand.request_move(target_marker_or_position)` | 应用层校验输入，再由 Y3 适配执行路径；到达由适配事件确认 |
| `WorldCommand.interact(interactable_id)` | 统一入口，按类型委托具体应用用例 |
| `WorldCommand.search/search_at` | 产生确定性候选列表和交互收据 |
| `WorldCommand.travel(route_id)` | 校验解锁/条件/成本并通过 18 可恢复 Saga 切换位置 |
| `EncounterStartPort` | 以 encounter ID、返回点和来源收据启动战斗 |
| `DialogueStartPort` | 以 dialogue ID、NPC ID 和世界上下文启动会话 |
| `RewardGrantPort` | 对宝箱/采集/搜索发放或待领，不直接改背包 |
| `TrustedPeriodPort`（17 提供） | 获取采集刷新周期 ID 与来源修订；非 LIVE 时冻结刷新型领取 |
| `TraversalSpacePort.get_marker/get_region` | 返回稳定 ID、归属、规范化整数坐标或 mapping 引用、表面/条件和 `spatial_revision`；绝不返回 Y3 句柄 |
| `TraversalSpacePort.locate_cell/query_cells/query_links` | `locate_cell` 只把已提交世界位置映射为顶层起点；`query_cells/query_links` 可在有效 WorldControlLease 下以 26 父会话的 runtime current_cell_id 查询水面窗口。均只报告空间事实，不应用轻功能力或距离预算 |
| `TraversalSpacePort.resolve_safe_landing` | 对候选格/marker 按阻挡、净空、地表与 fallback 顺序给出确定性安全落点；不宣称通行动画已经到达 |
| `TraversalWorldControlPort.acquire/release` | 26 以会话 ID 获取普通移动排他权；12 只持运行时 owner token，不复制 26 的阶段状态 |
| `WorldPositionCommitPort.commit_traversal_landing` | 26 收到带 session/movement token 的跳跃/离水表现完成通知后提交原逐段 command、receipt canonical tuple 字段、格/marker 与完整 source vector；12 复验后生成收据并更新位置。普通水格段不调用本端口 |
| `WorldSafeRecoveryPort.recover_last_safe_marker` | 取消未完成特殊通行并返回槽 2 的 `last_safe_marker_id`；不得使用水面/空中裸坐标 |

采集节点配置、可用/耗尽状态、本周期次数、唯一领取收据和采集奖励来源全部由 12 世界系统拥有并保存。17 只能计算周期边界；不得保存第二份节点状态、消费采集事件后改节点、发采集奖励或提供另一条采集用例。

`TraversalGrid/TraversalCell` 仅是探索地图离散空间，与 03 战斗 `Formation` 的 3×3 阵位完全无关：不共享 ID、坐标原点、序号、邻接、距离公式或存档字段，也不存在互转 API。普通格和普通邻接可以从 Y3 导航/高度数据预烘焙；悬崖跨越、单向落差、剧情门、桥洞和特殊踏水连接由稳定 `TraversalLink` 手工覆盖。12 只发布事实，26 才结合 04 Profile 计算当前可达集。

## 4. 领域模型

### 4.1 `AreaDefinition`

| 字段 | 类型/范围 | 说明 |
|---|---|---|
| `area_id` | `area_*` | 地区稳定 ID |
| `area_type` | `TOWN/WILDERNESS/FACTION/DUNGEON/BATTLE/UTILITY` | 类型 |
| `location_ids` | 有序 `location_*` | 子地点 |
| `entry_marker_id` | `marker_*` | 默认进入标记 |
| `camera_profile_id` | `camera_*` | 固定斜俯视参数引用 |
| `ambient_profile_id` | `ambient_*` | 环境声音/光照表现 |
| `minimap_id` | 稳定资源 ID | UI 映射 |
| `movement_profile_id` | `movement_*` | 速度、寻路与禁止区配置 |
| `condition_set_id` | 可空 | 地区准入条件 |
| `is_public_exploration` | 布尔 | BATTLE/UTILITY 通常 false |
| `deprecated` | 布尔 | 旧档兼容 |

### 4.2 `LocationDefinition`

字段：`location_id`、`area_id`、`name_key`、`bounds_mapping_id`、`discovery_marker_id`、`safe_return_marker_id`、`interactable_ids`、`neighbor_location_ids`、`condition_set_id`、`map_sort_order`、`fast_travel_unlock_id?`。

### 4.3 `WorldMarkerDefinition`

| 字段 | 说明 |
|---|---|
| `marker_id` | `marker_*` 稳定 ID |
| `area_id/location_id` | 归属 |
| `mapping_id` | 仅由 Y3 mapping 解析为点/朝向；配置不存句柄 |
| `marker_type` | `SPAWN/RETURN/SAFE_RETURN/INTERACTION/TRAVEL/CAMERA/ENCOUNTER/TRAVERSAL_START/TRAVERSAL_LANDING` |
| `safe_radius_cm` | 整数 0–5000；用于落点搜索 |
| `traversal_cell_id` | `traversal_cell_*`/null；通行起止 marker 必须绑定当前空间修订中的格 |
| `is_safe_recovery` | boolean；仅地面、净空通过且可从地区入口验证到达的 marker 可为 true |
| `fallback_marker_id` | 可空；解析失败时沿显式无环链回退，最终必须到地区 entry |

领域规则使用整数厘米表达距离阈值；适配器负责 Y3 世界单位换算，并经契约测试证明往返取整一致。

### 4.4 `WorldSpatialRegionDefinition`

| 字段 | 说明 |
|---|---|
| `region_id` | `region_*` 稳定 ID；语义配置和 Y3 区域映射的共同引用 |
| `area_id/location_id` | 归属，必须与其覆盖的格一致 |
| `region_type` | `LOCATION_BOUNDS/NAVIGABLE_GROUND/WATER_SURFACE/HAZARD/TRAVERSAL_TRIGGER/TRAVERSAL_LANDING` |
| `mapping_id` | Y3 区域/多边形映射逻辑 ID，不含句柄 |
| `condition_set_id` | 可空；只报告当前启用事实，能力校验仍由 26 执行 |
| `safe_fallback_marker_id` | WATER/HAZARD/TRAVERSAL 区域必填，且指向安全地面 |
| `priority` | 重叠区域稳定排序；高者优先，同值按 ID |
| `region_revision` | 该区域几何/启用事实版本，汇入 Grid `spatial_revision` |

12 拥有区域的几何身份、映射和启用修订；26 可用 `region_id` 绑定踏水或跳跃规则，但不得再创建一份区域坐标/句柄注册表。

### 4.5 `TraversalGrid`

| 字段 | 说明 |
|---|---|
| `grid_id` | `traversal_grid_*`；通常每个可探索 area 一张，可按层拆分 |
| `area_id` | 归属地区 |
| `cell_size_cm` | 正整数；发布后改变必须提升空间修订并提供重烘焙迁移策略 |
| `origin_mapping_id` | Y3 世界到规范化整数格坐标的原点/轴向映射 |
| `layer_ids` | 有序层 ID；桥上/桥下、洞窟高层不能仅靠二维坐标猜测 |
| `bake_version` | 烘焙工具与源地图版本 |
| `spatial_revision` | Grid、Cell、Link、Region 或权威阻挡变化后单调递增的聚合版本 |

`spatial_revision` 是选格确认的乐观并发版本，不是存档 `world_revision`。同一次 `query_cells/query_links` 必须来自同一空间修订；26 确认目标时若版本改变，旧可达集失效并重新查询。

### 4.6 `TraversalCell`

| 字段 | 类型/约束 | 说明 |
|---|---|---|
| `cell_id` | `traversal_cell_*` | 由 `grid_id + grid_x + grid_y + layer_id` 确定性生成；不作为任务/奖励永久 ID |
| `grid_id/area_id/location_id` | 稳定 ID | 归属必须一致 |
| `grid_x/grid_y` | integer | 离散探索格坐标 |
| `layer_id` | string | 立体重叠面的离散层；与战斗前后排无关 |
| `world_anchor_cm` | `{x,y,z}` integers | 格中心规范化地图坐标；仅运行时空间事实，不写玩家存档 |
| `height_level` | integer | 离散高度级；26 用于 `max_rise_levels/max_drop_levels` 校验 |
| `surface_type` | `GROUND/WATER/HAZARD/VOID` | 12 报告表面，26 决定能力是否允许进入 |
| `base_walkable` | boolean | 普通地面寻路是否可站立；WATER 不因踏水能力而改成普通可走 |
| `blocking_flags` | ordered enum set | `STATIC_BLOCKED/DYNAMIC_BLOCKED/OCCUPIED/QUEST_SEALED` 等空间事实 |
| `clearance_class` | enum | `SMALL/MEDIUM/LARGE/NONE`；表示碰撞净空，不表示角色具备能力 |
| `landing_safety` | `SAFE_GROUND/CONDITIONAL/UNSAFE` | 仅 SAFE_GROUND 可更新 `last_safe_marker_id`；条件项由 12 再解析 |
| `safe_landing_marker_id` | marker/null | SAFE_GROUND 必填；不得指向 WATER/HAZARD |
| `region_ids` | ordered set | 覆盖本格的 4.4 区域 |
| `reveal_policy` | `ALWAYS/ON_SELECT/ON_DISCOVERED/NEVER` | 仅告诉 26 是否可投影，不替代可达判定 |
| `region_revision` | integer | 覆盖区域/阻挡事实修订，必须不高于响应 `spatial_revision` |

普通格由地图烘焙生成，动态阻挡由 12 的空间注册表叠加；所有坐标在端口边界规范化为整数厘米和整数格。`cell_id` 只在匹配的 `spatial_revision` 内可用于确认，不保存为玩家长期位置，也不能与 03 的 Formation slot ID 互换。

### 4.7 `TraversalLink`

| 字段 | 说明 |
|---|---|
| `link_id` | `traversal_link_*`；稳定、全局唯一 |
| `from_cell_id/to_cell_id` | 同一发布空间版本中存在 |
| `direction` | `ONE_WAY/BIDIRECTIONAL` |
| `link_type` | `GROUND_ADJACENT/JUMP_DIRECT/JUMP_GAP/JUMP_RISE/JUMP_DROP/WATER_STEP/SCRIPTED` |
| `horizontal_cost_cells` | 非负整数；26 纳入能力/路径预算 |
| `rise_levels/drop_levels` | 非负整数，与两端高度差一致或有明确手工覆盖理由 |
| `required_clearance` | 净空等级 |
| `condition_set_id` | 可空；剧情门/机关只改变边是否启用 |
| `landing_marker_id` | 终点为可落地地面时必填；水面连续步可空 |
| `source_type` | `BAKED/MANUAL_OVERRIDE` |
| `link_revision` | 汇入 `spatial_revision` |

烘焙器为普通相邻格生成 `GROUND_ADJACENT`，并在项目声明的最大轻功半径内为空旷、安全、轨迹净空的地面格对生成 `JUMP_DIRECT`，使选点态能显示连续格范围而不是少量固定跳点；跨沟、屋顶、悬崖、单向落差、特殊水路和剧情边由 `MANUAL_OVERRIDE` 显式添加/屏蔽。12 校验几何与引用但不根据 `JUMP_BASIC/JUMP_LONG/JUMP_HIGH/WATER_WALK` 过滤 Link，能力闭包和路线预算由 26 负责。

| 字段 | 类型/范围 | 说明 |
|---|---|---|
| `interactable_id` | `interact_*` | 稳定 ID |

| `marker_id` | 合法标记 | 位置 |
| `interaction_radius_cm` | 50–1000 | 可触发距离 |
| `visibility_condition_id` | 可空 | 是否生成/显示 |
| `availability_condition_id` | 可空 | 可见但是否可操作 |
| `action_ref_id` | 稳定 ID | 对话、奖励、采集、路线、Encounter 等 |
| `persistence_policy` | `NONE/ONCE/PER_PERIOD/STATEFUL` | 状态归属 |

### 4.9 `WorldState`

| 字段 | 类型 | 说明 |
|---|---|---|
| `current_area_id/current_location_id` | 稳定 ID | 最近权威安全位置 |
| `current_marker_id` | `marker_*` | 最近已提交的普通移动/传送/特殊通行终点，不保存裸坐标 |
| `last_safe_marker_id` | `marker_*` | 最近确认的 `is_safe_recovery=true` 地面点；空中、水面和未确认落点绝不覆盖 |
| `facing_octant` | 0–7 | 可选恢复朝向 |
| `world_minute` | 0–1439 | 剧情世界时钟 |
| `world_day_ordinal` | 非负整数 | 休息/剧情推进的虚构天数 |
| `discovered_location_ids` | 排序集合 | 已发现地点 |
| `unlocked_travel_ids` | 排序集合 | 已解锁路线/站点 |
| `world_flags` | `flag_id -> 标量值` | 白名单布尔/小整数/字符串 ID |
| `interactable_states` | `interactable_id -> 状态摘要` | 一次性/有状态对象 |
| `world_revision` | 非负整数 | 权威世界变化加 1 |

### 4.10 交互状态

- 宝箱：`AVAILABLE → OPENING → REWARD_PENDING/OPENED`。`REWARD_PENDING` 是“对象已消耗、奖励待领”的业务终态，不是可再次打开的中间态。
- 一次性搜索：`HIDDEN/AVAILABLE → RESOLVING → REWARD_PENDING/COMPLETED`。进入 `REWARD_PENDING` 后发现/搜索事实已经提交且不可重做。
- 采集：按可信周期派生 `AVAILABLE/DEPLETED/REFRESH_UNKNOWN`，保存最后已领取 `period_id` 与本周期次数。
- 传送：`IDLE → VALIDATING → COST_RESERVED → FADING_OUT → RELOCATING → FADING_IN → COMMITTED`；视觉阶段不作为权威事务边界。

## 5. 配置表与字段

### 5.1 地区、地点、标记和连接

`areas`、`locations`、`world_markers` 使用 4.1–4.3 字段，`world_spatial_regions` 使用 4.4 字段。`location_edges` 字段：`from_location_id`、`to_location_id`、`bidirectional`、`travel_mode`（FOOT/PORTAL/CARRIAGE/SCRIPTED）、`condition_set_id`、`route_id?`。生成器构建地点可达图；该粗粒度图不能替代 4.5–4.7 的探索格图。

### 5.2 `movement_profiles`

| 字段 | 约束 | 说明 |
|---|---|---|
| `movement_profile_id` | `movement_*` | 配置 ID |

### 5.3 探索格、连接与阻挡配置

- `traversal_grids` 使用 4.5 字段；配置保存烘焙元数据和坐标变换，不把二进制导航资源内联进 Lua 业务表。

- `landing_clearance_profiles` 字段为 `clearance_class,radius_cm,height_cm,allowed_surface_types,occupancy_policy`；12 用于空间安全解析，不能包含轻功能力或武学等级。

格图应覆盖连续可探索地面与设计水域，而不是只登记几个固定跳点。主线所需的屋顶、沟壑、岸线和高低层必须同时存在格数据和 Link；特殊边手工覆盖只是修正烘焙图，不得退化为“点击固定热点播放动画”。

## 6. 运行时状态与不变量

### 6.1 运行时组件

- `WorldSession`：已加载 WorldState、当前 Y3 实例映射、配置版本、槽2修订。
- `MovementSession`：输入模式、普通移动目标、路径请求序号、最后安全 marker、卡住状态和 `movement_control_owner`；不持久化路径或 26 阶段。
- `InteractionFocus`：附近候选、选中 ID、距离、可用性；每次位置/条件变化重算。
- `WorldMutation`：交互命令、来源收据、奖励/成本预留和提交状态。
- `AreaRuntimeRegistry`：稳定 ID→Y3 句柄，仅适配层内存存在。
- `TraversalSpatialRegistry`：Grid/Cell/Link/Region/Marker 的同修订不可变快照、规范化坐标映射和已登记动态阻挡；12 独占注册，26 只通过端口查询。
- `WorldControlLease`：`owner=NORMAL/TRAVERSAL_26/RECOVERY`、`session_id`、`token`、`spatial_revision`；仅内存串行化移动入口，不复制 `SELECTING/IN_FLIGHT/WATERBORNE` 等 26 状态。

### 6.2 不变量

1. 当前 area/location/marker 必须互相归属且存在；不能保存任意运行时坐标作为唯一恢复点。
2. 一次性对象同一 `one_time_key` 最多成功一次；`REWARD_PENDING` 具有 `consumed=true` 语义，永久禁止再次交互、重算、重抽或重新发出来源奖励。
3. 采集周期只接受 `TrustedPeriodPort`；状态非 LIVE 时不切换周期、不采集领奖，但允许普通探索。
4. 同时最多一个权威交互命令；移动可在对话/战斗/传送时被输入锁定。
5. 距离只决定是否允许发起命令，不决定奖励随机；实际提交再次校验交互上下文。
6. 表现对象消失/动画失败不能自行设置宝箱已开或奖励已得。
7. world flags 类型由配置注册，未知 flag 不写入。
8. 世界位置与 `last_safe_marker_id` 只由 12 写入；26、Y3 动画和区域回调不能直接改槽 2。
9. 特殊通行开始、起跳、空中、水面移动和落地动画开始均不提交位置；匹配 session/movement token 的表现完成通知也只触发 26 进入领域复验，不能单独证明到达。只有当前 source vector、路线和安全落点复验全部通过才可提交目标 marker。
10. `last_safe_marker_id` 必须解析到 `SAFE_GROUND`、净空满足且当前空间修订有效的 marker。水面格、危险格、空中锚点或 `CONDITIONAL` 未解析格不得覆盖。
11. `TraversalCell/Link` 是按 `spatial_revision` 的只读事实；26 传回旧修订的选择一律拒绝，不能靠客户端显示仍高亮而放行。
12. 26 持有 `WorldControlLease` 时，普通 `RequestMove`、自动接近、搜索、采集、宝箱和传送都拒绝或排队；12 不通过任意一个交互偷偷取消通行。

## 7. 规则、算法与状态机

### 7.1 输入与移动优先级

- 对话、结算、加载、传送、过场和战斗拥有输入锁；锁存在时移动命令返回当前锁原因。
- `RequestMove` 只处理普通可寻路地面；点击需要跳跃/高跃/长跃/踏水的格时返回 `WORLD_SPECIAL_TRAVERSAL_REQUIRED` 并把格 ID 交给 26 的入口，不得让 Y3 寻路把水面临时标为可走。
- WASD 输入优先于未完成点击路径：非零 WASD 取消点击目标并进入直接移动。
- 点击可交互目标时建立 `auto_approach`；进入半径且仍可见/可用后只自动发起一次交互。玩家移动、目标失效或打开模态 UI 取消自动接近。
- 适配器以单调 `path_request_id` 忽略迟到路径回调，不能把旧回调当作新目标到达。
- 26 持有 `WorldControlLease` 时 WASD/点击事件路由给 26 或明确拒绝，不能同时启动普通路径。释放后才恢复普通移动；迟到普通路径回调仍按 request ID 丢弃。

### 7.2 交互候选选择

候选满足可见、在最大提示范围、未被会话锁定。排序：可用优先 → `priority` 降序 → 距离厘米升序 → `interactable_id` 升序。玩家可用键盘循环切换；实际命令仍按自身半径校验。

### 7.3 搜索

- 搜索由玩家主动命令触发，不是每帧自动扫描。
- 以当前权威位置和 `search_radius_cm` 获取映射候选，再按距离、ID 排序。
- 对每个候选校验条件与一次性状态；V1 一次命令只解析排序首个可解析目标。
- 搜索无结果不消耗资源，不推进世界时间；输出本地化反馈。
- 发现隐藏点先提交对应 flag/状态，再编排奖励或对话；若奖励容量不足，状态为 `REWARD_PENDING`，对象事实已完成，不能重复发现重抽。

### 7.4 宝箱/采集事务

1. 校验距离、可见、状态和来源唯一键。
2. 对掉落使用绑定的配置版本和显式种子准备奖励。
3. 发放可成功时按 18 的父事务/子收据 Saga 提交奖励与对象终态；容量不足且策略允许时，先确认对象 `REWARD_PENDING(consumed=true)` 与 10 的完整待领批次引用。
4. 提交成功后发布事件并播放表现；写入未知时对象显示核对状态且不可再交互。跨槽物理写可能部分完成，必须按同一收据前向恢复，不承诺云端 ACID 回滚。

待领批次随后由 10 `ClaimPendingReward` 完成时，不再把世界对象从 `REWARD_PENDING` 改写为 `OPENED/COMPLETED`，也不递增世界修订或重新发布 `ChestOpened/SearchPointResolved`。世界查询可把 10 的 pending 状态组合成 `reward_claimed=true` 的只读投影，UI 只补“奖励已领取”展示；对象的 consumed 权威事实始终不变。

采集 `max_harvests_per_period` 每次领取计 1；同一命令重试不增加次数。无可信周期时返回 `WORLD_REFRESH_TIME_UNAVAILABLE`。

### 7.5 地点发现

玩家首次进入地点边界并稳定停留至少 300ms 后发起发现命令；停留时间仅抗抖，不作为奖励权威。发现按 `location_id` 一次性收据提交，可解锁传送和任务事件。迟到的区域离开/进入回调按序号去重。

### 7.6 世界时钟

- `world_minute` 是剧情时钟，不等于现实服务器时间；初始值由新档配置。
- 仅休息、传送、任务/对话白名单效果可推进，公式：`total=old+delta`，`day_delta=floor(total/1440)`，`new_minute=total mod 1440`。
- `delta` 为整数 0–10080；负时间倒退 V1 禁止。
- 昼夜条件读取当前分钟所属阶段。玩家可通过旅店休息推进，不能因现实等待被主线阻塞。
- 日常/采集刷新仍使用服务器 period，不使用 `world_day_ordinal`。

### 7.7 传送事务

- 校验玩家在路线起点附近、路线已解锁、目的地有效、未在战斗/对话、成本足。
- 预留成本后先提交权威位置、时间推进和成本，再进行视觉淡出/移动/淡入；若引擎重定位失败，适配器尝试 fallback marker。
- 若所有落点失败，保留已提交世界状态但启动安全恢复到当前地区入口；不得重复扣费。为减少这种情况，发布前必须验证所有标记。
- Y3 表现可在提交前做淡出，但淡出完成不代表事务成功；失败时淡入原位置。

### 7.8 特殊通行空间查询与控制权

1. 顶层选格先按当前已提交位置向 `TraversalSpacePort.locate_cell` 获取起点格和 `spatial_revision`，再使用 04 Profile 的格数上界查询邻近 Cell/Link。嵌套水面选格禁止再次 locate：26 取父 TraversalSession.current_cell_id，12 在父会话已持有的 WorldControlLease 下复验该格仍为同一 WaterSurfaceZone 的 WATER 格，再以它查询窗口。12 只返回空间事实，不裁剪轻功能力、不生成可达集。
2. 26 计算可达集并投影高亮；高亮只是一份绑定 `origin_cell_id + ReachabilitySourceVector` 的视图，其中向量完整包含 `spatial_revision/world_revision/source_loadout_revision/source_progress_revision/profile_hash/rules_version`。玩家确认目标后，26 必须重新读取涉及的 Cell/Link 和六项来源，不能只复验空间修订。
3. 顶层确认后，26 以 `traversal_session_id`、起点 marker/cell、空间修订申请 `WorldControlLease`；12 确认当前世界修订、普通移动已停止且无其他 owner，返回一次性 token。踏水总会话从入水到离水/恢复始终持有该 lease；嵌套水面段只校验并复用它，禁止申请第二把 lease 或用岸边 marker 重置 runtime 起点。
4. 从取得 token 到安全结束，12 不更新 `current_marker_id/last_safe_marker_id`。Y3 起跳、跨格、水上步行、进入中间区域或播放落地动画均只是运行时事实，不能触发地点发现、任务到达或保存新位置。
5. 26 收到匹配的 `WATER_STEP_PRESENTATION_FINISHED` 时，只让 12 在原 lease/空间修订下复验目标仍是合法 WATER Cell；成功后由 26 更新父会话 current_cell_id、segment_sequence 与剩余预算，12 不提交 marker、不生成 receipt、不释放 lease。收到 `LANDING_PRESENTATION_FINISHED` 或 `SHORE_EXIT_PRESENTATION_FINISHED` 时，26 才把通知作为落地复验触发器并调用 `commit_traversal_landing`。12 按 control token、完整 source vector、目标 Cell/Link、marker、Profile/空间修订和完成序号复验，并调用 `resolve_safe_landing` 排除阻挡、错误表面和净空不足；动画或坐标回调本身不具有权威性。
6. 12 是落地结果 owner：复验通过后，对 canonical tuple `{player_save_scope, traversal_session_id, active_segment_command_id, segment_sequence, target_cell_id, rules_version}` 规范化哈希生成 `landing_receipt_id`。随后由 12 的 `world_position` section 一次提交 `current_area_id/current_location_id/current_marker_id/last_safe_marker_id/last_landing_receipt_id/world_revision`；同一 command 同输入重放派生同一 receipt 并返回原结果，不同输入复用立即拒绝。提交完成后发布世界落点事实、允许地点发现，再释放 control token。
7. 取消、能力变化、空间修订变化、表现失败或断线发生在第 6 步之前时，不存在新权威位置。26 进入恢复，12 将单位放回已保存 `last_safe_marker_id`；不得选择中间水格、空中格或客户端最近坐标。

踏水可在水面格图内连续选格/行走，但整个离岸阶段仍是一段未提交特殊通行；只有返回安全岸格并确认上岸才改变位置。由此断线重进必然回到最近安全岸边，不需要保存水面坐标或“剩余踏水距离”。

### 7.9 空间修订与安全落点

- 静态 Grid/Cell/Link/Region 由内容发布产生空间修订；登记的剧情门、机关和动态阻挡变化也单调提升会话 `spatial_revision`。普通装饰动画、粒子和未登记单位不改变权威修订。
- 查询响应必须携带统一 `spatial_revision`；无法构成同修订快照时返回 `WORLD_SPATIAL_SNAPSHOT_UNAVAILABLE`，26 保留普通探索但关闭新特殊通行。
- 安全落点排序固定为：指定目标 marker → 同格 `safe_landing_marker_id` → 目标 marker fallback 链 → 当前地点 safe return → 当前地区 entry；每步先校验地面、净空、条件和映射，再按 marker ID 稳定决胜。
- `resolve_safe_landing` 只证明“当前可以安全放置”，不证明角色已到达；预览时的成功结果不能代替落地后的再次校验。
- 若动画已落地但最终复验发现阻挡/修订变化，不能提交目标位置；26 播放恢复过渡，12 返回原 `last_safe_marker_id`。任务不会收到目标地点到达事实。

| `ResolveWorldUnknown` | receipt ID | 对象核对中 | 查询多槽收据 | 最终对象/奖励状态 | `SAVE_UNAVAILABLE` |
| `QueryTraversalSpace` | origin cell/规范化点、查询格半径、`expected_spatial_revision?` | Grid 已注册 | 同修订只读快照，无武学过滤 | Grid/Cell/Link/Region/Marker 空间事实 | `WORLD_TRAVERSAL_GRID_MISSING`、`WORLD_SPATIAL_REVISION_STALE` |
| `AcquireTraversalWorldControl` | 26 session、起点 cell/marker、Profile 哈希、空间/世界预期修订 | NORMAL owner、普通移动已停、起点与当前位置一致 | 内存 lease；同 session 重放返回原 token | owner token、起点、安全 marker、修订 | `WORLD_CONTROL_BUSY`、`WORLD_TRAVERSAL_ORIGIN_STALE` |
| `CommitTraversalLanding` | player save scope、session/control/movement token、原 active segment command、段序号、目标 cell/marker、Link 路径摘要、Profile/空间/世界 source vector、表现完成序号 | 匹配通知已触发领域复验；当前 source vector、路线与安全落点全部有效 | 12 从 command+规范输入生成 receipt，拥有的槽2 `world_position` 以其幂等提交；18 的槽5恢复事务只引用该 ID；完成后释放 lease | 新 area/location/marker/last safe/`landing_receipt_id`/world revision | `WORLD_TRAVERSAL_COMPLETION_STALE`、`WORLD_LANDING_UNSAFE`、`WORLD_SPATIAL_REVISION_STALE`、`IDEMPOTENCY_KEY_REUSED` |
| `RecoverTraversalToLastSafeMarker` | session/token或重进恢复原因、`command_id` | 存在有效 saved safe marker 或 fallback | 不提交水面/空中位置；必要的旧 marker 迁移按槽2幂等提交 | 恢复 marker、映射、lease released | `WORLD_SAFE_MARKER_INVALID`、`WORLD_MAPPING_MISSING` |

`RequestMove` 不要求业务幂等收据，但 `request_id` 单调去除迟到回调；所有可能发奖、扣费、设 flag 或改变一次性状态的用例必须有永久/周期幂等键。

`QueryTraversalSpace` 的“查询格半径”仅限制返回窗口和性能，不是可达规则。12 不接收轻功 ID/等级，也不能因看到 04 Profile 而隐藏水格或跳跃边；同一空间修订和同一窗口必须向所有合法调用者返回相同空间事实。

## 10. 存档 DTO、槽位与迁移

### 10.1 槽 2 `WorldSaveDTO`

| 字段 | 形态 | 说明 |
|---|---|---|
| `schema_version/revision` | 整数 | 槽信封 |
| `world_position` | 扁平记录 | `area_id,location_id,current_marker_id,last_safe_marker_id,last_landing_receipt_id?,facing_octant,world_revision`；唯一 owner 为 12 |
| `world_clock` | 扁平记录 | minute、day_ordinal |
| `discovered_locations` | 版本化有序 ID 编码 | 集合 |
| `unlocked_travel` | 版本化有序 ID 编码 | 集合 |
| `world_flags` | `flag_id -> 标量编码` | 类型表由配置校验 |
| `interactable_states` | `interactable_id -> 紧凑扁平记录` | state、period、count、receipt ref |

路径、裸坐标、Y3 区域句柄、附近对象、探索 Cell/Link、空间修订、WorldControlLease、选格 token、跳跃/踏水阶段、动画进度和水面剩余距离均不保存。普通安全移动或确认特殊落地后可同时更新 current/last safe；玩家在任何未完成特殊通行状态退出时，重进无条件回到已保存 `last_safe_marker_id`，再走其 fallback 链，不恢复空中或水面。

### 10.2 槽 5

槽 5 保存采集可信周期镜像、一次性交互收据、未知世界事务、奖励待领引用，以及 18 拥有的 `save_recovery_transactions`。特殊通行项只引用 12 生成的 `landing_receipt_id`、目标摘要和检查点状态，不复制位置、不成为第二份落地收据权威。槽 2/5 通过共同 receipt 对账；槽 5 不保存 26 会话轨迹，是否已落地最终以 12 的槽 2 `world_position.last_landing_receipt_id` 与已提交检查点为准。

其中采集镜像只保存 17 已确认的 `period_id/period_source_revision`，节点的 `count/depleted/collection_receipt_id` 仍是 12 的唯一权威。`REWARD_PENDING` 行必须保存 `consumed=1`、`pending_id` 与来源收据；待领完成状态不回写为第二个世界终态。

### 10.3 迁移

- 地点/标记改名使用显式 ID 映射；目的 marker 删除时迁移到地点 safe return，再到地区 entry，不能落到 `(0,0)`。
- 旧档只有 `current_marker_id` 时，经地面/净空/映射校验后初始化同值 `last_safe_marker_id`；校验失败走地点 safe return → 地区 entry，并以迁移收据提交。
- Grid/Cell/Link 只读生成物不做玩家存档迁移；空间发布变化使旧选格 token 失效。若旧候选版本曾保存 cell、水面坐标或通行阶段，迁移丢弃这些运行态并恢复 last safe。
- 交互对象下线保留已完成墓碑；旧 `AVAILABLE` 未完成状态可删除运行态但不能删除已领取收据。
- 刷新规则变化时保留最后可信 period；不得用本地日期重算旧次数。
- world flag 类型变化必须有逐值映射；无法转换进入只读恢复。
- 迁移后运行连接图和落点映射校验，再提交；重复运行一致。

## 11. Y3 适配与 UI

### 11.1 Y3 映射与运行时

- `area/location/marker/region/grid/interactable/camera/ambient` 稳定 ID 在 `adapters/y3/mappings` 映射 Y3 数字 Key/句柄；映射注册仍由 12 独占。
- 启动时注册区域进入/离开、单位点击、键盘、鼠标、路径完成/失败事件；每个回调转为纯 DTO 后才进入应用层。
- 点击地面射线、寻路、单位移动属于适配器；领域只接收规范化位置/距离/到达事实。
- 地图构建工具从导航面、地形高度、水域区域和静态碰撞烘焙 `TraversalCell`，再合并手工 `TraversalLink` 覆盖。运行时以同一坐标变换完成“Y3 点 ↔ 整数厘米 ↔ grid_x/grid_y/layer”映射，并用黄金样本证明往返落到同一 Cell。
- 登记的剧情阻挡/机关变化必须通过 `TraversalSpatialRegistry` 更新受影响 Cell/Link 并提升 `spatial_revision`；26 订阅修订事件后清除旧高亮。普通单位路过只作为落地时 occupancy 复验，不造成全图每帧重建。
- 26 可读取 Cell 的 `world_anchor_cm/layer/height/surface/reveal_policy` 来创建地面格贴花或轮廓，但具体可达颜色、选择反馈、跳跃轨迹和水面步点归 26 表现适配器；12 不持有高亮实例，也不因贴花生成失败改变空间事实。
- Y3 的起跳/落地表现完成通知必须携带 26 session、movement token、sequence 和目标映射；适配器只把通知转成 DTO 触发 26/12 领域复验。它不证明实际可达或安全，通用“单位停止移动”、当前坐标落在目标附近或动画结束都不能单独提交位置。
- 每帧逻辑只更新移动和交互焦点；禁止每帧扫描全图所有交互物。使用区域注册或空间索引维护附近集合。
- 镜头固定斜俯视，可按地区配置旋转/距离；剧情镜头有输入锁，结束后恢复 profile。
- 光照/环境音根据世界阶段事件切换；表现失败不改变 `world_minute`。

### 11.2 HUD 与地图 UI

状态覆盖 `LOADING/READY/INPUT_LOCKED/INTERACTION_BUSY/READ_ONLY/ERROR/RECOVERING`。

- HUD：当前交互提示、追踪任务摘要、搜索按钮、地图、队伍、设置；模态界面打开时输入锁可见。
- 点击与 WASD 可随时切换；移动目的地用地面标记反馈，路径失败显示原因并清除旧标记。
- 附近多个对象允许 Tab/方向键循环；提示显示动作键和禁用原因。
- 地图只显示已发现地点；未发现但任务明确指引的位置使用任务范围提示，不泄露隐藏点精确坐标。
- 马车页显示起终点、费用、世界时间推进和锁定原因；提交未知时显示核对而非再次购买。
- 搜索/采集/宝箱有明确成功、无结果、耗尽、待领取、服务器周期不可用反馈。
- 普通点击落在特殊通行格时，HUD 转交 26 打开轻功选格；范围格由 26 根据 Profile 与空间快照着色。12 只提供 anchor/表面/reveal 数据，不复用战斗阵型格 UI 或其 3×3 坐标。
- 空间修订、轻功 Profile 或起点变化导致旧范围失效时，先清除全部格投影再提示“地形已变化，请重新选择”，不能让视觉残留继续提交。

## 12. 边界、失败与恢复

| 场景 | 行为 |
|---|---|
| 玩家卡在不可走区 | 先停止并提示；仅通过“返回最近安全点”用例恢复，记录原位置诊断 |
| 标记映射缺失 | 构建/启动阻断；旧档用 fallback 链，不能静默 `(0,0)` |
| 区域事件乱序/抖动 | 使用序号和稳定停留去重；权威 current location 只采纳最新有效事件 |
| 自动接近途中目标隐藏 | 取消交互，不执行旧 action |
| 宝箱奖励写入未知 | 对象核对中不可点击；恢复收据后 OPENED/PENDING |
| 采集周期服务不可用 | 不刷新不发奖；已探索/移动/主线不受限 |
| 对话/战斗开始时仍移动 | 输入锁并停止单位；迟到路径回调按 request ID 丢弃 |
| 传送落点被临时单位阻塞 | 在 safe radius 取确定性候选；失败走 fallback |
| 特殊通行中断线/退出 | 不保存当前动画、格或水面坐标；重进将单位放回槽2 `last_safe_marker_id` |
| 目标格在确认前被封锁 | `spatial_revision` 或落地复验失败；26 清除旧选择，12 不提交位置 |
| 已起跳后目标出现临时占用 | 到达前解析同 marker 安全半径；仍无净空则回原 last safe，不把中间格当落点 |
| 26 会话 token 失配/重放 | 稳定拒绝；相同已提交 `landing_receipt_id` 返回原落点，不二次推进世界修订 |
| Y3 只回报“移动停止”未回报落地 | 视为未确认并恢复，不能提交目标 marker |
| Grid/Cell 映射或层解析缺失 | 关闭受影响区域特殊通行并报告内容错误；普通地面探索在安全范围内继续 |
| 空间快照构建中发生修订 | 返回 `WORLD_SPATIAL_SNAPSHOT_UNAVAILABLE`；不混用两版 Cell/Link，不显示半新高亮 |
| `last_safe_marker_id` 已被热更删除 | 按 marker fallback → location safe return → area entry 解析并幂等迁移；禁止 `(0,0)` |
| Y3 模型/动画缺失 | 可用占位表现；权威交互仍按 feature gate 决定，发布构建必须阻断缺失 |
| 配置热更删除当前区域 | 运行会话绑定版本至安全保存点，再迁移；不得中途改变连接图 |

## 13. 数据生成与校验

必须校验：

- 所有 area/location/marker/region/grid/cell/link/interactable/route ID 唯一、前缀正确、引用完整。
- 地点连接图从新档出生点可达所有主线必需地点；条件满足模型下无死路。
- 每地点有 safe return、每地区有 entry、每 Encounter 有合法 return marker、每路线有 fallback；每个 safe marker 必须绑定 `SAFE_GROUND` Cell、净空合法且 fallback 链无环。
- marker 映射存在、归属一致、交互半径/搜索半径/速度/时间范围合法。
- 所有可探索地面和设计水域均被 Cell 覆盖，无意外重叠层、孤立普通格或未归属区域；同 grid/layer 坐标唯一，世界 anchor 往返映射稳定。
- Cell 的 surface/base_walkable/height/landing_safety/clearance 与烘焙源一致；WATER/HAZARD/VOID 不得标记 `SAFE_GROUND`，WATER 不得因存在踏水内容被标为普通可走。
- Link 两端存在，方向、水平格成本与高低差一致；普通边来自烘焙，手工覆盖有理由和审计来源，覆盖后不存在重复冲突边或隐式双向。
- Region 覆盖格归属一致、修订可汇总；登记动态阻挡精确列出受影响格/区域和修订源，禁止未版本化的脚本直接改权威阻挡。
- 首章每个剧情必需特殊通行目标既有可用路径，也有安全落点/fallback；发布校验将 04 各可获得 Profile 交给 26 离线求解，但 12 的生成器自身不实现能力算法。
- `TraversalGrid/Cell/Link` 与 03 Formation Schema、ID 前缀和坐标类型零复用；检测到互相引用直接生成失败。
- 一次性 key 不重复；奖励型交互有来源唯一键和 PENDING 策略；采集有可信周期规则。
- 每个采集节点的 state/count/receipt owner 唯一指向 12，17 只提供 period rule；发现另一套刷新节点或领奖状态定义即生成失败。
- 所有 `REWARD_PENDING` 一次性对象均持久化 `consumed=1` 与 `pending_id`，且不存在待领完成后重新执行世界奖励/事件的配置路径。
- 昼夜阶段完整覆盖 1440 分钟，无重叠/空洞；主线夜间条件一定有可用休息/推进路径。
- action 类型与 ref 类型匹配，如 NPC→dialogue，CHEST→reward，ENCOUNTER→encounter。
- 正式内容不引用 BATTLE/UTILITY 地区为普通存档落点。

生成报告输出：世界连接图、主线地点可达路径、所有安全落点、交互密度、一次性 key、周期节点、隐藏点、主线昼夜可达证明、Y3 mapping 缺失表，以及每张探索 Grid 的格数/层数/地表分布/孤立格、Link 来源与单向边、落地净空、区域覆盖、坐标往返样本、空间修订清单和首章特殊通行路径输入包。

## 15. 验收标准

- 玩家无需开发命令可在三个首章地区使用点击和 WASD 完成移动、交互、搜索、采集、宝箱、传送与 Encounter 进出。
