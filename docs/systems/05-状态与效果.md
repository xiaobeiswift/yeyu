# 《雾州侠行》状态与效果系统工程规格

> 状态：实施候选稿；仅描述未来实现，不代表代码已经存在。
>
> 上位约束：[00-通用工程约定](./00-通用工程约定.md)。武学只引用本文定义的效果/状态，见 [04-武学系统](./04-武学系统.md)。行动调度与伤害结算见 [06-确定性战斗与AI](./06-确定性战斗与AI.md)。

## 1. 目标与非目标

### 1.1 目标

- 用声明式、可校验的数据表达伤害、治疗、聚气、状态施加/移除、护盾、复活、位移、召唤请求和首领机制信号。
- 定义持续状态的叠层、刷新、独立实例、持续时间、触发顺序、驱散、免疫、控制和来源归属。
- 所有效果在显式战斗上下文、显式 PRNG 和稳定目标顺序下执行，输出可重放的战斗事件。
- 防止无限触发、循环引用、概率越界、目标失效和表现回调反向改变权威结果。
- 为武学、装备、天赋、敌人、环境机制共用一套效果契约。

### 1.2 非目标

- 本系统不负责行动时间轴、玩家命令、最终攻击/防御公式版本选择、关卡奖励、永久角色成长或 Y3 特效播放。
- 首章不支持在配置中嵌入 Lua 表达式、函数名、任意脚本或动态加载远程效果。
- 战斗状态默认不跨战斗保存；永久伤病、食物增益等若后续需要，必须建独立世界增益系统并在开战时转换。
- UI 图标剩余秒数不参与持续时间判断；权威持续时间使用行动计数。

## 2. 依赖与跨系统接口

### 2.1 上游输入

| 系统 | 输入 |
|---|---|
| 武学/装备/天赋 | `effect_bundle_id`、被动触发钩子、来源 ID 与等级标量 |
| 战斗系统 | 当前战斗状态、规范化目标、行动/事件序号、显式 PRNG、伤害/治疗计算端口 |
| 敌人/首领/环境 | 机制效果包、阶段信号、召唤/位移请求 |
| 配置注册表 | 效果包、效果节点、状态、触发器、目标规则和标签 |

### 2.2 下游输出

| 消费方 | 输出 |
|---|---|
| 战斗内核 | 原子状态差异、追加事件、后续触发任务、召唤/阶段请求 |
| AI | 当前状态标签、可驱散/控制/护盾等只读摘要，不暴露隐藏随机结果 |
| 表现层 | 按事件序号消费 `EffectResolved/StatusApplied/DamageApplied` 等表现 DTO |
| UI | 状态图标、层数、剩余行动、来源和可驱散标签 |
| 测试/复盘 | 规范化效果轨迹、PRNG 消耗索引和事件哈希输入 |

### 2.3 权威边界

- 效果系统只操作战斗运行态副本，不直接写角色/武学/背包/任务存档。
- 召唤、阶段切换和环境变化输出“领域请求”，由战斗/关卡聚合验证并在同一事件循环中提交。
- `presentation_cue_id` 只附在事件上；资源缺失或动画中断不能重跑效果。

## 4. 领域模型字段

### 4.1 `EffectExecutionContext`

| 字段 | 类型 | 说明 |
|---|---|---|
| `combat_id` | string | 当前战斗唯一 ID |
| `sequence_cursor` | integer | 下一事件序号，由战斗聚合持有 |
| `source_actor_id` | string/null | 环境效果可空，但必须有来源配置 ID |
| `source_definition_id` | string | 武学、状态、敌人机制或环境 ID |
| `primary_target_ids` | ordered array<string> | 已由目标系统规范化 |
| `trigger_event` | event/null | 被动触发来源；主动效果可空 |
| `action_index` | integer | `0..99`，开战效果可为 0 |
| `trigger_depth` | integer | `0..16` |
| `prng` | explicit port | 唯一随机源；记录消耗索引 |
| `rules_version` | integer | 与战斗快照一致；字段名必须精确使用本行名称 |
| `scalar_map` | integer map | 仅配置声明允许的等级/阶段标量 |

### 4.2 `EffectBundleSpec`

字段：`bundle_id`、`schema_version`、`node_ids[]`（有序）、`atomicity`、`stop_policy`、`target_snapshot_policy`、`event_budget_override`（不得超过系统硬上限）、`presentation_group_id`。

- `atomicity=NODE`：每个节点独立提交，后续可见前节点结果；首章默认。
- `atomicity=BUNDLE_VALIDATE_THEN_APPLY`：先验证所有静态前置，再依序提交；运行中目标死亡仍按节点策略处理，不回滚已造成伤害。
- 不支持数据库意义的“整包回滚战斗结果”，避免触发事件无法逆转。

### 4.3 `EffectNodeSpec`

| 字段 | 类型 | 约束 |
|---|---|---|
| `node_id` | string | 包内唯一，稳定 |
| `operation` | enum | 见 4.4 |
| `target_rule_id` | string/null | 空则继承主目标 |
| `condition_id` | string/null | 声明式条件，禁止脚本 |
| `chance_bp` | integer | `0..10000`，默认 10000 |
| `magnitude_spec_id` | string/null | 伤害/治疗/聚气等标量定义 |
| `status_id` | string/null | 状态类操作必填 |
| `stacks` | integer | `1..99`，默认 1 |
| `duration_override` | integer/null | 必须在状态允许范围 |
| `failure_policy` | enum | `CONTINUE/STOP_BUNDLE/REQUIRE_SUCCESS` |
| `presentation_cue_id` | string/null | 只影响表现 |

### 4.4 原子操作枚举

| 操作 | 结果 | 关键限制 |
|---|---|---|
| `DEAL_DAMAGE` | 请求战斗伤害管线并应用生命/护盾差异 | 必须有伤害规格；不能直接写 HP 数字 |
| `HEAL` | 请求治疗管线 | 死亡目标默认不可治疗，除非规格允许复活前治疗 |
| `MODIFY_QI` | 增减聚气 | 结果钳制 `0..max_qi`，事件记录实际变化 |
| `APPLY_STATUS` | 添加/刷新/叠层状态 | 经过免疫、命中/抵抗和叠层规则 |
| `REMOVE_STATUS` | 按 ID/标签/类别驱散 | 按稳定规则选择实例 |
| `ADD_SHIELD` | 创建或增加护盾状态 | 护盾必须由 `status_` 定义承载 |
| `DISPEL` | 驱散若干增益/减益 | 配置数量与优先级，不能遍历无序集合 |
| `MOVE_POSITION` | 输出逻辑位移请求 | 阵位合法性由战斗阵位模块确认 |
| `SUMMON` | 输出召唤请求 | 敌人/关卡系统校验名额、模板和次数 |
| `REVIVE` | 把倒地目标恢复为存活并给定生命 | 首章若未配置任何引用则功能保持关闭 |
| `SET_MECHANIC_FLAG` | 更新战斗内机制标记 | 只允许注册键和值范围 |
| `EMIT_SIGNAL` | 发关卡/阶段信号 | 不能直接发永久奖励或任务完成 |

### 4.5 `StatusInstance`

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| `instance_id` | string | 战斗内确定生成：`combat_id:status_sequence` |
| `status_id` | string | `status_` 前缀、已注册 |
| `owner_actor_id` | string | 当前承受者 |
| `source_actor_id` | string/null | 来源可能是环境 |
| `source_definition_id` | string | 追溯武学/状态/机制 |
| `stack_count` | integer | `1..max_stacks` |
| `remaining_duration` | integer/null | 永久战斗状态可空；否则 `0..999` |
| `duration_unit` | enum | `OWNER_ACTIONS/GLOBAL_ACTIONS/SOURCE_ACTIONS/UNTIL_COMBAT_END` |
| `magnitude_snapshot` | integer map | 施加时冻结的白名单标量；最多一层键值 |
| `application_sequence` | integer | 稳定驱散与展示排序 |
| `trigger_counters` | flat integer map | 每行动/每战计数，重置规则由定义指定 |
| `suppressed` | boolean | 被免疫场/阶段临时压制时不触发，但持续时间照常走由配置决定 |

### 4.6 `StatusDefinition`

字段：`id`、`schema_version`、`name_key`、`description_template_key`、`polarity`（`BUFF/DEBUFF/NEUTRAL`）、`tags[]`、`stacking_mode`、`max_stacks`、`base_duration`、`duration_unit`、`refresh_policy`、`magnitude_policy`、`dispel_category`、`dispel_priority`、`control_tags[]`、`immunity_tags_required_absent[]`、`stat_contribution_set_id`、`trigger_ids[]`、`visual_id`、`visibility`、`persist_through_phase`、`deprecated`。

## 5. 配置规则

### 5.1 叠层模式

| 模式 | 行为 |
|---|---|
| `REPLACE` | 删除同 `status_id` 旧实例，创建新实例；先发移除再发添加事件 |
| `REFRESH` | 保持一个实例；层数不变，按刷新策略更新持续和强度 |
| `ADD_STACK` | 保持一个实例；层数增加至上限，可刷新持续 |
| `INDEPENDENT` | 每次创建独立实例；实例数受 `max_instances_per_actor` 限制 |
| `KEEP_STRONGER` | 比较规范化强度键；更强者替换，更弱者返回 `NO_CHANGE` |

同一状态来源是否区分实例由 `source_scope=ANY_SOURCE/PER_SOURCE_ACTOR/PER_SOURCE_DEFINITION` 决定。

### 5.2 刷新策略

`RESET_TO_BASE`、`KEEP_LONGER`、`ADD_DURATION_CLAMPED`、`NO_REFRESH`。增加后的持续时间不得超过 `max_duration`（默认 999）。强度策略为 `SNAPSHOT_NEW/KEEP_OLD/KEEP_MAX/ADD_CLAMPED`，必须与叠层模式兼容。

### 5.3 `StatusTriggerDefinition`

| 字段 | 约束 |
|---|---|
| `id` | `trigger_` 前缀、唯一 |
| `hook` | 注册枚举，如 `COMBAT_STARTED/BEFORE_ACTION/BEFORE_DAMAGE/AFTER_DAMAGE/HP_CHANGED/ACTOR_DOWNED/ACTION_FINISHED/STATUS_REMOVED` |
| `condition_id` | 声明式条件，可空 |
| `effect_bundle_id` | 引用存在 |
| `priority` | `-1000..1000` |
| `limit_per_action` | `1..99`，必填 |
| `limit_per_combat` | `1..9999`，必填 |
| `can_trigger_from_self` | boolean |
| `can_trigger_from_triggered_effect` | boolean，默认 false |
| `consume_stack` | `0..99` |

### 5.4 `MagnitudeSpec`

只允许白名单项组合：固定整数、来源/目标指定属性乘以倍率基点、武学等级标量、状态层数标量、目标已损生命比例、阶段标量。每项有系数上下限，固定顺序相加/相乘并逐步向下取整。禁止任意字段路径和表达式字符串。

### 5.5 条件配置

支持：存活/倒地、己/敌方、生命/聚气阈值、状态 ID/标签/层数、阵位排、伤害类型、招式标签、是否暴击/格挡、行动计数、机制标记。复合条件为显式 `ALL/ANY/NONE` 节点，最大深度 4、总节点 32；不得引用服务器时间或永久存档。

## 6. 运行时状态与处理循环

### 6.1 效果队列

战斗聚合维护 FIFO `EffectTaskQueue`。每项含效果包、上下文、触发深度和因果事件。初始主动效果入队后循环：取队首 → 解析目标 → 校验条件/概率 → 执行节点 → 追加事件 → 收集触发器 → 按稳定顺序把触发任务追加队尾。禁止递归函数直接执行整个链。

### 6.2 稳定顺序

- 节点按配置数组顺序。
- 目标按战斗系统的目标规范化顺序。
- 状态触发器按 `(priority, owner_side_order, owner_position, owner_actor_id, status.application_sequence, trigger_id)`。
- 驱散选择按 `(dispel_priority desc, application_sequence asc, status_id, instance_id)`。
- 同步死亡/阶段/召唤等后续检查由战斗文档规定，不由表现顺序决定。

### 6.3 持续时间结算

- `OWNER_ACTIONS`：拥有者一次行动（含因控制跳过）完整结算后的 `ACTION_FINISHED` 减 1。
- `SOURCE_ACTIONS`：来源角色行动结束减 1；来源退场后仍保留，除非配置移除。
- `GLOBAL_ACTIONS`：每个行动机会结束减 1。
- `UNTIL_COMBAT_END`：不递减。
- 降到 0 时在该行动所有 `ACTION_FINISHED` 触发器执行后移除，避免最后一跳丢失。

## 7. 规则、命中与安全预算

### 7.1 状态施加

1. 校验目标、免疫标签、状态定义和实例上限。
2. 若状态需效果命中，计算 `final_chance_bp = clamp(base_chance_bp + source.effect_accuracy - target.effect_resistance, 0, 10000)`。
3. 仅当概率不是 0/10000 时消费一次 PRNG；规则统一为 `roll in 0..9999` 且 `roll < final_chance_bp` 成功。
4. 按来源作用域匹配旧实例，执行叠层/刷新策略。
5. 应用状态属性贡献并令战斗派生状态失效重算；发布实际变化事件。

硬控制状态还要经过对应 `control_immunity` 标签；免疫时不消费状态命中 PRNG，发布 `StatusApplicationRejected(reason=IMMUNE)`。

### 7.2 效果节点概率

- 节点条件先判定，条件不满足不消费 PRNG。
- `chance_bp=0` 永不执行且不消费；`10000` 必执行且不消费；其他值恰消费一次。
- 多目标默认每目标独立判定，顺序按规范目标；若要求整包一次判定，配置 `chance_scope=BUNDLE`，只消费一次并影响全部目标。

### 7.3 驱散与免疫

- 驱散只移除 `dispel_category` 匹配且 `UNDISPELLABLE` 标签缺失的状态。
- 数量 `1..99`；不足时移除全部合法目标，操作仍成功并记录实际数量。
- 免疫默认阻止新状态，不自动清除已有状态；需要清除时免疫效果包显式包含 `DISPEL`。
- 状态被替换/驱散/到期分别记录原因，触发器可按原因过滤。

### 7.4 护盾

护盾是带 `SHIELD` 标签的状态，强度存于白名单 `shield_remaining`。多个护盾按 `(absorb_priority desc, application_sequence asc)` 吸收；每次吸收产生事件。耗尽后立即移除。护盾不改变 `max_hp`，治疗不能恢复护盾，除非显式 `ADD_SHIELD`。

### 7.5 控制

控制标签包括 `STUN/SILENCE/DISARM/ROOT/TAUNT`。战斗使用：`STUN` 跳过行动，`SILENCE` 禁主动绝招但可普攻，`DISARM` 禁套路主动/普攻并由配置决定替代动作，`ROOT` 禁位移，`TAUNT` 限制目标。多个控制状态并存，不以单一枚举互相覆盖。

### 7.6 事件与递归预算

- 单次行动最大效果节点执行数 `2048`、战斗总节点 `20000`、触发深度 `16`、单角色状态实例 `128`、全战斗状态实例 `512`。
- 达到任一预算立即停止新增任务，发布 `EffectBudgetExceeded`，战斗以 `INVALID_RULE_EXECUTION` 失败，不判任一方正常胜利。
- 配置静态检测到确定循环直接拒绝生成；预算用于处理条件性循环和数据缺陷。

## 8. 应用/领域服务用例

效果系统主要由战斗聚合内部调用；以下接口仍以结构化命令/结果定义，避免调用方直接改状态。

### 8.1 `ResolveEffectBundle`

| 项 | 契约 |
|---|---|
| 输入 | 战斗状态修订、`EffectExecutionContext`、效果包 ID、显式 PRNG 状态 |
| 前置 | 战斗进行中；来源与目标属于战斗；规则版本一致；事件预算充足 |
| 事务 | 在战斗聚合内依序执行，得到新战斗状态、PRNG 状态、事件和后续请求；外部不可部分提交 |
| 输出 | 实际节点结果、事件范围、PRNG 消耗范围、状态修订 |
| 错误 | `EFFECT_CONFIG_MISSING`、`EFFECT_TARGET_INVALID`、`EFFECT_BUDGET_EXCEEDED`、`COMBAT_REVISION_CONFLICT` |
| 幂等 | 由战斗命令序号保证；同一命令不得再次执行，重放从旧状态和同 PRNG 可得相同结果 |

### 8.2 `ApplyStatusOperation`

输入目标、状态、来源、层数、持续、概率上下文；只能由效果执行器调用。输出 `APPLIED/REFRESHED/STACKED/REPLACED/NO_CHANGE/REJECTED` 和事件。运行中直接从 UI 调用返回 `EFFECT_CALLER_UNAUTHORIZED`。

### 8.3 `RemoveStatuses`

输入目标、选择器、数量、移除原因；按稳定驱散顺序执行。输出移除实例 ID 与触发任务。重复移除已不存在实例返回成功且 `removed=[]`，方便事件重放，不生成第二次移除事件。

### 8.4 `AdvanceStatusDurations`

输入完成的行动事件、战斗状态修订；前置为该行动尚未结算持续时间。事务执行对应触发、递减和到期移除。行动序号是幂等键；重复调用返回原事件范围。

### 8.5 `PreviewEffectTooltip`

输入效果包、武学等级和展示上下文，不含真实战斗目标。输出可展示标量、范围和条件，不执行随机/状态变化。若配置无法生成准确描述，返回 `EFFECT_TOOLTIP_UNRESOLVED` 并阻断内容发布。

### 8.6 `ValidateEffectGraph`

构建期/启动期只读用例。输入配置版本，输出断链、强连通循环、预算上界、非法条件、未映射表现和描述错误；不修改存档。

## 9. 领域与战斗事件

所有事件都由战斗聚合封装为 06 §11 的 `CombatEvent`，完整继承通用 `DomainEvent` 信封，并额外带战斗 `sequence`、`action_index`、`causation_id`；效果系统不自行生成 `event_id`，也不带服务器时间。

| 事件 | 关键载荷 |
|---|---|
| `EffectBundleStarted/Finished` | 包 ID、来源、目标、节点结果摘要、PRNG 消耗范围 |
| `EffectNodeSkipped` | 节点 ID、目标、原因 `CONDITION/CHANCE/INVALIDATED` |
| `DamageRequested/DamageApplied` | 规格引用、计算明细摘要、护盾/生命实际变化 |
| `HealingApplied` | 请求量、实际治疗、溢出量 |
| `QiChanged` | 旧值、新值、实际变化、来源 |
| `StatusApplied/Refreshed/StackChanged/Replaced` | 实例/状态、层数、持续、来源 |
| `StatusApplicationRejected` | 状态、目标、原因、是否消费随机 |
| `StatusRemoved` | 实例、状态、原因 `EXPIRED/DISPELLED/REPLACED/CONSUMED/OWNER_REMOVED` |
| `ShieldAbsorbed/ShieldBroken` | 实例、吸收值、剩余值 |
| `PositionMoveRequested/Resolved` | 来源、目标、起止位、拒绝原因 |
| `SummonRequested/Resolved` | 模板、位置、请求/拒绝结果 |
| `MechanicSignalEmitted` | 信号 ID、整数载荷 |
| `EffectBudgetExceeded` | 预算类型、当前计数、触发链摘要 |

表现层必须按序消费；可跳过纯诊断事件，但不能更改结果。

## 10. 存档 DTO 与快照

### 10.1 永久存档

- 普通战斗状态、效果队列、护盾、聚气和持续时间不写槽 `1–5`。
- 首发不支持战斗中退出续战；异常退出重进时回到开战前安全点，奖励只在结算事务确认后保存。
- 状态/效果配置版本 ID 进入战斗快照和复盘摘要，但配置正文不进云档。

### 10.2 `StatusRuntimeSnapshot`

仅用于战斗内内存重放/自动化测试：扁平行含 `instance_id/status_id/owner/source/source_definition/stack/remaining/duration_unit/application_sequence/suppressed/magnitude_key/value`。若未来支持战斗断点，必须另立 ADR，验证三层限制、PRNG/队列/命令完整恢复后才能落盘。

### 10.3 擂台

槽 `100` 不保存开战时状态实例；只保存武学/装备/天赋来源。任何公开档携带的运行状态均拒绝或忽略并记录恶意字段。

## 11. Y3 适配与 UI

### 11.1 Y3 表现适配

- `EffectPresentationAdapter` 消费已确认事件，映射飘字、特效、音效、震屏和逻辑位移动画。
- 同一事件 ID/序号只播放一次；重连/加速可跳过非关键动画但保持最终模型/血条状态。
- 伤害飘字使用事件中的实际生命/护盾变化，不从 Y3 单位属性回读。
- 资源缺失记录 `PRESENTATION_RESOURCE_MISSING` 并使用安全占位，不让战斗等待无限时间。

### 11.2 状态 UI

- 图标显示极性、层数、剩余“自身行动/全局行动/来源行动”及来源；不伪装为秒。
- 公开可见状态按 `(polarity, display_priority, application_sequence)` 排序；隐藏状态只对调试界面可见。
- 详情文案由配置标量生成，说明叠层、持续、驱散类别与触发条件。
- 状态快速变化时 UI 可合并动画，但事件日志和最终层数必须准确。
- 表现积压时允许“追帧/跳过动画”，不得阻塞领域继续到超时或改变 AI 读取状态。

## 12. 边界、失败与恢复

- 目标在前一节点死亡：按节点 `dead_target_policy=SKIP/ALLOW/RETARGET` 处理；`RETARGET` 必须重新走稳定目标规则，不消费额外随机除非规则明确。
- 来源死亡不自动取消已入队效果；是否取消由效果包 `requires_source_alive` 配置。
- 状态定义缺失、非法强度字段、运行时循环或预算超限均使战斗进入规则错误，不以普通失败结算奖励。
- 表现回调超时不回滚效果；应用层可跳过 cue 后同步最终状态。
- 状态实例上限达到时返回明确拒绝，不能删除最旧实例腾位置，除非状态定义自身为 `REPLACE`。
- 复活目标的原状态清理规则必须配置；默认倒地时移除 `remove_on_down=true` 的状态，其余保留至战斗结束。
- 整数乘法必须保持中间值小于 `2^53`；配置生成器需做上界分析，运行时再次保护。

## 13. 生成与静态校验

必须拒绝：效果/状态/目标/表现断链、效果包直接/间接确定循环、无触发上限、非法概率/倍率/持续/层数、条件深度超限、状态模式与刷新策略不兼容、永久奖励操作、未知机制键、不可描述 tooltip、召唤模板断链、可能超过整数安全范围的幅度。

生成报告应包含：效果引用反向索引、触发强连通分量、每行动理论节点上界、每种状态叠层示例、控制/免疫矩阵、驱散优先序、PRNG 消耗路径、12 门武学所有招式的 tooltip 对照和无引用“孤儿”配置。

## 15. 验收标准

- 首章所有武学、敌人和首领效果均只通过声明式效果/状态配置实现，无任意 Lua 脚本字段。
- 相同战斗状态、效果上下文、命令和 PRNG 状态重复执行得到相同状态差异、随机消耗和事件序列。
- 叠层、刷新、独立实例、驱散、控制、护盾和持续时间黄金样本全部通过。
- 静态循环在生成期拒绝，条件性循环在运行预算内安全终止并判规则错误，不错误发奖。
- 状态运行态不进入普通云档或公开擂台档，Y3 单位状态不被当作权威。
- 动画加速、跳过、资源缺失和 UI 帧率变化不改变任何效果结果。
- UI 数值和实际效果使用同一配置来源，所有状态说明可生成且无断链。

## 17. 待决项

- 首章是否启用复活；操作已预留，未有合法配置引用时必须保持关闭。
- 位移是否改变阵型动态加成；当前初始阵型属性不重算，动态相邻效果需声明为战斗状态规则。
- 持续伤害采用来源施加时快照还是每跳实时属性；由各状态 `magnitude_policy` 明确，默认快照。
- 同一效果命中公式是否区分控制、毒、流血等类别；当前统一评分，可由标签增减贡献扩展。
- `GLOBAL_ACTIONS` 是否对召唤物/环境行动计数；当前每个正式行动机会都计数，纯触发不计。
- 后续若支持战斗断点保存，必须完整保存效果队列、状态、PRNG 和命令游标；当前明确不支持。
