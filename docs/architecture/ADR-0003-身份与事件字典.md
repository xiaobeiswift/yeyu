# ADR-0003：命令、来源、事务、收据与事件身份

> 状态：已采纳（规划阶段）

## 决策

| 名称 | 语义 | 生命周期 | 示例 |
|---|---|---|---|
| `command_id` | 一次命令及其重试身份 | 发起时创建，重试不变 | 点击领取、提交阵型 |
| `source_occurrence_id` | 一次奖励/进度来源事实 | 来源系统创建，永久不复用 | 某次 Encounter 结算 |
| `transaction_id` | 多 owner 编排事务 | 编排器创建 | 任务交付+奖励 |
| `receipt_id` | 事务或子步骤的结果身份 | owner 提交后保存 | 槽4奖励子收据 |
| `event_id` | 已提交事实的投递身份 | outbox 创建 | `transaction_id:event:1` |
| `correlation_id` | 诊断链路 | 会话/用例范围 | UI→应用→平台 |

要求：

- 同一 command_id 携带不同输入哈希时返回 `IDEMPOTENCY_KEY_REUSED`。
- 任务/奖励去重使用 source_occurrence_id 或 receipt_id，不只依赖 event_id。
- event_id 只能防重复投递；事件重建或补发不能创造第二份业务权益。
- 子收据使用 `transaction_id:owner:step` 稳定派生。
- 事件 Schema 由 `EventSchemaRegistry` 注册生产者、版本、payload 和消费者。

### 确定性业务收据

需要在结果未知后重新派生的业务收据使用 `CanonicalReceiptHashV1`：生产者规格必须写明唯一 namespace、唯一 owner 与有序 tuple；序列化按“字段名 UTF-8 字节长度 + 字段名 + 类型标签 + 值 UTF-8 字节长度 + 值”逐项拼接，整数值使用无前导零十进制，禁止空值与本地时间。摘要固定为 SHA-256 小写十六进制，ID 为 `receipt_<namespace>_v1_<digest>`。非生产者只能传入 tuple 或引用结果，不能自行删字段、换序、换哈希或生成同义 receipt；每个 namespace 必须提供黄金向量和同 key 不同输入拒绝测试。这是碰撞规避与确定性规则，不是客户端防篡改边界。

轻功落地 namespace 固定为 `world_landing`，唯一 owner 为 12，tuple 固定为 `{player_save_scope, traversal_session_id, active_segment_command_id, segment_sequence, target_cell_id, rules_version}`。26 提供 tuple，18 只保存恢复引用；`player_save_scope` 使用认证存档上下文中的内部作用域键，不把原始平台 AID 写入 receipt 明文或常规日志。

### CombatEvent 专化

战斗内部事件仍遵守通用信封：`event_id = combat_id .. ':' .. sequence`、`aggregate_id = combat_id`、`revision = sequence`。战斗内部不写服务器时间；`sequence` 是唯一排序依据。跨系统只消费 `CombatFinished` 或含 settlement receipt 的 `EncounterCompleted`，不能把表现事件当成持久化结算。
